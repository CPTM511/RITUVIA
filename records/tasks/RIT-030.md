# RIT-030: Provider-neutral AI and Tarot interpretation contracts

- Backlog item: RIT-030
- Related records: D-032, D-033, D-037

The queue state, priority, milestone, dependencies, and owner gates remain canonical in
[BACKLOG.md](../../BACKLOG.md).

## Outcome

The workspace now has a provider-neutral AI package whose first runtime schema accepts only public
deterministic Tarot V1 facts and approved version references, and whose strict output contract
represents bounded reflective interpretation without allowing the model to redefine facts or
self-certify unsafe claims.

## Scope

Included: package/build activation; structured generation and provisional streaming capability
types; normalized result, usage, failure, provenance, opaque generation authorization, and operational metadata
types; strict JSON-only Tarot V1 input and input-bound output parsers; centralized limits; stable fact-reference derivation;
synthetic one-card and three-card fixtures; adversarial unit tests; compiled runtime verification;
decision/status/evidence records.

Excluded: provider SDKs, real model/API calls, credentials, model choice, prompt construction,
retrieval, pre-generation classification, retries, fallback, prose-level semantic verification,
post-generation safety verification, persistence, telemetry emission, database/API/UI changes,
production content, payments, deployment, and activation.

## Acceptance criteria

- [x] `@rituvia/ai` builds as a strict private ESM package without a provider SDK, external runtime
      dependency, Node runtime API, environment access, or network call.
- [x] Capability-based structured generation and optional streaming interfaces expose only
      normalized success, usage, categorical failure, and provisional delta contracts; provider
      requests require an opaque internally issued allowed authorization.
- [x] Tarot input accepts the public deterministic fact projection plus exact versioned provenance
      and an allowed safety decision; private question/journal/identity/payment/audit data and every
      non-allowed route fail closed.
- [x] Canonical output covers symbols, possibilities, reflection questions, small action, optional
      approved ritual reference, uncertainty boundary, source provenance, and exact reflective
      safety literals.
- [x] Runtime parsers enforce versions, exact keys, bounded normalized text/collections, BCP 47
      locale, checksums, JSON-only input, recursive immutability, and exact output binding to the
      input's facts, approved sources, and approved ritual codes without executing object getters.
- [x] Synthetic one-card and three-card fixtures plus provider fakes compile and pass focused tests;
      no production or copyrighted tradition content is introduced.
- [x] Architecture and compiled-workspace verification include the new package without crossing a
      human approval gate.

## Risks and rollback

Exact reference binding does not prove that generated prose faithfully describes the referenced
facts or sources; RIT-033 must provide deterministic fallback and RIT-034 must reject fabrication
and unsafe claims. The interfaces do not authorize a provider/model,
budget, content corpus, or production activation.

Rollback removes the unused `@rituvia/ai` package, lockfile importer, and build-verifier entries.
No migration, persisted data, provider side effect, secret, or destructive cleanup exists.
