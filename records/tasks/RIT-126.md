## Risks and rollback

The Codex app currently executes project cron jobs locally, so read-only is prompt-enforced rather
than a hard filesystem sandbox. The mandatory dirty-checkout stop, fixed runner, no external data,
failed-run-only notifications, and pause-first response reduce but do not erase that limitation.
Repository tests cannot continuously attest future app-state drift.

Independent review classified activation without cost authority, hard isolation, and observed
outputs as High risk. D-108 resolves OWN-020 by selecting pause, which removes the active scheduled
exposure; hard isolation, separately approved model use, and the three clean-run results remain
explicit RIT-126 blockers rather than being treated as completed evidence.

Current safe state is already paused. Rollback preserves pause or, if full removal is
required, delete them only after pause and remove the manifest, runner, policy test, runbook, and
records together. No RITUVIA production or provider state requires reversal.
