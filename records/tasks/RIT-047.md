# RIT-047: Anonymous full-loop browser acceptance

- Backlog item: RIT-047
- Related records: D-050, D-051

The queue state, priority, milestone, dependencies, and owner gates remain canonical in
[BACKLOG.md](../../BACKLOG.md).

## Outcome

Prove one continuous anonymous production-artifact journey from a deterministic Tarot reflection
through a private intention, free ritual, private journal, and Revisit, while retaining the
focused failure, deletion, privacy, mobile, keyboard, RTL, and reduced-motion guarantees of the
completed Milestone 4 slices.

## Scope

Included: an explicit safe-intake action into a deterministic Tarot reflection and an explicit
Tarot-result action into Sanctuary; one same-tab browser journey that preserves only opaque
resource identifiers between pages; deterministic mocked first-party API responses; one safe
retry with stable idempotency; a free ritual and journal; Sanctuary-to-Revisit handoff; Revisit
completion and deletion; mobile, keyboard, focus, RTL, reduced motion, touch, axe, console,
request, storage, metadata, and private-canary assertions; composition with the existing Tarot,
intention, ritual, and Revisit browser suites; and the complete milestone workspace verification
matrix.

Excluded: account creation or anonymous-to-account merge; reminder delivery; production analytics
activation or viewed-event ingestion; payment, Credits, enhanced ritual, or provider flows;
Firefox/WebKit installation in the local Chromium-only CI image; manual VoiceOver/NVDA evidence;
golden screenshot changes; production deployment; and any owner-gated legal, payment, provider,
language, or launch action.

## Acceptance criteria

- [x] An allowed private question offers an explicit action into Tarot without copying the
      question, and a revealed deterministic Tarot result offers a non-coercive action into
      Sanctuary while the same tab links the exact reading through an opaque UUID only.
- [x] One anonymous browser context completes reading, intention, free ritual, journal, Revisit
      scheduling/completion, journal deletion, and Revisit deletion without account or payment.
- [x] The continuous journey proves mobile layout, keyboard activation and focus, reduced-motion
      behavior, RTL reflow, touch targets, and zero serious/critical axe findings.
- [x] At least one recoverable service failure preserves the same idempotency key, and no
      automatic retry, duplicate mutation, unexpected request, unexpected console/page error, or local
      request failure occurs.
- [x] Private question, intention, action, journal, and Revisit reflection canaries never enter
      browser URL/history, storage, public metadata, console errors, screenshots, or analytics
      requests.
- [x] Existing focused browser suites remain independently runnable, and
      `test:accessibility` composes them with the new continuous full-loop gate.
- [x] The complete milestone workspace unit, AI, configuration, migration, PostgreSQL,
      production-build, browser/accessibility, evidence, architecture, record, and secret matrix
      passes.

## Risks and rollback

The main risks are falsely calling isolated page scripts a full loop, copying private prose across
routes, weakening existing failure/deletion coverage, duplicating browser policy logic, or making
the milestone gate too broad to diagnose. The continuous verifier therefore uses one browser
context and real navigation while focused scripts remain the source of detailed slice-specific
assertions. Rollback removes the result action and continuous verifier; no schema, persisted
production data, provider, or deployment state changes.
