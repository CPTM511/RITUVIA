# RIT-036: Fixed AI regression and adversarial release evaluations

- Backlog item: RIT-036
- Related records: D-039, D-040, D-041, D-042, D-043

The queue state, priority, milestone, dependencies, and owner gates remain canonical in
[BACKLOG.md](../../BACKLOG.md).

## Outcome

RIT-036 converts the existing English/Tarot synthetic safety, generation, fallback, and
verification evidence into one checksum-bound, zero-tolerance release gate that active Quality CI
cannot silently omit or weaken.

## Scope

Included: a pure strict evaluation suite/baseline parser and scorer; code-fixed thresholds; a
test-result executor; 34 ordered synthetic release cases; exact contract-version and checksum
binding; deterministic
fact/schema/source/fallback metrics; critical safety, privacy, continuation, completeness, and safe
control gates; mutation evidence; a dedicated `pnpm test:ai-evals` command; active Quality workflow
integration; CI-script/step anti-tamper checks; a CI/test-only evaluator contract; and durable
decision evidence.

Excluded: a live provider/reviewer/model, provider SDK, key, network or paid call, production
content/prompt/fallback/classifier/safety activation, representative human model-output review,
latency/cost/canary evidence, a non-English language launch, database/persistence, UI, payment,
deployment, and public launch.

## Acceptance criteria

- [x] The suite and metadata-only baseline are synthetic, strictly versioned, recursively
      immutable, uniquely ordered, and bound by the SHA-256 digest of exact suite bytes.
- [x] Cases cannot define thresholds, executable behavior, or self-reported pass flags; the safe-off
      baseline accepts no external/paid calls or observations and stores no question, generated
      prose, prompt, reviewer text, journal, identity, or payment data.
- [x] Every registered case and safe control must match its exact categorical outcome; all-fallback
      behavior fails because safe one-card, three-card, theme-only, and negation controls must remain
      allowed, pending verification, or verified as applicable.
- [x] Applicable deterministic fact, schema, source, and authorized-fallback assertions must pass
      100%; missing/unexpected cases, unsafe continuation, privacy leaks, and critical failures must
      remain exactly zero.
- [x] The fixed gate covers every post-generation deterministic check code and every
      pre-generation risk category, including crisis precedence, Unicode/confusable input,
      professional advice, certainty, dependency, paid efficacy, supernatural persecution,
      relationship mind reading, cultural/source drift, trust failure, fallback, and safe controls.
- [x] `pnpm test:ai-evals` executes the release contract plus the real interpretation,
      retrieval/prompt, RIT-032/033/034 production boundaries with local synthetic adapters only;
      every case requires unique passed runtime evidence before an in-memory observation is scored,
      and the active Quality workflow runs it after unit tests.
- [x] CI-contract mutation tests reject removal, pass-through replacement, or reordering of the
      exact release executor; the evaluator remains CI/test-only and does not expand the production
      `@rituvia/ai` API.
- [x] No provider/model approval, runtime activation, network, secret, spend, database, migration,
      browser surface, payment, deployment, or public launch is introduced or implied.

## Verification evidence

The focused release command binds all 34 registered cases to 145 passing assertions across six
evaluation, interpretation, retrieval/prompt, pre-generation safety, generation/fallback, and
post-generation verification files. Eight new scorer tests prove
the exact green decision and independently mutate critical outcome, fact, schema, source, fallback,
privacy, continuation, all-fallback controls, case completeness/order, checksum, fixture-defined
threshold, executable field, self-reported pass, and paid/network behavior. The CI-contract suite
passes 20 assertions including explicit deletion, replacement, and ordering failures.

The full pinned repository quality gate, compiled artifact counts, architecture/secret/record
evidence, and final test totals are recorded in `PROJECT_STATUS.md`. RIT-036 changes no database
source or migration and does not need a browser acceptance rerun because it adds no user-facing
surface.

## Risks and rollback

The synthetic gate proves the repository boundary, not the quality or operational performance of a
future live model. Provider/model candidate comparison, representative human review, cost/latency,
canary, and production rollback evidence remain later activation requirements. V1 covers only
English Tarot/secular reflection; confusable Unicode is adversarial evidence, not another language
launch.

Rollback removes the explicit Quality step, root script and CI-contract entries, evaluation scripts,
two synthetic fixtures, tests, and D-043. No data, migration, remote state, provider account,
credential, payment, or production environment is changed.
