# RIT-031: Curated content retrieval and prompt versioning

- Backlog item: RIT-031
- Related records: D-031, D-032, D-037, D-038

The queue state, priority, milestone, dependencies, and owner gates remain canonical in
[BACKLOG.md](../../BACKLOG.md).

## Outcome

The AI package can now retrieve only an externally authorized, checksum-verified, published exact
Tarot content snapshot and assemble it with an independently authorized versioned prompt into an
immutable prompt artifact carrying complete persistable provenance.

## Scope

Included: pure JSON retrieval and prompt contracts; injected snapshot-integrity and server-owned
allowlist authority boundaries; published-only and full publication/rights eligibility; exact
catalog/deck/spread/card/orientation/position/reading-type/locale/tradition/theme binding; bounded
selected excerpts; checksummed mandatory safety and tone instructions; separated system and JSON
data messages; runtime identity guards; deterministic provenance; focused adversarial tests;
architecture and compiled-build evidence.

Excluded: production content or publication, provider/model SDKs or calls, credentials, question
safety classification, provider-request creation, generation, streaming, timeout/retry/fallback,
post-generation semantic verification, database persistence, telemetry emission, API/UI changes,
other modalities/locales/traditions, payments, and deployment.

## Acceptance criteria

- [x] Retrieval requires a real injected checksum verifier and a separate server-owned exact
      authority verifier; there is no permissive default or package-owned credential/runtime.
- [x] Only exact published, rights-eligible, AI-retrieval-enabled Tarot content for the public draw
      facts, selected theme, locale, and tradition can be selected; no fallback or `latest` exists.
- [x] The canonical placeholder remains unavailable, and every relevant checksum, approval,
      status, rights, date, ID, version, locale, tradition, theme, orientation, position, and spread
      mismatch fails closed.
- [x] Prompt definitions bind exact checksum, external approval, evaluation version, reviewer,
      locale, tradition, output schema, mandatory safety text, and tone text.
- [x] Assembly accepts only runtime-issued inputs, retrieval bundles, and prompt definitions;
      selected excerpts remain JSON data outside the system instruction channel, and the final
      prompt artifact is runtime-issued and recursively immutable.
- [x] Persistable provenance records explicit catalog checksum scope, dated content/source/rights
      evidence, deterministic engine, retrieval/assembly/safety policies, prompt, output schema,
      locale, tradition, theme, and tone without private question, journal, identity, or audit data.
- [x] Focused unit, architecture, type, lint, and compiled-workspace gates cover the new contracts
      without activating any owner-gated runtime.

## Verification evidence

- Focused retrieval/prompt tests use synthetic test-only published data and real SHA-256 digests;
  the canonical placeholder is only a negative fixture.
- Architecture policy now treats `@rituvia/ai` as a pure module and rejects environment, network,
  and ambient runtime-global access.
- The production artifact verifier requires compiled retrieval/prompt JavaScript and declaration
  files, checks their exports, and proves the placeholder cannot cross the retrieval boundary.
- Full repository quality-gate results are recorded in `PROJECT_STATUS.md` and the final task
  result after generated evidence is synchronized.

## Risks and rollback

An injected authority verifier is only as correct as the future server-owned allowlist behind it;
RIT-033 must wire that policy, accept only the branded prompt artifact, persist provenance, and
keep telemetry redacted. RIT-034 must still detect model-level fabrication, unsafe claims, and
semantic noncompliance. No production content, provider, or runtime is approved here.

Rollback removes the unused retrieval/prompt modules and their evidence. There is no migration,
stored data, provider side effect, secret, or destructive cleanup.
