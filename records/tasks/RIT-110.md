# RIT-110: Structured editorial content repository and publishing workflow

- Backlog item: RIT-110
- Related records: D-038, D-080
- Owner approval: Not required; no content, locale, indexing, provider, legal policy, deployment, or production state is activated

The queue state, priority, milestone, dependencies, and owner gates remain canonical in
[BACKLOG.md](../../BACKLOG.md).

## Outcome

The repository has one strict Git-authored editorial registry and a pure `@rituvia/content`
boundary for source, claim, rights, review, version, localization, deprecation, private preview,
and service-authorized publication decisions across heterogeneous content assets.

## Scope

Included: a shared immutable schema; source and claim inventories; rights and expiry; explicit
author/AI-assistance/reviewer records; forward-only states; reciprocal acyclic supersession;
source-checksummed localization; private noindex preview; process-owned record/source authority
fingerprints and locale publication authority; safe artifact paths; registrations for two existing
approved English catalogs; architecture/CI integration; focused tests and documentation.

Excluded: changing existing content prose; migrating every historical content family; database,
CMS, admin API, public route, sitemap, structured data, page-quality or near-duplicate scoring,
content report queue, AI retrieval activation, non-English publication, regional tradition,
provider, payment, legal-policy activation, production deployment, DNS, or public launch.

## Acceptance criteria

- [x] Exact stable identities, versions, artifact checksums, locales, methods/traditions,
      audiences, authors, sources, claims, rights, reviews, risk, and publication metadata parse
      through one strict immutable contract.
- [x] Author/reviewer separation, unexpired review and rights, complete claim/source evidence, and
      process-owned record/source authority fingerprints plus locale authority are required for
      publication.
- [x] Preview is exact-digest, role-bound, private, no-store, and noindex; it cannot produce a
      public publication authorization.
- [x] Status changes are forward-only; corrections retain old versions, require reciprocal
      same-lineage replacement, and reject broken or cyclic supersession.
- [x] Translations bind exact source record, version, and checksum and cannot publish before
      localized approval.
- [x] Artifact path traversal, symlinks, out-of-content resolution, checksum drift, unknown fields,
      duplicate active canonical paths, stale review, reference-only rights escalation, and
      unauthorized publication fail closed.
- [x] Canonical paths match the approved locale, translation requires source translation rights,
      and review/rights expiry advances with the current UTC date rather than a frozen build date.
- [x] Existing approved English numerology and Western natal education assets pass the shared gate
      without replacing their stricter domain-specific parsers or activating production.
- [x] Focused tests, package build/typecheck, architecture, CI contract, records, formatting,
      linting, generated evidence, and secret checks pass without the unrelated complete workspace
      test matrix.

## Verification evidence

- The content repository and path boundary passed 13 focused tests; architecture, workspace,
  CI-contract, and i18n dependency boundaries passed another 95 focused tests.
- `@rituvia/content` typecheck and production build passed, and the live verifier accepted 2
  records, 5 sources, and 5 claims.
- Architecture, active CI least privilege, localization, 123 durable records, relevant ESLint and
  Prettier checks, the 977-file secret scan, and frozen offline lockfile installation passed.
- Independent QA/security re-review reported no P0 or P1 findings after canonical-path,
  authority-fingerprint, current-date, translation-rights, and symlink-boundary corrections.
- The complete 1,674-test workspace/browser/database matrix is intentionally deferred under the
  layered verification policy because this slice adds no runtime route, database behavior,
  dependency/toolchain change, or production activation.

## Risks and rollback

The shared registry proves repository and process authority, not external legal, cultural, or
rights authenticity. Domain-specific body validators remain mandatory, and a consumer must accept
only an exact authorization result rather than raw manifest data. RIT-113 still owns broad
near-duplicate, thin-page, and search-intent quality.

There is no database migration, runtime route, content-text change, locale activation, indexing
activation, provider, payment, deployment, or public launch. Roll back by removing
`@rituvia/content`, the editorial manifest/verifier, and their architecture and CI registration;
existing specialized content paths remain intact.
