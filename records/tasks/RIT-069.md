## Outcome

Close the bounded one-time Stripe Test Mode Credit-pack payment slice with an independently
reviewed integrity matrix. Preserve the distinction between browser return, verified payment
facts, fulfillment, and provider-confirmed refund or dispute state.

## Scope

Included: server-authoritative price/policy; hosted Test Mode checkout; raw signature and replay
boundaries; pending, failure and expiry mapping; exact duplicate/conflict handling; deterministic
out-of-order reduction; one-time fulfillment; return-query forgery resistance; full-unused-pack
refund; partial-refund rejection; dispute hold; shortfall review; reconciliation; privacy export;
least privilege; and a milestone product-size and readiness checkpoint.

Excluded: Stripe Live; real card or provider-account acceptance; subscriptions; Customer Portal;
partial-refund product support; support/admin dispute workflow; provider kill switch; production
tax/legal/country configuration; deployment; DNS; and public launch.

## Acceptance criteria

- [x] Browser return and query parameters never grant paid value; owner status remains unfulfilled
      until verified provider state and fulfillment complete.
- [x] Missing, stale, malformed, or provider-rejected Stripe signatures normalize to a private
      invalid-webhook failure and cannot reach persistence.
- [x] Checkout completion requiring action remains pending; asynchronous failure remains failed;
      expiry remains expired.
- [x] Twenty concurrent deliveries of one verified success produce one transition and nineteen
      duplicates.
- [x] Refund-first/success-second replay converges deterministically; altered duplicates conflict.
- [x] A partial refund amount is recorded as a verified mismatch and creates no order transition or
      fulfillment outbox.
- [x] A signed Test Mode dispute resolves the exact Charge, PaymentIntent, Checkout Session, and
      order before creating a dispute fact; refunded charges fail closed.
- [x] Full refund, dispute hold, consumed/reserved shortfall, exactly-once grant, reconciliation,
      owner restoration, and privacy export gates pass.
- [x] The complete workspace unit/integration/build matrix runs once at this milestone.

subscription and Customer Portal lifecycle, no operator dispute/support workflow, and no provider
kill-switch rehearsal. These are assigned to later backlog items and are not represented as
complete.

outbox, Credit, refund, dispute, and reconciliation evidence remains append-only and must not be
rewritten.
