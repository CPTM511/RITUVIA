## Outcome

Provide one fixed privacy-safe protected-Beta SLO/alert policy, preserve trace correlation through a
real Web read-only containment response, and rehearse the existing dynamic kill-switch path without
building a second monitoring or control platform.

## Scope

Included: six fixed numeric Beta objectives; explicit freshness; breached/unknown alert routing;
fixed runbook and owner links; server-only normal/read-only configuration; proxy containment;
payment-webhook, logout, and session-revocation exemptions; exact 503/Retry-After/private-cache and
correlation behavior; existing local PostgreSQL astrology kill-switch drill; documentation and
records.

Excluded: external metrics/exporter, paging or public status provider; production monitoring;
dynamic no-redeploy global control plane; payment/country/provider kill switches from RIT-075;
support operations from RIT-125; game day from RIT-128; standing staging; deployment, launch,
production flags/data/credentials, provider activation, pricing/legal changes, and broad rewrites.

- [x] Six fixed Beta SLOs expose exact objective, comparison, unit, freshness, owner, severity, and

      non-healthy result is actionable and correlation-required.

- [x] Focused configuration, proxy, observability, database kill-switch, architecture, records,

- [x] Documentation states the exact implementation gap: no external monitoring/status provider,

## Risks and rollback

The environment-backed global mode requires a Web restart and therefore is not an instant
production control plane. Webhook and account-safety exemptions deliberately preserve settlement
truth and user control but require their own dependency health. Missing telemetry remains unknown
and must alert rather than silently appear healthy.

Rollback removes the evaluator, operation-mode configuration, proxy branch, tests, runbook, and
records. There is no migration, persisted user state, external provider, deployment, or production
action to reverse.
