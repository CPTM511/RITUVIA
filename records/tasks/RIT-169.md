# RIT-169: Standing-staging deployment preflight and secretless IaC

- Backlog item: RIT-169
- Related records: None
- Owner approval: not required for provider-neutral, disabled preparation. Provider selection,
  account creation, paid plans, terms, credentials, DNS, deployment, scans, restore, and launch
  remain explicit Owner execution gates.

The queue state, priority, milestone, dependencies, and owner gates remain canonical in
[BACKLOG.md](../../BACKLOG.md).

## Outcome

Prepare one smallest reversible, provider-reviewable standing-staging deployment contract that can
be inspected and dry-run without secrets or external mutations, so an approved provider choice can
move directly into bounded execution and Gate H evidence instead of another architecture rewrite.

The contextual precedents are D-097, D-104, D-109, and D-112; none authorizes the external actions
excluded below.

## Scope

Included: Web/Worker/PostgreSQL/PITR topology, environment isolation, exact typed configuration,
secret placeholders, protected ingress, noindex, health/readiness, monitor/DAST attachment points,
migration/restore/rollback order, budget hooks, immutable revision binding, and offline preflight.
Excluded: provider account/project creation, vendor terms or payment, real credentials, DNS,
resource provisioning, deployment, remote scan, database restore, invitation delivery, Gate H
completion, production, or launch.

## Acceptance criteria

- [ ] One disabled IaC/provider manifest describes only the minimum protected-staging Web, Worker,
      PostgreSQL/PITR, edge, monitoring, security, and evidence surfaces with no second architecture.
- [ ] Exact D-104/D-112 session, invite, abuse, private/noindex, synthetic-data, and safe-off
      configuration is fail-closed and contains placeholders rather than secrets.
- [ ] Preflight rejects production values, shared credentials/data, public ingress, missing budget
      authority, mutable release identity, absent restore/rollback, and unsupported provider drift.
- [ ] Runbook names every human Button/provider step, input, expected evidence, failure recovery,
      cleanup, rollback, and the boundary between preparation and Owner-authorized execution.
- [ ] Focused parser/config/IaC tests, architecture, environment, record, generated-evidence,
      formatting, lint, and secret gates pass under the pinned toolchain.

## Verification evidence

Pending implementation. Local validation must never be labelled standing staging, provider restore,
external monitoring/security, Gate H, deployment, or launch evidence.

## Risks and rollback

Provider specifications and pricing can drift. Keep provider assumptions versioned, reviewed, and
bounded; never put credentials or private exports in IaC/state/evidence. Rollback removes the
disabled templates and preflight integration only. Any external resource cleanup is a separate
Owner-approved provider action with retained audit/billing evidence.
