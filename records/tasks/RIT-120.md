## Outcome

Provide one private Owner operations dashboard that truthfully summarizes all eight required
domains and the protected-Beta release sequence without adding an admin attack surface or
misrepresenting missing local/Test Mode evidence as production state.

## Scope

Included: strict eight-section source manifest; fixed environment/source/freshness/data-quality,
window, approval, evidence, runbook, state, and known-gap labels; protected-Beta release-gate
summary; fail-closed projection; deterministic Markdown; digest-bound private JSON/Markdown CLI;
focused tests; runbook; Owner decision request; task, decision, backlog, status, and user-manual
truth.

Excluded: Web/admin route or button; production metric readers; durable analytics collection;
revenue or queue aggregation; provider APIs; infrastructure cost ingestion; budget approval or
enforcement; support action; deployment; standing staging; penetration test; Gate H completion;
launch authorization.

## Acceptance criteria

- [x] Health, revenue, core loop, AI, queue, support, cost, and approvals appear exactly once in
      canonical order.
- [x] Every section displays environment, source, observed-through time, maximum age, freshness,
      data quality, window, approval reference, evidence, runbook, state, and fixed known gap.
- [x] Missing, stale, future, and synthetic evidence becomes `unknown`, never zero or healthy.
- [x] The release panel shows OWN-019, RIT-127/RIT-128/RIT-130, standing staging, Gate H, and
      independent-security state without authorizing deployment.
- [x] Inputs reject extra/private/accessor-backed fields, arbitrary detail text, unsafe evidence
      paths, invalid windows, inconsistent Gate H claims, and invented unavailable-source evidence.
- [x] The CLI reads one bounded regular JSON file and writes exclusive digest-bound mode-0600 JSON
      and Markdown without overwrite, symlink following, provider access, or data mutation.
- [x] The runbook and Chinese manuals state the exact entry point and that no Web/Admin button exists.

## Risks and rollback

The dashboard is manually generated and does not itself provide live monitoring, paging, read
auditing, or browser accessibility. A future browser route must not reuse admin owner helpers
without exact role enforcement and read-audit coverage. The current dashboard intentionally shows
unknown or blocked state for unsupported sources and release gates.

Rollback removes the new analytics module, CLI, tests, scripts, and documentation. Generated
private reports can be deleted locally. No database, provider, deployment, or production data
rollback is required.
