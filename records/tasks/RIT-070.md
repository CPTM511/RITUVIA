# RIT-070: Subscription Lifecycle and Entitlements

- Backlog item: RIT-070
- Implementation revision: `db91755`
- Related records: None

The queue state, priority, milestone, dependencies, and owner gates remain canonical in
[BACKLOG.md](../../BACKLOG.md).

## Outcome

Provide a Stripe Test recurring-subscription lifecycle whose local authority is reserved before
Checkout, whose signed provider facts are verified before reduction, and whose Plus entitlement
and monthly Credit allocations remain exactly once, invoice-scoped, and nonnegative.

## Scope

Included: local subscription root reservation; monthly and annual products; signed subscription
event ingestion; amount, currency, product, interval, order, account, invoice, and subscription
matching; Plus entitlement lifecycle; eight monthly Credits; annual monthly allocation schedule;
cancellation; invoice-scoped full-refund reversal; durable conflict review; quarantine; and
least-privilege runtime roles.

Excluded: Stripe Live; Customer Portal; customer account UI; commerce admin UI; dispute workflow;
provider kill switches; production migration; deployment; DNS; legal-policy activation; and launch.

## Acceptance criteria

- [x] A local subscription root is reserved before recurring Stripe Test Checkout, and concurrent
      open subscriptions fail before provider session creation.
- [x] Signed events must match immutable local account, product, interval, amount, currency, order,
      invoice, and subscription facts before reduction.
- [x] Plus access and eight Credits per available month are granted exactly once.
- [x] Annual plans schedule twelve monthly allocations but release only the current period.
- [x] Cancellation removes future subscription allocations without touching purchased Credits.
- [x] Full refunds reverse only unconsumed Credits linked to the exact invoice; conflicts create a
      durable review and quarantine the poison event without blocking later work.
- [x] Runtime privilege drift, duplicate events, concurrent grants, and negative projections fail
      closed.

## Risks and rollback

Primary risks are external Checkout duplication, forged lifecycle facts, duplicate monthly value,
cross-invoice reversal, purchased-Credit damage, and a poison event blocking the queue. Local root
reservation, signed fact matching, unique allocation evidence, source-linked reversal, durable
review, quarantine, and role attestation contain those risks.

Rollback disables recurring Checkout and subscription-event reduction. Existing roots, events,
allocations, entitlements, reversals, and review records remain append-only; no destructive
rollback or balance rewrite is permitted.
