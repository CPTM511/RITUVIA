# RIT-094: Natal chart and textual table UI

- Backlog item: RIT-094
- Related records: D-067, D-068, D-070, D-072

The queue state, priority, milestone, dependencies, and owner gates remain canonical in
[BACKLOG.md](../../BACKLOG.md).

## Outcome

An authenticated English user can open a private saved natal calculation at
`/en/readings/astrology`, understand its confidence and unavailable states, inspect a responsive
presentation-only chart, and read every authoritative fact in semantic tables without exposing
birth data or activating new calculations.

## Scope

Implement a read-only latest-saved-result viewer before birth-profile creation or location search.
The route uses the existing owner-scoped `AstrologyCalculationService.list()` boundary and renders
only server-authored `AstrologyNatalFactsV1`.

Included: authenticated private page; owner-scoped query-free GET API; strict response contract;
exact, approximate, unknown, unavailable, empty, loading, retry, offline, and service-unavailable
states; SVG fact presentation; table-authoritative placements, houses, angles, and aspects;
confidence and approximation disclosure; English messages; mobile, zoom, keyboard, forced-colors,
reduced-motion, and RTL-safe layout; focused route, component, proxy, accessibility, and browser
evidence.

Excluded: birth-profile entry/editing, location search, calculation POST, native execution,
interpretive prose, personality claims, AI, intention creation, analytics, provider activation,
feature-flag activation, new persistence, production migration, deployment, public launch, and
golden screenshot changes.

## Acceptance criteria

- [x] The reviewed page is data-free before client authorization; its private data API requires an
      authenticated account session, uses no sensitive URL query, returns private no-store/noindex
      responses, and exposes only owner-scoped saved calculations.
- [x] A strict response parser rejects unknown keys, malformed facts, oversized payloads, and
      content-bearing failure details before rendering.
- [x] Exact facts show eleven placements, twelve house cusps, angles, and approved aspects;
      approximate facts visibly disclose the approximation window and suppress houses, angles, and
      aspects; unknown or unavailable facts never invent a chart.
- [x] A responsive SVG presents only approved facts, while semantic tables with captions remain the
      authoritative complete representation. Labels, symbols, text, and stroke patterns ensure
      color is never the sole encoding.
- [x] The UI does not derive planet-house membership, retrograde status, interpretations, or other
      facts absent from `AstrologyNatalFactsV1`.
- [x] Empty, loading, retry, offline, unavailable, narrow mobile, 200%/400% zoom, keyboard, focus,
      forced-colors, reduced-motion, and pseudodirectional RTL behavior pass focused checks. Chart
      geometry and degree values remain LTR while surrounding layout mirrors.
- [x] Birth date, time, place, coordinates, location queries, and private canaries never enter URLs,
      history, metadata, analytics, logs, browser storage, screenshots, or rendered error copy.
- [x] Formatting, linting, affected type checking/build, architecture, records, secret policy,
      diff hygiene, focused unit/route/browser/accessibility tests, and the final task-specific
      evidence pass without repeating the complete workspace suite.

## Risks and rollback

Natal facts are private and may indirectly reveal birth details even when raw profile input is
absent. The first slice therefore remains authenticated, no-store, query-free, analytics-free, and
read-only. The golden prototype supplies visual language only; its browser-local Sun-sign
simulation is not a calculation source.

Wheel rotation, collision handling, display precision, and planet-house assignment are not
separately approved facts. Keep the first wheel presentation-only and table-authoritative rather
than silently inventing those rules.

Rollback removes the private page/API, response parser, UI/messages/styles/tests, and proxy entries.
It does not alter persisted encrypted calculations, the default-off feature flag, native source
archives, or D-069 Corresponding Source obligations.
