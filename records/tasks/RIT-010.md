# RIT-010: Accessible English Web shell and locale-prefixed routing

- Backlog item: RIT-010
- Related records: D-023

The queue state, priority, milestone, dependencies, and owner gates remain canonical in
[BACKLOG.md](../../BACKLOG.md).

## Outcome

The first public Web surface is useful, calm, server-rendered, keyboard-accessible, responsive, and
available at one explicit English locale path without implying that unfinished experiences or
unapproved languages are live.

## Scope

Included: strict English locale routing, explicit root redirect and unsupported-locale failure,
server-side `experience.public_shell` safe-off enforcement, typed source messages, configured
branding, metadata/canonical foundation, semantic home/header/navigation/footer content,
responsive and reduced-motion styles, restrictive shell response headers, unit/contract coverage,
and real browser verification.

Excluded: authentication/account controls, implemented divination methods, legal or policy text,
additional locale activation, full ICU translation tooling, a reusable component library, sitemap,
PWA installation/offline caching, analytics, production deployment, and every owner-gated action.

## Acceptance criteria

- [x] When the server-side public-shell flag is enabled, `/` redirects to `/en`; exact supported locale parsing fails closed; unsupported locale paths return 404, while disabled/error flag states return 404.
- [x] The document language/direction and canonical/hreflang metadata agree with the rendered locale and non-production pages are not indexable.
- [x] Home, header, primary navigation, skip link, main content, and footer render meaningful server HTML with one clear primary action.
- [x] User copy comes from a typed message catalog, branding comes from runtime configuration, and no non-English locale is activated.
- [x] Keyboard focus, semantic order, 44px targets, reduced motion, long text, 320px reflow, 200% zoom, RTL-safe primitives, and no-JavaScript behavior are verified.
- [x] Unit/contract tests, real-browser checks, full repository gates, independent review, documentation, and project state are reconciled.

## Risks and rollback

The main risks are an invalid locale silently rendering English or generating an unbounded cache,
a disabled or unavailable activation plane leaking shell HTML/RSC, navigation targets implying
unfinished features, inaccessible reflow/focus, metadata disagreeing with the route, remote
resources escaping the performance/privacy budget, or working brand text becoming hardcoded.
Strict finite routing, server-side safe-off evaluation, representation-level integration checks,
server-rendered/resource assertions, and real-browser checks cover those risks. Rollback is
repository-only: revert the RIT-010 commit and regenerate evidence. It changes no database, remote,
production, payment, or owner-gated state.
