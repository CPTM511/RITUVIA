# RIT-066: Product Detail, Checkout Return, and Order Status UX

- Backlog item: RIT-066
- Related records: D-079, D-091, D-092

The queue state, priority, milestone, dependencies, and owner gates remain canonical in
[BACKLOG.md](../../BACKLOG.md).

## Outcome

Provide one small, noindex English Credit-pack page that renders server-authoritative catalogue
contents and one-time USD prices, starts the existing hosted Stripe Test Mode checkout with stable
retry idempotency, and confirms fulfillment only from an owner-scoped server status.

## Scope

Included: active US/USD one-time Credit packs; exact catalogue contents, non-transferability,
non-renewal, no-cash-value and approved refund-baseline disclosures; verified-account and 18+ gates;
same-origin CSRF-protected checkout; strict Stripe-hosted URL acceptance; stable per-pack retry
keys; a private `/api/v1/checkout/return/{orderId}` status route; delayed-webhook polling; generic
purchase return copy; account discovery link; mobile, Axe, route, service, database and build
evidence.

Excluded: Stripe Live Mode; subscriptions; crypto; taxes; final legal terms; refund initiation;
order history; invoices; billing portal; production provider activation; deployment; DNS; public
indexing; and public launch.

## Acceptance criteria

- [x] Product cards show the exact current catalogue contents and price without accepting
      client-controlled money, Credit quantity, eligibility, or fulfillment facts.
- [x] Checkout requires the authenticated verified adult account, same-origin CSRF, and the
      existing server-side catalogue and Country Policy evaluation.
- [x] A retry reuses the same bounded idempotency key after a network failure, including when
      browser storage is unavailable, and cannot create a duplicate order.
- [x] The browser accepts only an HTTPS `checkout.stripe.com` response before navigation.
- [x] Return status is owner-scoped and private/no-store; missing sessions and cross-account IDs
      share the same not-found response.
- [x] A paid order remains pending until the matching current fulfillment version is active.
- [x] The page is noindex, keyboard-readable, responsive at 375px without horizontal overflow,
      and has zero Axe violations in the focused browser check.

## Risks and rollback

Primary risks are redirect-based value issuance, stale fulfillment display, cross-account order
enumeration, duplicate orders after retry, client price drift, and misleading commercial terms.
The route reads only the authenticated owner's durable order/item/current-fulfillment join; the
return component never grants value; checkout uses the existing authoritative service; and the
page identifies the refund language as a development baseline rather than final active legal
terms.

Rollback removes the `/en/plans` page, its account link and reviewed proxy paths, then restores the
return component to the legacy local-order endpoint. Existing orders, payment events, Credits and
fulfillment evidence remain unchanged. No migration or destructive rollback is required.
