# RIT-057: Identity, privacy, and authorization security suite

- Backlog item: RIT-057
- Related records: D-057, D-058

The queue state, priority, milestone, dependencies, and owner gates remain canonical in
[BACKLOG.md](../../BACKLOG.md).

## Outcome

Prove the completed Milestone 5 account foundation as one adversarial identity, privacy, and
authorization boundary: another user cannot claim or inspect resources, bearer and CSRF material
cannot be replayed across sessions, export and deletion remain owner-scoped and recoverable,
ordinary users cannot gain admin authority, and private content cannot enter logs, analytics,
metadata, browser state, or audit evidence.

## Scope

Included: one independently runnable RIT-057 suite that composes the focused authentication,
anonymous merge, account-control, privacy-export, privacy-deletion, admin-security, observability,
analytics, metadata, route authorization, PostgreSQL concurrency/privilege/recovery, and
production-artifact browser gates; explicit mapping to the production security-test matrix;
security-negative review for every currently implemented account-linked resource; and the
complete milestone workspace verification matrix required by D-050.

Excluded: production email/OAuth/WebAuthn or wallet identity; admin routes or UI; support access
to private content; final legal retention text; production data mutation; provider activation;
deployment; public launch; new locale activation; and golden screenshot changes.

## Acceptance criteria

- [x] Cross-user access remains indistinguishable or denied for account history, sessions,
      readings, intentions, rituals, journals, Revisits, orders, entitlements, exports, deletion,
      and role mutations without accepting client-selected ownership.
- [x] Authentication challenges, anonymous and account sessions, merge keys, export requests, and
      deletion requests reject replay, cross-account substitution, stale authentication, expiry,
      and incorrect binding while preserving exact idempotent recovery.
- [x] Every cookie-authenticated mutation in the implemented account/privacy surface rejects
      missing or mismatched session CSRF and foreign origin before persistence.
- [x] Export remains complete, recent-authenticated, encrypted, owner-scoped, expiring, and
      append-only; deletion destroys implemented private content and authority, fences export
      completion, survives restore, and prevents reauthentication.
- [x] Admin authorization remains finite and default-deny; ordinary users, missing/stale
      assurance, and out-of-role actions cannot mutate roles, while audit failure rolls back and
      append-only digest evidence survives restore without private data.
- [x] Private canaries and bearer material remain absent from logs, analytics, URLs, metadata,
      browser storage, client responses, export/audit metadata, console output, and external
      requests.
- [x] The dedicated security suite and the one-time Milestone 5 workspace unit, AI,
      configuration, migration, PostgreSQL, build, browser/accessibility, architecture, evidence,
      record, dependency, and secret gates pass with no critical/high finding.

## Planned files and verification

Primary areas are a root RIT-057 suite command and orchestrator, focused security-test inventory,
the current security/test/status documentation, and durable task evidence. Product/runtime code
changes are allowed only when a reproducible security gap requires the smallest corrective patch.

Run the dedicated identity/privacy/authorization suite first so failures remain attributable.
After it passes, run the complete milestone matrix exactly once. Do not repeat the full workspace
unit suite after documentation-only changes; reuse that passing evidence only when source,
dependencies, toolchain, configuration, and generated inputs remain unchanged.

## Risks and rollback

Main risks are mistaking separately passing slices for an integrated authorization boundary,
omitting a resource from the IDOR matrix, leaking private content through diagnostic evidence,
weakening security checks to shorten runtime, or repeatedly running unrelated tests. Rollback
removes only the suite composition and documentation; additive security corrections must retain
their own safe rollback. No production action, destructive migration, retention change, provider
activation, or deployment is authorized.

## Verification evidence

RIT-057 adds exact privacy proxy admission and cross-site metadata denial, then binds the dedicated
deletion role to one account through a transaction-local request-token hash, a security-barrier
view, and row-level policies. The database test connects directly with that role and proves a
second account is neither visible nor mutable. The real-browser privacy flow covers sign-in,
export request, metadata, encrypted download, account deletion, old-session/export denial,
dropped-response replay, and private canaries.

`test:identity-privacy-authorization` composes the focused security slices. Its focused Vitest
stage passes 37 files and 472 tests; all specialized account, export, deletion, admin, recovery,
and browser gates pass. The one-time milestone matrix passes formatting, linting, all 13 package
type checks, 123 files and 1,644 workspace tests, 34 AI cases with zero critical failures, all 20
migrations plus logical restore, 115 production artifacts, and the complete accessibility browser
matrix. `pnpm audit --audit-level=high` exits successfully with no critical/high advisory after
pinning patched PostCSS and brace-expansion versions and adding a reviewed minimatch CommonJS
compatibility patch; two moderate advisories remain.

Production admin activation remains safe-off. Before any admin route or credential is deployed,
role mutation and audit append require a reviewed database-bound privileged procedure or
equivalent database-enforced step-up capability, approved WebAuthn/enrollment, and owner approval.
