# RIT-045: Consented transactional Revisit reminder adapter

- Backlog item: RIT-045
- Related records: D-049, D-062, D-063

The queue state, priority, milestone, dependencies, and owner gates remain canonical in
[BACKLOG.md](../../BACKLOG.md).

## Outcome

Let a signed-in owner explicitly enable or disable one privacy-safe English email reminder for one
scheduled private Revisit, while preserving anonymous-first value, immediate withdrawal,
local-calendar/quiet-hours behavior, once-only delivery, bounded failure, and a hard safe-off
production provider boundary.

## Scope

Included: strict exact-version preference mutation; account-owned private list/resource APIs;
same-origin/session-CSRF/idempotency; committed-only UI state; anonymous safe empty discovery;
additive subscription queue and append-only operation ledger; database-clock local-date/time-zone
and quiet-hours claims; hashed leases, three attempts, deterministic retry, dead letter, stale
completion fencing, second pre-provider authorization, fixed lock-screen-safe English copy,
identifier-only provider input, provider-neutral disabled adapter, bounded identifier-free worker
events, privacy export, privacy-deletion cancellation, focused PostgreSQL/browser/accessibility
evidence, and documentation.

Excluded: production email provider/domain/credentials, recipient email decryption, deployed
scheduler, marketing or weekly summaries, push/SMS/in-app notifications, another locale,
production legal/unsubscribe copy, delivery dashboards/alerts, retention changes, deployment,
public launch, golden screenshot changes, or any private reflection content in messages/jobs.

## Acceptance criteria

- [x] Only an active account owner can subscribe or unsubscribe one owned scheduled Revisit using
      the exact English email/once/version contract; anonymous Revisit use remains complete and
      gets a safe empty reminder discovery response.
- [x] Exact same-key replay returns the recorded result after later preference changes, changed
      reuse conflicts, operation history is append-only, and runtime cannot delete subscriptions or
      mutate/delete operation evidence.
- [x] Claims use database local date/time zone, quiet hours, `SKIP LOCKED`, bounded hashed leases,
      three attempts, deterministic retry, terminal dead letter, stable provider idempotency, and
      once-only completion.
- [x] Worker authorization rereads account, ownership, parent lifecycle, locale, contract,
      preference, quiet hours, and lease immediately before provider use; unsubscribe and privacy
      deletion prevent delivery and clear active leases.
- [x] Provider input and fixed message contain no email address or private question, intention,
      action, ritual, journal, relationship, health, or generated prose. The only composed adapter
      is hard disabled.
- [x] UI provides signed-out, loading, saving, enabled, disabled, retry, dead-letter, delivered,
      offline, and failure states with native checkbox semantics and no optimistic success.
- [x] Privacy export includes visible reminder/operation evidence without hashes or leases, and
      privacy deletion cancels queued delivery before identity tombstoning.
- [x] Focused tests, all 25 migrations, affected builds/type checks, architecture, Revisit and
      continuous core-loop Chromium, and shared accessibility verification pass without rerunning
      the unrelated complete unit matrix.

## Risks and rollback

Primary risks are inferred consent, private lock-screen disclosure, duplicate delivery, sending
after withdrawal/deletion, cross-account delivery, local-date/quiet-hours drift, stale lease
completion, unbounded retries, and accidentally activating an external provider.

The implementation uses an independent exact-version account preference, fixed generic copy,
identifier-only jobs, live authorization, database-clock local scheduling, lease fencing,
provider idempotency, bounded retry/dead letter, privacy-deletion cancellation, and a disabled
adapter. Rollback stops route/worker composition and leaves additive evidence intact; no
destructive down migration is defined.
