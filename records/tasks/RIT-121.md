# RIT-121: Finalize threat model and remediate launch findings

- Backlog item: RIT-121
- Related records: D-098, D-099

The queue state, priority, milestone, dependencies, and owner gates remain canonical in
[BACKLOG.md](../../BACKLOG.md).

## Outcome

Produce a versioned threat model for the approved English, anonymous, free, protected closed-Beta
core loop, verify every reachable trust boundary and retained integration against current evidence,
and close every reproducible Critical or High finding that would block that Beta without restoring
frozen product breadth.

## Scope

Included: Question/Theme through Interpretation, Intention, Small Action, Free Ritual, Private
Reflection, and Revisit; anonymous authority, cookies, CSRF/origin handling, server actions and API
boundaries, owner scoping, private-data handling, output rendering, security headers, configuration
fail-closed behavior, local persistence boundaries, dependencies, secret scanning, build/CI supply
chain, and the retained but disabled integration surfaces whose misconfiguration could expose the
approved Beta.

Excluded: public or Beta deployment, production data, DNS, production credentials, live payment or
crypto, production AI, astrology activation, paid-offer implementation, new locales/countries,
growth expansion, legal-policy activation, irreversible migration, golden screenshot updates, broad
rewrites, and remediation below High unless it is necessary to validate or safely contain a
Critical/High finding.

## Acceptance criteria

- [x] A dated, versioned threat model identifies the approved Beta assets, attackers, abuse cases,
      trust boundaries, reachable data flows, retained disabled integrations, and explicit out-of-
      scope production gates.
- [x] Every applicable production-pack threat and security-test-matrix row is mapped to current
      implementation evidence, a safe-off control, a follow-up task, or an explicit non-applicable
      rationale for this Beta.
- [x] Every reproducible Beta-blocking Critical or High finding is fixed with the smallest complete
      change, regression evidence, and rollback notes; zero such findings remain open.
- [x] Secret, dependency, static/architecture, environment/configuration, private-data, authorization,
      browser-security, and build evidence required by the affected scope passes under exact Node
      `26.5.1` and pnpm `11.13.1`.
- [x] Lower-severity and unavailable external evidence is recorded truthfully with compensating
      controls or later task ownership and is not misreported as a completed production gate.
- [x] Backlog, project status, decision linkage, durable records, generated evidence, and Owner-facing
      launch documentation agree on the result and the next single eligible task.

## Verification evidence

The dated threat model maps the approved Beta assets, data flow, retained integrations, threat
register, and every row in `contracts/security-test-matrix.csv`. Primary and independent read-only
review reproduced zero Critical or High vulnerabilities. Lower findings remain explicit: nonce/hash
CSP hardening, exact route-profile enforcement, intake/endpoint abuse controls, Tarot mutation CSRF
defense-in-depth, two Moderate Prisma-tool dependency advisories, and unavailable standing staging,
DAST, external penetration test, broad SAST/license/application-SBOM, and immutable hosted-run
evidence.

Under exact Node `26.5.1` and pnpm `11.13.1`, CI-contract, architecture, environment-contract,
configuration-boundary, focused security, dependency audit, current-source secret scan, pinned-tool,
full-history Gitleaks, identity/privacy/authorization, database owner-scope, and browser privacy gates
pass. The production build verifies 121 artifacts across 61 generated routes, and the six-stage
Home-to-Revisit browser loop passes 12 continuous transitions with zero account, payment, serious/
critical Axe, console, request, touch-target, layout, or private-data-leak failure. Gitleaks scanned
85 commits with no remaining leak; `pnpm audit --audit-level=high` reports zero Critical, zero High,
and two Moderate transitive Prisma-tool advisories. The identity/privacy suite
first exposed one stale browser assertion for `privacy-export-package.v1`; the durable migration and
all implementation/service contracts require `v2`, so the assertion was corrected and the failed
privacy browser boundary passed before the full suite rerun.

D-099 records the only RIT-121 code change to security policy: one exact immutable Gitleaks
commit/path/rule/line fingerprint for the public `commercial.fulfillment.v1` schema-version label.
No rule, regex, path, provider, deployment, production data, product route, database schema, or
runtime feature was enabled.

## Risks and rollback

The principal risk is either under-scoping a reachable private-data or authority boundary or
over-scoping the task into frozen payments, AI, astrology, localization, growth, or production
activation. Severity requires a reproducible attack path and impact against the approved Beta; lack
of production-provider or penetration-test evidence must remain an explicit future gate rather than
an invented pass.

Rollback reverts only RIT-121 code, test, and documentation changes, restores its prior queue state,
and regenerates evidence. It must not weaken the intake-first journey, delete audit/replay/recovery
obligations, activate a provider, change production data, or restore frozen expansion.
