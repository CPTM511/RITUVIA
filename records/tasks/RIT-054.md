# RIT-054: Selective and account deletion workflow

- Backlog item: RIT-054
- Related records: D-056

The queue state, priority, milestone, dependencies, and owner gates remain canonical in
[BACKLOG.md](../../BACKLOG.md).

## Outcome

Let a recently authenticated account irreversibly remove all linked private content or delete the
account through an owner-scoped, idempotent workflow that immediately revokes affected access,
crypto-shreds private plaintext-bearing fields, preserves only explicit pseudonymous
commerce/consent/security evidence under its existing source retention, and records completion
evidence without private content.

## Scope

Included: one strict `POST /api/v1/privacy/deletions` contract with explicit private-content or
account scope; exact same-origin/session-CSRF evidence; recent authentication; request
idempotency, account serialization, and bounded rate control; immutable request and one-per-request
completion evidence; immediate revocation of linked anonymous sessions; owner-link deletion state;
crypto-shredding of intention, legacy/current journal, and Revisit ciphertext; privacy-export
artifact destruction; account-scope revocation of every account session/passkey and
pseudonymization of profile and authentication identity; denial of future authentication or
account/private-resource reads after account deletion; retained-category evidence limited to
derived reflection metadata, consent history, commerce/entitlement records, and security/privacy
audit; and focused route, service, PostgreSQL, authorization, concurrency, privacy, configuration,
migration, and recovery verification.

Excluded: inventing or activating final legal retention periods; deleting immutable money,
provider-event, consent, privacy-export audit, or deletion evidence; provider-side customer
deletion; backup expiry enforcement; production KMS/data-key destruction; support/admin processing;
outbox/queue infrastructure; production data mutation; destructive production migration;
deployment; public launch; legal/privacy copy changes; locale activation; and golden screenshot
updates.

## Acceptance criteria

- [x] Missing active/recent authentication, exact same-origin evidence, session CSRF, strict body,
      idempotency key, policy configuration, or rate capacity fails closed with no deletion write.
- [x] Same-key replay returns one owner-scoped result; concurrent requests serialize; another
      account cannot inspect, complete, or reuse the request.
- [x] Private-content scope revokes linked anonymous sessions, severs account authorization,
      crypto-shreds all implemented private free-text ciphertext, destroys export artifacts, and
      leaves the signed-in account usable for future new data.
- [x] Account scope additionally marks the account deleted, pseudonymizes profile/authentication
      identity, revokes all account sessions and passkeys, clears the session cookie, and prevents
      authentication, export, history, and exact-resource recovery.
- [x] Completion evidence contains only version, scope, counts, retention-category codes, and a
      digest; retained financial/consent/security records contain no newly introduced private text
      and receive no invented retention period.
- [x] Focused unit, route, database, configuration, architecture, migration, secret, type, lint,
      formatting, record, generated-evidence, and affected-package build gates pass without
      repeating the complete workspace suite reserved for RIT-057.

## Planned files and verification

Primary areas are an expand-only privacy-deletion migration; database request/finalization
persistence; account/subject authorization filters; strict server policy configuration; Web
deletion service and route; focused unit/route tests; and an isolated PostgreSQL gate.

Run parser/service/route tests first, then the dedicated PostgreSQL gate covering recent
authentication, replay/concurrency, owner isolation, session/passkey revocation, ciphertext
replacement, link denial, artifact destruction, retained records, terminal completion evidence,
restore, and runtime privileges. Close with affected formatting, linting, type checking,
architecture, migration, CI-contract, secret, record, generated-evidence, checksum, and database/
Web production builds. The complete identity/privacy matrix remains reserved for RIT-057.

## Risks and rollback

Main risks are deleting another account, claiming completion while plaintext remains, retaining an
export artifact, allowing stale anonymous/account sessions, breaking immutable commerce evidence,
re-identifiable tombstones, replaying a destructive request with different scope, and treating a
local structural exception list as final legal policy. Rollback disables the route before any
production activation; completed crypto-shredding is intentionally irreversible. No production
deletion, final retention decision, provider action, deployment, or public launch is authorized.
