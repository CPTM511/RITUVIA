# RIT-075: Payment/provider kill switches and no-fallback contract

- Backlog item: RIT-075
- Related records: D-094, D-101, D-110
- Owner approval: Not required for the repository-local safe-off composition. Enabling a country,
  provider, method, paid product, credential, deployment, or production payment remains separately
  Owner-gated.

The queue state, priority, milestone, dependencies, and owner gates remain canonical in
[BACKLOG.md](../../BACKLOG.md).

## Outcome

Compose the existing country/fiat/crypto default-off flags with the exact Country Policy route so
every new purchase fails closed before local persistence, subscription reservation, provider use,
or Checkout URL replay, with no automatic provider fallback.

## Scope

Included: one pure payment-route decision, DB-backed Web flag composition, legacy local and Stripe
Test new-purchase guards, negative tests, HTTP failure mapping, runbook, and records. Excluded:
provider activation/selection/contact, credentials, network, migrations, pricing, paid UI,
webhooks, refunds, disputes, fulfillment, reconciliation, deployment, and production launch.

## Acceptance criteria

- [x] Country and fiat/crypto checkout controls are independently required and default safe-off.
- [x] Country Policy must authorize the exact country, currency/asset, provider, method, kind, and
      recurrence at the same server-owned instant.
- [x] Every non-empty fallback-provider list fails closed; no alternate provider/method is chosen.
- [x] Guards run before order/subscription persistence and provider invocation.
- [x] Safe-off blocks disclosure of an already attached, unexpired Checkout URL.
- [x] Control-reader/configuration faults return redacted unavailable responses; eligibility
      denials remain non-sensitive.
- [x] Signed settlement, refund, dispute, fulfillment, entitlement, and reconciliation paths are
      unchanged and remain processable.

## Risks and rollback

This repository cannot revoke a provider URL copied before safe-off or cancel provider-side
renewals. Signed events for prior obligations must continue through settlement. Rollback removes
this additive slice and records; there is no migration or external state to reverse.
