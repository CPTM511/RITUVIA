# RIT-127: Cost budgets, allocation, and anomaly controls

- Backlog item: RIT-127
- Related records: D-088, D-103, D-105, D-106
- Owner approval: D-106 approves Option A safe-off for the protected free Beta. Option A explicitly
  does not provide the exact production amounts, vendors, currency/FX rules, alert destinations,
  runtime enforcement, or permitted degradation required for completion.

The queue state, priority, milestone, dependencies, and owner gates remain canonical in
[BACKLOG.md](../../BACKLOG.md).

## Outcome

Prepare one provider-neutral fail-closed daily cost guardrail simulation that reconciles proposed
provider/feature allocations, detects missing or unbudgeted cost, and evaluates a closed safe-action
vocabulary without asserting approval or executing provider/runtime changes.

## Scope

Included: strict proposed-policy/source/observation parsing; fixed provider/feature registries;
exact 24-hour UTC window; environment/currency allocation; reporting coverage; warning and limit
simulation; essential-service protection; denied spend authority; private digest-bound
JSON/Markdown; Owner dashboard categorical projection; CI/build/docs.

Excluded: production amounts; provider billing ingestion; invoice/FX reconciliation; database
migration; distributed reservation; provider/model change; worker/runtime mutation; automatic
degradation; external alerts; admin route/Button; deployment; DNS; public launch.

## Acceptance criteria

- [x] Unknown fields, accessors, private content, invalid periods, duplicate lines, unsafe essential
      actions, and inconsistent totals fail closed.
- [x] Proposed policies cannot self-assert approval and require unique finite provider/feature lines
      whose allocations sum to the proposed total.
- [x] Missing, stale, synthetic, incomplete, and unavailable cost cannot appear as zero or available
      budget; unbudgeted observations remain explicit.
- [x] Warning and limit simulations come only from the parsed proposed line and stay inside the closed
      safe-action vocabulary.
- [x] Essential safety/payment/backup/privacy/entitlement lines are alert-only; all non-essential
      lines remain denied because no approved runtime authority exists.
- [x] The private CLI binds the real input SHA-256, rejects symlinks/oversized input, writes new
      mode-0600 files only, and never overwrites evidence.
- [x] Owner operations shows local guardrail verification separately from unavailable production
      budget and cost aggregates.
- [ ] OWN-005 records exact policy bytes, amounts, environment, currency, effective/expiry time,
      providers/features, alert routes, and permitted degradations.
- [ ] A durable atomic reserve/commit/release/reconcile contract prevents concurrent, retry,
      fallback, crash-recovery, late-cost, and duplicate-idempotency overspend.
- [ ] Fixed cost alert IDs, severity, owner, runbook, correlation, deduplication, acknowledgement,
      recovery, burn-rate, price-drift, retry/queue-storm, and alert-delivery behavior pass.
- [ ] Full focused analytics, CLI, Owner dashboard, CI-contract, type, build, formatting, lint,
      records, generated-evidence, architecture, and secret checks pass after the approved runtime
      contract is implemented.

## Risks and rollback

The local evaluator is deliberately not a distributed spend reservation system and exposes no
admission API. It cannot prevent a live provider call until a future approved adapter uses atomic
durable state.
Provider invoices, late corrections, taxes, fees, disputes, FX, and external alert delivery remain
unimplemented. Production paid providers remain safe-off.

Rollback removes the new analytics/CLI/test/CI/docs surface. No migration, provider state, private
user data, or production configuration requires reversal.
