# RIT-092: Encrypted birth profile and uncertainty model

- Backlog item: RIT-092
- Status: Done
- Related decisions: D-067, D-068
- Production engine method gate: OWN-015

The queue state, priority, milestone, dependencies, and owner gates remain canonical in
[BACKLOG.md](../../BACKLOG.md).

## Outcome

RIT-092 adds an account-session-authorized encrypted birth-profile boundary with exact,
approximate, and unknown-time semantics. The complete private payload is AES-256-GCM encrypted and
owner/resource bound; PostgreSQL stores only coarse certainty, versions, keyed digests, revision,
timestamps, and ciphertext.

The profile preserves original local input, explicit approximation window, opaque selected place,
coordinates, IANA time zone, provider/data/license digest, exact Node/ICU/tzdata provenance, fold
choice, offset, and UTC instant when a time is known. Unknown time never invokes time resolution
and never fabricates noon, an offset, a runtime, or a UTC instant.

## Scope

Included: strict immutable V1 domain contracts; selected-location reread; exact fold/gap
resolution; encrypted create/read/list/update/delete service; transaction-local account-session
authorization; owner predicates; optimistic revision checks; idempotency operation ledger;
tombstone deletion; privacy export decryption and digest verification; selective/account deletion;
privacy-deletion evidence count; least-privilege app and deletion-role grants; RLS for the dedicated
deletion role; migration, schema, fixtures, and focused tests.

Excluded: real GeoNames data import, location-search HTTP route or UI, natal calculations, Swiss
Ephemeris/native artifacts, public birth-profile UI, analytics, external provider calls,
production migration, deployment, and public launch.

## Acceptance status

- [x] Exact time requires a real local time and stores replayable UTC, offset, fold, provider,
      location, and runtime provenance.
- [x] Approximate time requires an explicit bounded uncertainty window and retains that uncertainty
      beside the resolved center instant.
- [x] Unknown time requires null birth time and stores no UTC, offset, fold, or runtime resolution.
- [x] All private birth input and provenance live in one owner/resource-bound encrypted payload;
      plaintext columns contain no date, time, place, coordinates, UTC instant, or label.
- [x] Persistence resolves the active account session inside the transaction and never trusts a
      caller-supplied user ID.
- [x] Cross-account reads return not found; writes use owner predicates, idempotency evidence, and
      optimistic revisions.
- [x] Individual deletion cryptographically overwrites the payload and tombstones the profile.
- [x] Privacy export includes active profiles, decrypts them, validates the keyed payload digest,
      and excludes operation hashes.
- [x] Selective and account privacy deletion overwrite all active profile ciphertext, record the
      count, and preserve the existing lawful-retention categories.

## Verification evidence

Focused domain, Web service, location/time-zone, privacy export, and privacy deletion tests pass.
The isolated PostgreSQL birth-profile verifier applies all 26 migrations and proves session
authorization, cross-account isolation, create replay, optimistic update conflict, tombstone
deletion, and denied physical delete/owner reassignment. The existing isolated privacy export and
privacy deletion verifiers both apply the same 26 migrations and prove birth-profile export and
ciphertext destruction through the dedicated deletion role.

Affected Domain, Divination, Database, and Web typechecks pass. The complete workspace unit/browser
matrix is intentionally deferred to the milestone/release integration gate because this task
changes no UI, production provider, native engine, payment, deployment, or public behavior.

## Risks and rollback

Approximate times remain lower-confidence inputs; downstream RIT-093 must preserve the profile
revision and full provenance snapshot and must suppress unsupported time-sensitive facts.
Historical pre-1970 time-zone results remain explicitly limited confidence.

Production create/update remains safe-off until a real approved location snapshot is imported and
composed. D-069/OWN-013 now permit local AGPL integration; OWN-015 blocks the exact astrology
method, retained natal calculation, and production release work in RIT-093.

Rollback disables the birth-profile application boundary, then reverses the additive migration
only before production data exists. After retained profiles exist, rollback must preserve the
tables and ciphertext or use a separately reviewed compatible migration; it must never silently
drop private birth data or privacy-deletion evidence.
