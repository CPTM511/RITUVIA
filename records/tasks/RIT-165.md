# RIT-165: Publish the pre-launch execution plan and exact product user manual

- Backlog item: RIT-165
- Related records: None

The queue state, priority, milestone, dependencies, and owner gates remain canonical in
[BACKLOG.md](../../BACKLOG.md).

## Outcome

Give the Owner one executable path from the current verified repository state to a limited public
launch, and give users, support, product, QA, and engineering one detailed Chinese manual that
explains every reachable workflow, exact visible control location, actual system behavior, state,
failure recovery, privacy boundary, and launch limitation without presenting test-mode or safe-off
capabilities as live.

## Scope

Included: reconcile current product truth and launch gates; define the critical path, dependencies,
evidence, owner decisions, rollback points, and go/no-go criteria; inventory actual routes and
visible controls from implementation and browser evidence; document anonymous core loop, account,
privacy, readings, numerology, astrology, content/share, commerce test-mode, accessibility, mobile,
offline, error, retry, and support workflows; explain deterministic, AI, persistence, and provider
boundaries; index and compile the new documents.

Excluded: changing product behavior, golden screenshots, database schema, provider configuration,
legal policy, prices, country eligibility, deployment, DNS, production AI, live payments, live
crypto, production data, or public launch; activating any frozen or owner-gated capability.

## Acceptance criteria

- [x] The launch plan starts from current repository truth and identifies one ordered critical path
      through technical, operational, legal/commercial, staging, rehearsal, and Owner go/no-go gates.
- [x] Each gate names its outcome, dependencies, required evidence, rollback point, and responsible
      approval without estimating unsupported calendar dates.
- [x] The detailed Chinese manual inventories every currently reachable user-facing route and
      workflow with exact visible English control labels, desktop/mobile location, prerequisites,
      success/loading/empty/error/offline/retry behavior, and current activation state.
- [x] Each workflow explains how the feature actually works across UI, server authority, domain
      logic, persistence, AI/deterministic boundaries, privacy, analytics, replay, and recovery.
- [x] Test-mode, safe-off, frozen, unimplemented, and production-gated capabilities are labelled
      explicitly and are never described as publicly live.
- [x] Documentation index, compiled manual source list, task/status/backlog records, checksums, and
      applicable documentation/record/link/generated-evidence gates pass.

## Risks and rollback

The main risk is a manual that drifts from visible UI or turns a repository capability into a false
production claim. Every workflow and control must be traced to current source or browser evidence,
and every launch step must preserve the production pack's explicit Owner gates.

Rollback removes the two new documents and their index/compiler entries, restores RIT-165 to its
prior queue state, and regenerates evidence. This task changes no runtime, schema, provider,
deployment, public copy, or production data.
