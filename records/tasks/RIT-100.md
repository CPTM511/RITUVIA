# RIT-100: ICU i18n and content translation workflow

- Backlog item: RIT-100
- Related records: D-027, D-074
- Owner approval: Not required; no non-English locale is activated

The queue state, priority, milestone, dependencies, and owner gates remain canonical in
[BACKLOG.md](../../BACKLOG.md).

## Outcome

The repository now has a strict `@rituvia/i18n` package for ICU message inspection and formatting,
BCP 47 locale and IANA time-zone canonicalization, explicit locale fallbacks, complete
locale-aware formatters, and fail-closed translation publication. A checksummed English source
catalog and approved glossary carry source version, editorial, rights, context, risk, reviewer,
placeholder, markup, link, and length metadata.

Six representative core messages run through the source catalog end to end. Reviewed account,
commerce, ritual, Tarot, shell, and astrology surfaces now use explicit locale formatting rather
than manual parameter replacement or fixed English formatters.

## Scope

Included: exact source, translation, and glossary schemas; pinned ICU dependencies; nested
plural/select formatting; strict message argument checks; content checksums; translation states
and methods; high-impact qualified review; source binding; key/placeholder/markup/link/length/
glossary/forbidden-term gates; process-owned publication authorization; explicit observable
fallback; Web source-catalog integration; architecture and localization regression gates.

Excluded: activation of another locale; Arabic RTL remediation; CJK/Devanagari typography;
localized slugs, hreflang, sitemap, or redirects; localized email/reminders; legal or policy
translation; machine publication; vendor workflow; production deployment; DNS; and public launch.

## Acceptance criteria

- [x] Source messages and glossary have strict versioned metadata and checksum evidence.
- [x] ICU plural, select, nested grammar, and exact placeholders format through one package.
- [x] BCP 47 locale, IANA time zone, number, currency, percent, unit, date, time, relative time,
      list, and display-name formatting use explicit inputs.
- [x] Missing, unexpected, stale, invalid, unsafe, overlong, untranslated, glossary, and review
      failures block publication.
- [x] Runtime admits only an exact validated and process-authorized approved translation.
- [x] Locale fallback is finite, explicitly configured, and emits structured fallback evidence.
- [x] Reviewed Web surfaces no longer use manual placeholder replacement or fixed English
      formatters.
- [x] No non-English locale or unreviewed translated content is activated.

## Risks and rollback

Automated checks cannot establish cultural quality, legal sufficiency, or support readiness for a
new locale. FormatJS adds pinned runtime dependencies, so dependency review and lockfile integrity
remain release requirements. The process-owned authorization set intentionally requires
revalidation after process restart.

Rollback removes `@rituvia/i18n`, the source catalog and manifest, Web catalog bridge, localization
gate, and explicit locale props, restoring the prior English-only implementation. No migration,
customer data, production state, secret, provider, payment, remote deployment, or irreversible
action requires reversal.
