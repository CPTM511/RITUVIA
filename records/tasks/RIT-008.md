# RIT-008: Document preview, staging, and production environments

- Backlog item: RIT-008
- Related records: D-090
- Owner approval: public AGPL repository governance is approved through D-090; protected
  preview/staging engineering is allowed by the production pack; production deployment, DNS,
  indexing activation, customer data, and provider activation remain separately gated

The queue state, priority, milestone, dependencies, and owner gates remain canonical in
[BACKLOG.md](../../BACKLOG.md).

## Outcome

Create one current, testable environment contract for local, preview, staging, and production so
deployment work cannot silently share secrets, data, provider authority, indexing state, or
irreversible migration risk across environments.

## Scope

Included: environment purpose and trust boundaries; isolation matrix; secret sources and rotation;
database, cache, object-storage, provider, analytics, and email boundaries; robots/indexing policy;
migration, backup, restore, promotion, rollback, evidence, and owner gates; a machine-verifiable
documentation contract.

Excluded: creating a hosting project, provisioning cloud services, production deployment, DNS,
Search Console, public product launch, customer or copied production data, live payment/crypto/AI/
email providers, production secrets, destructive migration, backup deletion, or weakening any
existing release gate.

## Acceptance criteria

- [x] One canonical document defines local, preview, staging, and production purpose, authority,
      allowed data, networking, access, lifetime, and promotion boundaries.
- [x] Every non-local environment uses isolated databases, caches, object storage, encryption and
      signing keys, provider projects/accounts or credentials, analytics destinations, and email
      authority; production secrets or private production content never flow downward.
- [x] Secret delivery, browser-exposure denial, least privilege, rotation, break-glass, audit, and
      revocation requirements are explicit.
- [x] Local, preview, and staging remain disallow-all/no-sitemap; production indexing requires the
      approved HTTPS canonical origin, current reviewed inventory, and a separate owner launch gate.
- [x] Migration, compatibility, backup, isolated restore, rollback/roll-forward, and destructive
      operation gates distinguish preview, staging, and production.
- [x] Deployment promotion requires exact revision, immutable build/source evidence, required CI,
      environment-specific configuration validation, smoke/security evidence, and recorded owner
      approval where applicable.
- [x] A focused verifier fails when required environment, isolation, indexing, data, secret,
      deployment, rollback, or approval language drifts.
- [x] README, architecture/runbook references, durable records, backlog, status, and generated
      evidence reflect the current contract without claiming a deployment.

## Risks and rollback

Documentation can create false confidence if it implies resources exist. Every environment row must
distinguish required future controls from currently verified implementation. RIT-016's isolated
loopback compatibility rehearsal is evidence of one protected staging pattern, not a standing
external staging service.

Rollback removes the environment contract and verifier only if superseded by a stricter approved
record. It does not delete infrastructure, data, backups, secrets, DNS, or deployment state.
