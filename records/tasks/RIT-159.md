# RIT-159: Production source-of-truth pack reality audit

- Backlog item: RIT-159
- Related records: D-045

The queue state, priority, milestone, dependencies, and owner gates remain canonical in
[BACKLOG.md](../../BACKLOG.md).

## Outcome

Install the owner-supplied 2026-07-23 production source-of-truth pack with only the repository's
required deterministic LF text normalization, reconcile its requirements against the current
repository and real browser behavior, and leave one evidence-based implementation sequence without
activating any production provider or duplicating existing architecture.

## Scope

Included: archive and golden-prototype integrity verification; committed source pack and root
instruction integration; current module, route, schema, API, authorization, payment, Credit,
entitlement, AI, localization, test, and operational capability mapping; a gap and security-delta
matrix; schema/OpenAPI adaptation guidance; existing quality gates; production-artifact browser and
accessibility evidence; and status/backlog/decision reconciliation.

Excluded: feature implementation, schema migration, provider SDK or credential setup, wallet/SIWE
implementation, Stripe or Coinbase activation, production AI calls, legal-policy activation,
production deployment, public launch, deletion of user-authored untracked files, and visual
baseline changes.

## Acceptance criteria

- [x] The ZIP, golden prototype, manifest, JSON contracts, OpenAPI, screenshots, and pack verifier
      pass their declared integrity checks.
- [x] The complete pack is committed under its recommended repository documentation path and its
      applicable rules are merged without overwriting stricter repository constraints.
- [x] The audit maps current routes, modules, database models, APIs, provider boundaries, tests,
      feature flags, and production-safe-off state to the new contracts.
- [x] A capability, gap, and security-delta matrix identifies reuse, missing production behavior,
      conflicts, owner gates, and the next dependency-ordered slices.
- [x] The proposed SQL and OpenAPI are adapted conceptually to existing models and routes; no blind
      migration or duplicate service is introduced.
- [x] Current repository checks and real-browser accessibility/responsive flows pass or every
      environmental/product failure is recorded exactly without weakening a gate.
- [x] Documentation, backlog, decision summary, durable records, and project status reflect the
      new truthful baseline.

## Verification evidence

The pack verifier, deterministic record/index checks, architecture/migration/instruction/secret
gates, formatting, lint, type checking, 1,440 unit tests, 145 AI release assertions, production
build, configuration boundary, production-artifact accessibility, and full PostgreSQL foundation
matrix pass. The exact command evidence, route/schema/API map, visual baseline inspection, disabled
capabilities, and accessibility corrections are recorded in
`docs/reports/RITUVIA_PHASE_0_REALITY_AUDIT_2026-07-23.md`.

The owner reran the three environment-dependent commands in an unrestricted shell using the pinned
Node.js 24.18.0 toolchain after Codex's approval path failed before process creation. Configuration
verification passed typed parsing, fail-closed startup, server-only imports, and client-delivery
secret isolation. Accessibility passed all four public and three private routes with 31 axe scans,
381 reviewed contrast nodes, keyboard, expanded-text, RTL, connectivity, interpretation,
touch-target, theme, no-JavaScript, screenshot, and local-request checks. Database verification
passed local PostgreSQL attestation, every MVP migration, seed, privileges, RLS, constraints,
transactions, races, resets, logical restores, anonymous identity, reading/reporting, and
interpretation claim/replay/fencing/fallback behavior. The obsolete owner-untracked
`apps/web/server/tarot-reading-state 2.ts` duplicate was removed after exact comparison with the
superseding canonical implementation.

## Risks and rollback

The largest risk is treating the golden prototype's simulations or proposed SQL as production
authority, or marking local MVP evidence as provider-ready. The audit therefore makes no schema or
runtime change and keeps every production provider safe-off.

Rollback removes only the newly installed documentation pack, restores the obsolete untracked
safe-off stub if still wanted, and reverts RIT-159 documentation, instruction, status, backlog, and
decision records. It does not mutate a database, provider, deployment, secret, payment, customer
record, or either D-030-excluded QA report copy.
