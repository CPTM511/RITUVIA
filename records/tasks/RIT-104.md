# RIT-104: Localize transactional email/reminder/support templates

- Backlog item: RIT-104
- Related records: D-075, D-078

The queue state, priority, milestone, dependencies, and owner gates remain canonical in
[BACKLOG.md](../../BACKLOG.md).

## Outcome

RITUVIA now has checksummed, versioned lifecycle-message architecture for the English once-only
Revisit reminder and a support-receipt preview, with exact delivery locale, time-zone and
quiet-hours authorization, immutable queue provenance, safe HTML/plain text, and no production send
capability.

## Scope

Included: lifecycle source/runtime catalogs and manifest binding; strict reminder and support
receipt renderers; locale/date/time-zone/quiet-hours formatting; safe headers and URLs; HTML/plain
equivalence; delivery suppression and preview-only fallback telemetry; immutable queue template
provenance; retained version registry; send-time date/time-zone/quiet-hours reauthorization;
privacy export; GET-safe preference deep link and focus; focused unit, architecture, localization,
migration, PostgreSQL, Chromium preview, and Revisit browser evidence.

Excluded: a scheduler; real provider or support mailbox; actual email; support service-level
claims; production legal/unsubscribe text; non-English production catalog; locale/country launch;
deployment; DNS; and public release.

## Acceptance criteria

- [x] English lifecycle source and runtime catalogs have exact identity, content type, checksum,
      and key/value parity.
- [x] Reminder jobs persist and validate template ID, version, source checksum, resolved locale,
      and fallback-used state.
- [x] Reminder rendering is lock-screen safe, private-content free, locale/time-zone aware,
      quiet-hours aware, and equivalent in semantic HTML and plain text.
- [x] Header/control/bidi and unsafe-link inputs fail closed before rendering or provider use.
- [x] Unsupported delivery locales are suppressed; explicit local preview fallback emits one
      deduplicated non-identifying event and cannot activate sending.
- [x] Synthetic exact non-English rendering remains test-only and does not enter production
      catalogs, routes, storage, or delivery.
- [x] Send-time authorization rechecks current ownership, preference, template, local date, time
      zone, due threshold, and quiet hours after claim.
- [x] Unknown template versions dead-letter before provider use and prior versions must remain
      registered while referenced.
- [x] The fragment-only reminder settings deep link is same-origin, GET-safe, focusable, preserves
      private-route query denial, and does not mutate consent.
- [x] Documentation, durable records, queue state, rollback, and owner gates match implementation.

## Verification evidence

Focused i18n, Domain, Worker, and Web tests cover catalog parity, binding agreement, exact locale
rendering, date/time-zone/quiet-hours behavior, strict input rejection, HTML/plain output,
delivery suppression, fallback telemetry, support receipt, unknown version rejection, and settings
focus. Package type checks and architecture, localization, migration, record, and secret policies
pass.

The isolated PostgreSQL gates deploy all migrations and prove additive provenance persistence,
runtime grants, privacy export, exact claims, once-only delivery, immediate unsubscribe, and
send-time denial after a claimed Revisit changes to a future date/time zone. The dedicated
320-pixel Chromium preview passes three Axe scans with zero external requests, storage writes,
layout failures, or locale activations. The focused Revisit browser proves GET-safe preference
navigation and consent preservation.

The complete 1,674-test workspace suite is intentionally deferred under D-050 because RIT-104 is
an ordinary focused task rather than a milestone integration or release-candidate gate.

## Approval outcome

No owner gate is crossed. English remains the only authorized lifecycle-message locale. Production
legal text, support address/service level, scheduler, email domain/provider, real sends, any
non-English catalog, locale/country launch, deployment, DNS, and public release retain their
existing owner gates. RIT-105 remains blocked on OWN-004.

## Risks and rollback

The main future risk is removing an old template version while delayed rows still reference it.
Rollout therefore registers a new version before selecting it and retains old versions until no
references remain. Roll back writers to a retained binding; unknown versions fail before provider
use. The additive database columns are privacy-minimal and may remain through code rollback.
