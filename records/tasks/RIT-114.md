# RIT-114: Structured data and complete public crawl validation

- Backlog item: RIT-114
- Related records: D-026, D-076, D-083, D-084
- Owner approval: Not required for internal implementation and validation; production deployment,
  DNS, Search Console, public launch, another locale, and actual indexing remain owner-gated

The queue state, priority, milestone, dependencies, and owner gates remain canonical in
[BACKLOG.md](../../BACKLOG.md).

## Outcome

Publish minimal source-authorized JSON-LD for every approved public page and prove the complete
45-route build and production HTTP crawl surface without exposing private data or crawler-only
claims.

## Scope

Included: centralized schema type and serialization contract; explicit reviewed page hierarchy;
visible H1, description, and parent-link parity; exact canonical and language identity; all-route
optimized-build and HTTP checks; representative real-browser schema and injection validation; CI,
documentation, and evidence integration.

Excluded: new content or routes; author, publisher, date, FAQ, HowTo, Product, Offer, rating, or
review schema; Search Console/Bing credentials; analytics; locale/country launch; deployment, DNS,
public launch, actual indexing, payment, database, or AI changes.

## Acceptance criteria

- [x] All 45 approved public pages emit exactly one schema graph node with the reviewed type,
      canonical URL, English language, and visible title and description.
- [x] Guide and collection hierarchy is derived from explicit inventory authority and requires a
      visible internal parent link; invisible breadcrumbs are not emitted.
- [x] Unknown schema shapes, unsupported claims, malformed inventory, hidden-copy substitution,
      canonical poisoning, and private-data injection fail closed.
- [x] JSON-LD serialization prevents script termination and executable injection.
- [x] Optimized-build and production HTTP validation cover the complete 45-route crawl inventory;
      real Chromium covers representative schema shapes and families.
- [x] Focused typecheck, lint, formatting, unit/contract tests, CI contract, architecture, records,
      generated evidence, and secret checks pass.

## Verification evidence

- D-084 centralizes the exact mapping: one `WebSite`, three `WebPage`, four `CollectionPage`, and
  37 `Article` documents.
- The build policy compares each graph to the canonical document, visible H1, visible main-copy
  description, and visible inventory-authorized parent link. Template, hidden, `aria-hidden`,
  script, and style content cannot satisfy those checks.
- The configuration boundary requests all 45 canonical public URLs and applies exact robots,
  canonical, hreflang, Open Graph, and JSON-LD checks to each response.
- The focused Chromium gate covers all four schema types across core, numerology, Tarot, and
  ritual/reflection examples and proves script-breaking input remains one inert JSON-LD node.
- Twelve focused test files pass 125 tests. Strict content and Web typechecks, focused ESLint and
  formatting, CI contract, and architecture pass. The optimized Next.js build generates 60 pages,
  and the build policy validates all 45 public artifacts within fixed budgets.
- The non-restricted production configuration boundary requests and audits all 45 canonical public
  pages. Chromium validates six representative static production documents, exact local
  account-session probe isolation, zero external requests, private-canary exclusion, and inert
  JSON-LD injection.
- No complete 1,674-test workspace rerun is required for this ordinary bounded task; affected
  contracts, optimized build, full public crawl surface, and focused browser behavior provide the
  task-specific closure evidence.

## Risks and rollback

Search-engine interpretation remains external and may evolve. The implementation intentionally
uses a conservative vocabulary and does not claim eligibility for rich results that require
unavailable visible authority. Search Console verification and live indexing remain release
operations rather than local completion evidence.

Rollback removes the centralized JSON-LD component and RIT-114 validation wiring while retaining
the D-083 public-page inventory. No database or customer-data rollback is required.
