# RIT-025: Private one-card tarot reflection flow

- Backlog item: RIT-025
- Related records: D-028, D-033, D-034

The queue state, priority, milestone, dependencies, and owner gates remain canonical in
[BACKLOG.md](../../BACKLOG.md).

## Outcome

The repository now contains a private, accessible, mobile-first theme-only one-card flow that
creates or resumes an anonymous session, requests one server-authoritative draw, explicitly reveals
the already fixed card, and presents a reviewed limitation, reflection question, and small action
without AI, account, payment, raw-question transfer, analytics, or redraw behavior.

## Scope

Included: exact private route and metadata; ten-theme choice; no-JavaScript safe state; separate Web
Crypto idempotency keys; cancellable session/read transport; manual same-key retry; conflict-only
start-over; server-side catalog presentation projection; strict V2 public response parsing; explicit
reveal; loading/offline/session/conflict/limit/unavailable/error states; responsive, RTL, dark,
reduced-motion, forced-color, keyboard, focus, touch-target, and screen-reader behavior; shared
catalog safe-off routing; build and browser evidence; and durable status/decision records.

Excluded: production catalog publication or activation, raw intake-question consumption, AI
interpretation, three-card flow, user-visible redraw, report/share, intention/ritual continuation,
analytics, offline caching, account/payment behavior, deployment, and public launch.

## Acceptance criteria

- [x] An anonymous mobile user can select one of ten reviewed themes and reach a useful one-card
      result with card/orientation, theme-specific possibility, alternative lens, limitation,
      reflection question, and one small action in a short linear flow.
- [x] The browser sends only the exact theme-only V1 command, never controls card/orientation or
      content, and rejects malformed, oversized, extra, mismatched, or non-one-card V2 responses.
- [x] Session and reading commands use distinct UUID V4 idempotency keys; explicit retry preserves
      them, conflict requires start-over, and reveal performs no request or redraw.
- [x] Page, API, framework representations, query variants, caching, metadata, and normal runtime
      fail closed behind the same approved-catalog gate; the synthetic fixture is never activated.
- [x] Loading, validation, offline, session, conflict, limit, service, generic error, ready, replay,
      revealed, mobile, no-JavaScript, dark, RTL, expanded-text, forced-color, and reduced-motion
      behavior have automated or browser evidence.
- [x] Focused/full tests, strict types, formatting, lint, architecture, production build/budgets,
      Chromium/axe, Playwright, configuration, record, generated-evidence, and secret gates pass.
- [x] Backlog, project status, decision/task records, record index, compiled manual, and checksums
      reflect the final verified slice.

## Risks and rollback

The UI and server projection are production-shaped, but no production tarot catalog is approved;
normal runtime therefore remains deliberately unavailable. Browser success uses an isolated
intercepted eligible response and is not evidence that the synthetic placeholder is publishable.
RIT-027 still owns broader limits/redraw/report UX, and RIT-028 owns the eventual combined
one/three-card deterministic E2E matrix.

No database schema, production state, customer data, analytics, AI, payment, deployment, or owner
gate changed. Roll back by removing the private page, V2 presentation/parser, and exact proxy page
allowlist while retaining the RIT-024 safe-off facts API. Once any V2 consumer exists, retain its
compatibility and use the runtime gate for rollback instead of altering historical facts.
