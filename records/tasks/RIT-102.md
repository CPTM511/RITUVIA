# RIT-102: CJK and Devanagari typography and input QA

- Backlog item: RIT-102
- Related records: D-077

The queue state, priority, milestone, dependencies, and owner gates remain canonical in
[BACKLOG.md](../../BACKLOG.md).

## Outcome

RITUVIA now has locale-specific local font fallbacks, CJK line-breaking and Devanagari shaping
contracts, React-controlled composition evidence, Unicode-safe private text handling, and
representative name/date/browser QA without activating another locale.

## Scope

Included: Japanese, Korean, Simplified Chinese, Traditional Chinese, and Devanagari fallback
stacks; strict CJK and normal grapheme-safe wrapping; removal of mobile `break-all`; test-only
script fixtures; hydrated Japanese/Hindi composition with forced rerender; actual platform-font
inspection; Devanagari shaping measurement; CJK punctuation line-boundary checks; native
Gregorian ISO dates; representative account/profile/private-text preservation; NFC storage;
ZWJ/ZWNJ admission with bidi/control rejection; CI-enforced static and browser gates; and durable
documentation.

Excluded: real locale activation; translated production content; locale routes or switcher;
remote fonts; country/payment/support/legal readiness; changing deterministic Gregorian
calculation inputs; browser/device linguistic sign-off; golden screenshot updates; production
deployment; DNS; and public launch.

## Acceptance criteria

- [x] Locale-specific local UI/display fallback stacks exist for Japanese, Korean, Simplified
      Chinese, Traditional Chinese, and Devanagari without a remote font surface.
- [x] Production CSS uses strict CJK line breaking and rejects `word-break: break-all`.
- [x] A hydrated React controlled field preserves Japanese and Hindi composition through an
      unrelated rerender and final candidate confirmation.
- [x] Browser evidence confirms four CJK punctuation/wrapping profiles, actual platform glyph
      providers, and measurable Devanagari shaping at 320 CSS pixels.
- [x] Representative names and private text preserve NFC, supplementary CJK characters, and
      legitimate ZWJ/ZWNJ while unsafe bidi/control characters remain rejected.
- [x] Client and server name bounds no longer disagree through native UTF-16 `maxlength`.
- [x] CJK/Hindi formatting uses explicit locale/time zone while native and deterministic date
      values remain canonical Gregorian `YYYY-MM-DD`.
- [x] Focused unit, type, lint, architecture, localization, RTL, CI, build, accessibility,
      privacy, record, and secret gates pass.
- [x] English remains the sole runtime/published locale and no owner gate is crossed.

## Verification evidence

Focused Vitest passes 233 tests across 14 UI styles/primitives/preview, CI and writing-system
policy, domain account/birth-profile/question/intention/reflection/ritual/Revisit text, Web
account response parsing, and i18n formatting files.

The dedicated Chromium gate reports two Axe scans, four CJK line-break scenarios, five actual
platform-font scenarios, two hydrated composition/rerender scenarios, two grapheme scenarios, two
temporary screenshots, 320-pixel reflow, and zero serious/critical Axe violation, external
request, storage write, console/page error, or locale activation.

The complete 1,674-test workspace suite is intentionally deferred under D-050 because RIT-102 is
an ordinary focused localization task.

## Approval outcome

No owner gate is crossed. English remains the only supported and published locale. Test-only
`lang` documents and synthetic strings do not approve Japanese, Korean, Chinese, Hindi, any
country, content set, support path, legal/payment copy, or production launch.

## Risks and rollback

Automated platform-font evidence does not establish typographic quality on every operating
system, and synthetic composition cannot replace final native-device IME, WebKit/Firefox,
VoiceOver/NVDA, or qualified linguistic review. Those remain release checks, not hidden
acceptance. Rollback is source-only and requires no migration, data reversal, provider action,
deployment change, or customer remediation.
