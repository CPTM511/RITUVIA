# RIT-166: Route the primary free-reading entry through approved safety intake

- Backlog item: RIT-166
- Related records: D-097

The queue state, priority, milestone, dependencies, and owner gates remain canonical in
[BACKLOG.md](../../BACKLOG.md).

## Outcome

Make the visible anonymous product journey begin at the approved private question/theme intake,
then continue to the same deterministic one-card reading and complete reflection loop without
introducing account, payment, production AI, or persistent question-text requirements.

## Scope

Included: change the primary homepage free-reading CTA and any equivalent approved core entry to
the activated localized intake route; preserve direct one-card routes as valid destinations;
reconcile loading, 404/safe-off, allowed, reframed, blocked, crisis, offline, unavailable, retry,
mobile, keyboard, focus, reduced-motion, and privacy behavior; update exact route/button/manual
evidence; extend the continuous production-artifact browser flow from `/en` through intake.

Excluded: changing approved intake policy/copy, persisting raw questions, adding AI classification,
changing deterministic Tarot, activating another locale/country, account requirements, pricing,
Credits, payment, deployment, DNS, public indexing, or golden screenshot updates without the
existing ADR and Owner gate.

## Acceptance criteria

- [x] `Begin a free reading` starts at the localized intake route when the approved activation
      reference is present; disabled/error activation remains fail-closed with no bypass link.
- [x] Allowed and user-adopted reframed paths continue to the same private one-card reading using
      only the approved theme handoff; blocked and crisis states never expose a reading action.
- [x] Raw question text remains absent from URLs, metadata, analytics, persistent intake storage,
      browser history, reading creation, reports, and logs.
- [x] Home-to-Revisit production-artifact browser evidence covers desktop, 320px mobile, keyboard,
      focus, reduced motion, offline/unavailable/retry, Axe, and privacy canaries without account,
      checkout/payment, production AI, or unexpected requests.
- [x] Direct one-card URLs remain valid, rollback is one bounded navigation change, and all
      affected documentation, route inventories, records, generated evidence, and checks pass.

## Verification evidence

The homepage Hero and one-card card now route to localized intake. Allowed results use a
one-time, categorical theme handoff and replace navigation to the existing one-card route;
reframed and blocked suggestions require explicit adoption and resubmission, while blocked and
crisis results expose no reading action and clear the raw draft. Production activation accepts
only `own-009.question-intake.en.v1`.

Focused handoff, form, shell, route, proxy, configuration, and privacy-contract tests pass with
178 Web assertions and 25 configuration assertions. The Web typecheck and 61-page production
build pass. `pnpm test:configuration-boundary` passes its isolated production, safe-off, secret,
and exact activation checks. `pnpm test:accessibility` passes the continuous Home-to-Revisit
browser journey and the public/private accessibility matrix with zero serious/critical Axe
violations, account creation, payment requests, unexpected requests, layout/touch-target failures,
console/page errors, or private storage/metadata/history leaks.

## Risks and rollback

The principal risk is making the first anonymous value inaccessible when intake activation is
missing or misconfigured. The implementation must fail closed rather than silently bypass safety,
and release configuration must prove the exact activation reference before exposing the homepage.

Rollback restores the previous homepage target while preserving the intake route, policy, tests,
and historical D-097 decision. A rollback does not authorize public launch or make direct-to-Tarot
equivalent to the approved intake-first product contract.
