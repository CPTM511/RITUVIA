# RIT-164: Reconcile the restored-schema drift baseline and backup recovery gate

- Backlog item: RIT-164
- Related records: None

The queue state, priority, milestone, dependencies, and owner gates remain canonical in
[BACKLOG.md](../../BACKLOG.md).

## Outcome

Restore trustworthy backup-recovery evidence by explaining and reconciling the exact SQL drift
between the restored database and the canonical Prisma schema without touching production data or
weakening drift detection.

## Scope

Included: capture the normalized restored-schema SQL delta; compare it with all 39 immutable
migrations, Prisma schema, grants, views, triggers, and recent commerce changes; determine whether
the verifier target or reviewed baseline is stale; apply only an evidence-backed reversible fix;
and rerun local backup recovery plus applicable CI, migration, record, and generated-evidence gates.

Excluded: destructive migration; production restore or data mutation; accepting a new baseline
without reviewing its SQL; suppressing drift; changing retention, backup policy, provider state,
golden screenshots, product scope, deployment, or DNS.

## Verification evidence

RIT-163 reached restored-schema verification under Node.js 26.5.1 and received the fingerprint
above instead of the reviewed
`f564815fc5f4c5f8c23fc8b47d98d995e32f5d70a4c72e5c2a36890e6b4ca84c` baseline with 18,271 bytes
and 371 lines. Running the same drill directly under Node.js 24.18.0 produced the identical new
fingerprint, proving that the failure predates and is independent of the runtime upgrade.

The normalized 485-line SQL contains 161 statements: 70 `DropForeignKey`, two `DropIndex`, one
`AlterTable`, 83 `RenameForeignKey`, and five `AddForeignKey`. Every object maps to the existing
immutable migration history. The complete 4,744-byte/114-line increase maps exactly to 38
database-only foreign keys added by the seven post-baseline commerce migrations; no unknown object
or migration rewrite is accepted. The object-level review is recorded in
[`docs/reports/RITUVIA_RIT_164_SCHEMA_DRIFT_REVIEW_2026-07-31.md`](../../docs/reports/RITUVIA_RIT_164_SCHEMA_DRIFT_REVIEW_2026-07-31.md).

The only implementation change updates the reviewed fingerprint metadata in
`packages/db/prisma/schema-drift-baseline.json`. The verifier remains fail-closed and still requires
the exact Prisma version, byte count, line count, and SHA-256 digest.

Under Node.js 26.5.1 and pnpm 11.13.1, the focused baseline test passes four assertions; migration
policy passes all 40 immutable files; `pnpm test:backup-recovery-database` applies all 39 migrations
and verifies synthetic custom-format backup, isolated restore, snapshot equality, least privilege,
and cleanup; and the database package typecheck and build pass. `pnpm test:ci-database` is not a
local database gate and correctly refuses a non-GitHub ephemeral target; its CI contract and safety
tests pass separately. Record, generated-evidence, formatting, lint, and workspace type gates pass
after state synchronization.

## Risks and rollback

The risk is normalizing a real unreviewed schema difference into the baseline. The task must inspect
the SQL, not only its hash, and must not edit an immutable migration.

Rollback restores the prior verifier or baseline file from Git and regenerates evidence. The task
uses only isolated synthetic local databases and performs no production or irreversible action.
