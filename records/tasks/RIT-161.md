# RIT-161: Core-loop product convergence

- Backlog item: RIT-161
- Related records: D-095

The queue state, priority, milestone, dependencies, and owner gates remain canonical in
[BACKLOG.md](../../BACKLOG.md).

## Outcome

Make one owner-verifiable product stage authoritative: an adult can move from a question or theme
through a useful symbolic interpretation, intention, small action, free ritual, private reflection,
and optional Revisit without account or payment pressure.

## Scope

Included: split the mixed product guide into a plain-language user guide, an owner capability map,
and an engineering runbook; publish an explicit Keep/Freeze/Delete-candidate inventory; pause
non-core queue expansion; preserve the production pack's safety and security invariants; and
reverify the existing production-artifact core-loop browser journey.

Excluded: deleting implementation code; changing database schemas; modifying golden screenshots;
activating production AI, email, astrology, payments, countries, or locales; changing legal or
retention policy; deploying; changing DNS; or claiming public production readiness.

## Acceptance criteria

- [x] The user guide contains only user goals, steps, boundaries, recovery, privacy, and
      accessibility language; it contains no task IDs, API/database internals, or test commands.
- [x] The owner capability map states one stage goal, one acceptance journey, plain-language status,
      current gaps, and explicit Keep/Freeze/Delete candidates.
- [x] The engineering runbook owns routes, modules, local startup, focused verification, and frozen
      scope so those details no longer appear in the user guide.
- [x] RIT-074 and other non-core expansion remain Planned; no non-core feature becomes Ready during
      this reset.
- [x] The existing core-loop browser journey passes from the production build with no payment
      request, serious/critical accessibility violation, or private-data leak.
- [x] Record, generated-evidence, formatting, link, and documentation checks pass.
- [x] Project status, backlog, decision register, task record, and documentation index agree.

## Risks and rollback

The primary risk is mistaking a sequencing reset for permission to remove production safeguards or
silently abandon approved long-term requirements. D-095 keeps safety, privacy, payment, AI, legal,
localization, and release gates authoritative while changing only the current execution focus.

Rollback restores the prior queue statuses and document index. No code, schema, production data,
provider setting, golden screenshot, or irreversible artifact is changed by this task.
