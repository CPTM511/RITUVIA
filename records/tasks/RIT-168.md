# RIT-168: Protected-Beta invite admission and revocation contract

- Backlog item: RIT-168
- Related records: D-097, D-100, D-104, D-112
- Owner approval: D-104 approves the exact protected-Beta cohort and invite posture. Deployment,
  public access, standing staging, external edge/provider configuration, and launch remain separate
  Owner gates.

The queue state, priority, milestone, dependencies, and owner gates remain canonical in
[BACKLOG.md](../../BACKLOG.md).

## Outcome

Require one deny-by-default, opaque, single-use or explicitly revoked invite before anonymous
session issuance for the approved at-most-25-person English adult protected Beta, without adding
network/device fingerprinting, public access, or production deployment.

## Scope

Included: exact invite state contract, cryptographic token handling, atomic consume/replay/revoke,
cohort cap, expiry, session binding, least privilege, redacted telemetry, calm invalid/expired/used/
revoked/unavailable recovery, restore evidence, and focused Web/database/browser verification.
Excluded: email delivery, mass messaging, external WAF/CAPTCHA/vendor activation, device or IP
profiling, account creation, payment, production AI, public indexing, staging creation, deployment,
DNS, or launch.

## Acceptance criteria

- [x] Anonymous session issuance fails closed before session creation without one valid unconsumed,
      unrevoked, unexpired invite under the exact D-104 policy version.
- [x] Invite creation/consume/replay/revoke and the 25-person cohort cap are database-atomic and
      restore-safe; changed replay and concurrent double use fail deterministically.
- [x] Storage and telemetry contain only bounded policy/state metadata and one-way token evidence;
      no raw token, IP, user agent, device identifier, question, or other private content is logged
      or persisted.
- [x] User recovery is calm and accessible for missing, invalid, used, expired, revoked, and
      temporarily unavailable admission without exposing cohort or internal state.
- [x] Existing safety intake, rate limits, free core loop, logout/revocation, containment, and
      no-payment/no-provider boundaries remain unchanged.
- [x] Focused unit, route, PostgreSQL race/privilege/restore, browser/accessibility, architecture,
      build, record, generated-evidence, and secret gates pass under Node.js 26.5.1 and pnpm 11.13.1.

## Risks and rollback

This repository-local contract does not prove protected ingress, standing staging, external
monitoring, provider restore, independent security review, Gate H, or deployment readiness.
Rollback disables invite issuance/consumption composition and preserves immutable synthetic
evidence; deleting records or changing production admission/retention requires a reviewed forward
change and explicit Owner approval.
