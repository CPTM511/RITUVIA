# RIT-163: Upgrade the pinned Node.js toolchain to 26.5.1

- Backlog item: RIT-163
- Related records: D-096

The queue state, priority, milestone, dependencies, and owner gates remain canonical in
[BACKLOG.md](../../BACKLOG.md).

## Outcome

Run local development, CI, builds, tests, and new deterministic time-zone results on one exact
Node.js 26.5.1 contract before simplifying the product implementation.

## Scope

Included: canonical Node pins; matching Node type declarations and lockfile; CI contract and
mutation tests; deterministic runtime provenance and fixtures; active architecture and development
documentation; full workspace regression evidence.

Excluded: dependency upgrades unrelated to Node; database migrations or stored-data rewrites;
production deployment or provider activation; golden screenshot changes; product behavior changes;
and RIT-162 dead-code deletion.

## Acceptance criteria

- [x] `.node-version`, package engines, pnpm resolution policy, CI contract, and Node type
      declarations agree on Node.js 26.5.1.
- [x] The official exact runtime reports Node.js 26.5.1, ICU 78.3, and tzdata 2026b.
- [x] New historical-time-zone results and tests carry the exact 26.5.1 runtime provenance while
      historical task, decision, and persisted evidence remain unchanged.
- [x] Focused CI-contract, time-zone, birth-profile, and privacy-export tests pass.
- [x] Full quality, database-foundation and subscription, browser/accessibility, native security,
      and generated-evidence gates pass under Node.js 26.5.1 and pnpm 11.13.1; the separately
      failing pre-existing backup drift baseline is isolated in RIT-164.
- [x] Project status, backlog, decision register, task record, and generated evidence agree.

- `APP_ENV=local BRAND_CANONICAL_ORIGIN=http://localhost:3000 pnpm check` passes evidence,

- Commercial subscription persistence passes. Native security passes 151 mutation cases; live OSV

## Risks and rollback

Node.js 26.5.1 is a Current release on the upgrade date, so runtime regressions and shorter support
horizon are the primary risks. Exact pins, focused deterministic tests, and the complete local CI
matrix contain that risk before any production action.

The Homebrew formula available during execution remained at 26.5.0 after `brew update`; repository
and CI verification therefore used the official exact 26.5.1 binary. Plain shell `node` remains
dependent on the owner's package-manager update cadence, while repository commands fail closed on
any non-26.5.1 runtime.

Rollback restores the active runtime, engines, pnpm resolution version, Node type declaration,
lockfile, CI contract, and new-result provenance to the prior Node.js 24.18.0 baseline. There is no
schema migration, production data mutation, provider action, deployment, or golden screenshot
change to reverse.
