# RIT-053: Privacy export workflow

- Backlog item: RIT-053
- Related records: D-055

The queue state, priority, milestone, dependencies, and owner gates remain canonical in
[BACKLOG.md](../../BACKLOG.md).

## Outcome

Let a recently authenticated account request, inspect, and download a complete export of the
currently implemented account-linked data through an owner-scoped, idempotent, encrypted,
short-lived workflow with append-only privacy audit evidence.

## Scope

Included: the production-pack `POST /api/v1/privacy/export` request boundary; session-bound CSRF;
server-side recent-authentication enforcement; per-account rate limiting; request idempotency;
account authorization without a client-selected owner; one versioned package containing a
human-readable Markdown summary and machine-readable JSON data; currently retained account
profile, verified identity, active-session metadata, immutable subject links, consent, Tarot,
interpretation/report, intention, ritual, journal, Revisit, and implemented commerce data;
authorized decryption of private fields; a separately keyed AES-256-GCM export artifact stored
only as ciphertext; database-clock expiry; integrity evidence; private no-store metadata and
download responses; separate immutable request and one-per-request artifact rows; append-only
requested, completed, failed, and download-authorized audit events; and focused parser,
cryptography, route, PostgreSQL, authorization, configuration, privacy, and recovery verification.

Excluded: changing legal/privacy text or final jurisdictional retention periods; production
object storage, KMS activation, asynchronous queue/outbox infrastructure, email delivery, support
or admin access, export of data categories not yet implemented, deletion, consent changes,
provider activation, deployment, public launch, new locale activation, and golden screenshot
updates. The local modular-monolith slice keeps the encrypted artifact in PostgreSQL and leaves
provider-neutral object storage/worker delivery for the existing infrastructure milestones.

## Acceptance criteria

- [x] A request without an active recently authenticated account session, exact same-origin
      evidence, session CSRF, valid idempotency key, configured export key, or available rate
      capacity fails closed without creating an export or audit row.
- [x] Concurrent or replayed same-key requests create one account-owned export; another account or
      another canonical request cannot claim or inspect it.
- [x] A completed export contains versioned human-readable Markdown and machine-readable JSON for
      every currently implemented, retained account-linked data category, with private fields
      decrypted only inside the authorized builder and no bearer/hash/key material included.
- [x] The stored artifact is authenticated ciphertext bound to the account, export identifier,
      schema, and expiry; tampering, wrong key, cross-account access, expiry, and unavailable
      storage fail closed.
- [x] Metadata and download responses are private/no-store/noindex; download requires the current
      account session plus session CSRF and records append-only authorization evidence without
      logging or auditing private content.
- [x] Focused unit, route, database, configuration, architecture, migration, secret, type, lint,
      formatting, record, generated-evidence, and affected-package build gates pass without
      repeating the unrelated complete workspace suite.

## Planned files and verification

Primary areas are a dedicated privacy-export migration and database persistence boundary; a
Web-only export cryptography/builder/application service; privacy request, metadata, and download
routes; strict server configuration and environment examples; focused unit/route tests; and an
isolated PostgreSQL privacy-export gate. Current privacy, data, API, test, backlog, status, and
decision records will be reconciled after implementation.

Run the export cryptography/builder/persistence and HTTP tests first, then the dedicated PostgreSQL
gate covering recent authentication, idempotency, concurrency, owner isolation, completeness,
expiry, tamper resistance, audit immutability, and runtime privileges. Close with affected
formatting, linting, type checking, architecture, migration, CI-contract, secret, record,
generated-evidence, checksum, and database/Web production builds. The complete workspace and
browser matrix remains reserved for RIT-057 or another explicit integration trigger.

## Risks and rollback

Main risks are exporting another account's data, omitting an implemented private category,
plaintext persistence or telemetry leakage, stale-auth bypass after session rotation, unbounded
artifact growth, incomplete idempotency after response loss, expired download availability, and
mutable audit evidence. Rollback disables the privacy routes and builder while retaining encrypted
request/audit rows for later policy-governed cleanup. No destructive migration, final retention
decision, production data mutation, provider activation, deployment, or golden baseline change is
authorized.
