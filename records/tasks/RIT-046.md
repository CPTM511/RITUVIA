# RIT-046: Privacy-safe core-loop analytics and WMRS

- Backlog item: RIT-046
- Related records: D-050, D-051

The queue state, priority, milestone, dependencies, and owner gates remain canonical in
[BACKLOG.md](../../BACKLOG.md).

## Outcome

Create a strict, purpose-scoped analytics boundary for the anonymous Tarot reflection loop so
synthetic consented events can reconstruct the core funnel and a versioned seven-day WMRS
projection without exposing private text, raw identity, resource identifiers, or browser data.

## Scope

Included: a framework-independent `@rituvia/analytics` package; an exact closed event union;
purpose-scoped pseudonymous subject, session, reflection-session, and semantic-event keys; a
fail-closed Web adapter that requires the exact optional-product-analytics consent purpose and
notice version; a bounded in-memory sink for tests only; deterministic deduplication, funnel, and
WMRS projections; server-authoritative event intents after successful reading, intention, ritual,
journal, and Revisit transitions; interpretation-viewed contract support without a browser queue;
private-canary and adversarial-object tests; and layered task-specific verification.

Excluded: production event persistence or export; third-party SDKs; browser storage, beacon, or
offline analytics queues; analytics consent UI or legal copy; retention/deletion policy activation;
historical backfill; account merge; bot classification; production dashboards; acquisition,
commerce, experiment, safety-risk, or marketing analytics; production deployment; and changes to
golden screenshots.

## Acceptance criteria

- [x] Event contracts accept only a versioned nine-event core-loop set and exact safe categorical
      fields, rejecting private text, raw UUIDs, arbitrary properties, malicious accessors, and
      unknown keys.
- [x] The Web adapter emits nothing unless the exact consent purpose and notice version are
      currently allowed, derives purpose/version/environment-isolated keyed pseudonyms, never
      exposes source identifiers, and cannot block the product when analytics is unavailable.
- [x] Semantic event keys and projections deduplicate retries and replay, preserve event-time
      ordering, identify late data, and reconstruct the reading-to-revisit funnel.
- [x] WMRS v1 counts distinct consented anonymous analytics subjects with at least one Tarot
      reflection session containing deterministic reading completion followed by intention,
      ritual completion, journal creation, or Revisit completion in `[asOf - 7 days, asOf)`;
      qualifying reflection sessions are reported separately.
- [x] Successful non-replayed server transitions produce only safe event intents; business
      rollback, replay, account-only sessions, missing consent, denied/withdrawn/stale consent, and
      sink failure produce no duplicate event and never fail the user operation.
- [x] Production composition remains hard safe-off with no event table, outbox, vendor, network,
      credential, browser storage, or historical inference.
- [x] Focused analytics, Web application-service, formatting, lint, type, architecture, records,
      generated-evidence, and secret checks pass without rerunning the complete workspace suite.

Run the analytics package tests first, then focused Web service/adapter tests. Close with
affected-package type checking, targeted lint/format, architecture, records, generated evidence,
and secret scanning. Defer the complete 1,574-test workspace suite and anonymous full-loop browser
matrix to `RIT-047` unless focused evidence identifies cross-cutting risk.

## Risks and rollback

Primary risks are converting the necessary anonymous cookie into analytics consent, leaking raw
identity or reflection text through event fields, treating generation as user viewing, counting
replays, allowing analytics failure to affect the product, and claiming population-wide metrics
from only consented subjects.

The slice therefore remains safe-off, uses exact typed inputs and keyed pseudonyms, separates the
interpretation-viewed contract from server generation, emits only after successful non-replayed
state changes, and labels WMRS v1 as consented-anonymous coverage. Rollback removes the package and
injectable event intents; there is no persisted or externally transmitted analytics data to
migrate or delete.
