# RIT-056: Admin roles, MFA requirement, and audit foundation

- Backlog item: RIT-056
- Related records: D-052, D-057

The queue state, priority, milestone, dependencies, and owner gates remain canonical in
[BACKLOG.md](../../BACKLOG.md).

## Outcome

Provide a server-authoritative, default-deny admin authorization kernel with the canonical role
matrix, owner-only role lifecycle, recent authentication plus same-identity passkey assurance,
digest-only safe diffs, atomic tamper-evident audit evidence, and a dedicated least-privilege
database login without activating a production admin application or WebAuthn ceremony.

## Scope

Included: one dependency-free security policy package; five canonical roles and finite actions;
append-only role grants/revocations; singleton operator bootstrap; final-owner protection; exact
typed confirmation; active/recent account-session checks; short-lived MFA assertions bound to the
same user/session/auth identity/passkey; successful and denied privileged-action evidence;
allow-listed changed fields and before/after digests; a serialized SHA-256 audit chain; atomic
mutation/audit rollback; exact `rituvia_admin_service` privileges; focused unit, PostgreSQL,
migration, recovery, architecture, CI-contract, secret, type, lint, format, record, and build
verification.

Excluded: production WebAuthn registration/assertion or MFA issuance; admin UI/routes; support
private-content grants; refund execution; content/policy/payment/model publication; bulk actions;
production role bootstrap; audit retention activation; deployment; public launch; legal/privacy
changes; and golden screenshot updates.

## Acceptance criteria

- [x] Unknown roles/actions and ordinary users fail closed; each non-owner role has only its exact
      finite capability and no private-content read action.
- [x] Role changes require an active owner assignment, non-stale/non-future reauthentication,
      matching live passkey MFA evidence, and exact typed confirmation.
- [x] Role grants/revocations are append-only, duplicate active roles conflict, and the final active
      owner cannot be revoked.
- [x] Successful and denied privileged attempts emit bounded audit evidence containing no raw
      before/after values, secrets, bearer tokens, email, journal, prayer, prompt, or wallet data.
- [x] Authorization, mutation, and audit append are one serializable transaction; audit failure
      rolls back the role change and predecessor uniqueness prevents chain forks.
- [x] The dedicated database login cannot issue MFA assertions, mutate/delete/truncate audit
      evidence, read private journals, own schema objects, or perform DDL.
- [x] Focused policy, PostgreSQL migration/replay/constraint/privilege/restore, type, lint,
      formatting, architecture, migration, CI-contract, secret, record, generated-evidence, and
      affected-package build gates pass without running the full RIT-057 matrix.

Run the three policy tests and CI database-safety unit tests first, then the dedicated PostgreSQL

## Risks and rollback

Main risks are credential-to-user mismatch, magic-link-only escalation, stale MFA/reauth, duplicate
or unrevokable roles, revoking the final owner, mutation without audit, audit chain forks, private
values in diffs, and an overprivileged admin database login. Rollback keeps every admin route
absent and stops use of the dedicated login; append-only role and audit evidence must not be
deleted. Production MFA/enrollment/bootstrap, retention, deployment, and launch remain owner
gates.
