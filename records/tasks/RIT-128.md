## Outcome

Execute one reproducible local failure matrix across security, containment, AI, payments,
notifications, database control/recovery, dependency ownership, and secret boundaries; close every
repository-scope Critical/High finding; and record external evidence gaps without claiming Gate H.

## Scope

Included: existing fixed security/abuse/authorization controls; correlated Web read-only mode; AI
timeout/unavailable/malformed/late/trust failure; payment provider unavailability, reconciliation,
duplicate/out-of-order webhook behavior; reminder provider retry/dead letter; dynamic astrology
kill switch; local custom-format backup/isolated restore; CI/architecture/secret policy; one manual
command, runbook, report, and project records.

Excluded: standing staging; production metrics/pager/status; provider credentials or calls;
provider-managed PITR/restore; live payment/AI/email/wallet controls; customer communication; hosted
DAST; independent penetration test; production mutation, deployment, DNS, public access, launch;
RIT-127 budget authority or runtime ledger implementation.

## Acceptance criteria

- [x] Security, anonymous-capacity, authorization, route-enumeration, SLO unknown/breach, and Web
      read-only scenarios fail closed without private content.
- [x] AI timeout, unavailable, malformed/hostile, late, and trust-denied scenarios preserve bounded
      retry/fallback/verification and make zero external or paid calls in release evals.
- [x] Payment provider unavailability, missed webhook, 20-way duplicate delivery, out-of-order
      replay, refund mismatch, reconciliation, least privilege, and zero-ingestion-fulfillment pass.
- [x] Notification provider disabled, unavailable, rejected, timeout, stale-template, retry, dead
      letter, authorization, hard ignore-abort deadline/cancellation, and idempotency scenarios pass
      without an external send.
- [x] Stripe account transport failure and payment/subscription/reconciliation database claim/list
      outages recover inside their own loops without collapsing unrelated Worker work.
- [x] The database kill switch finishes safe-off and the custom-format isolated restore proves exact
      snapshot equality, least privilege, and cleanup.
- [x] One exact `pnpm test:incident-game-day` entry point and runbook map every scenario, expected
      outcome, response rule, evidence boundary, known gap, and rollback.
- [x] All three discovered High findings and the missing consolidated entry point are remediated and
      retested; zero repository-scope Critical/High finding remains, and Medium pre-activation gaps
      have explicit owners and compensating safe-off controls.
- [x] The final repeatable game-day command, focused checks, record/generated evidence, and complete
      workspace gate pass after the new records and state reconciliation.

## Risks and rollback

Repository-local simulation cannot prove provider-managed recovery, external alert delivery,
standing-staging behavior, customer communication, or an independent penetration test. Live
providers remain safe-off. Production AI circuit-breaker/provider-health and real provider-key
rotation remain pre-activation Medium gates. OWN-005 Option A deliberately leaves RIT-127 Blocked
and must not be treated as budget completion.

Rollback removes the package command, runbook, report, task record, and state references. Test
databases and build outputs are disposable; no production or provider state requires reversal.
