# RIT-073: Commerce Admin and Immutable Event Timeline

- Backlog item: RIT-073
- Related records: D-093, D-094

The queue state, priority, milestone, dependencies, and owner gates remain canonical in
[BACKLOG.md](../../BACKLOG.md).

## Outcome

Provide a safe-off, owner-only single-order commerce administration kernel with a bounded immutable
timeline, durable idempotent reconciliation and refund commands, separate execution evidence, and
fail-closed least-privilege storage.

## Scope

Included: reviewed order and timeline projections; stable pseudonymous account reference; recent
account authentication; same-session passkey assertion; reason and ticket references; typed
confirmation; bounded inspection, reconciliation, refund, lease, and retry policy;
provider-neutral executors; append-only operation attempts; audit hash chain; event digests;
concurrent replay; policy-version replay; and runtime privilege attestation.

Excluded: admin HTTP route or UI; production passkey challenge issuer; Stripe Live executor;
customer support workflow; dispute evidence workflow; production migration; deployment; DNS;
legal-policy activation; and launch.

## Acceptance criteria

- [x] Only an active owner with recent authentication and a recent same-session passkey assertion
      can inspect or command an order.
- [x] The service reads only reviewed security-barrier projections and cannot read raw commerce
      tables or private journals.
- [x] Historical creation events remain `created` even when current order or payment-attempt state
      has advanced.
- [x] Reconciliation and refund commands require reason, ticket, typed confirmation, explicit
      limits, and durable acceptance before executor invocation.
- [x] Concurrent exact retries converge on one operation and one executor call; changed order,
      amount, or currency conflicts fail closed.
- [x] Exact replay remains valid after a limit-policy version change.
- [x] Executor failure is recorded and exact retry reuses the operation identifier.
- [x] Audit and operation-event evidence verifies cryptographically and cannot be updated,
      deleted, or truncated by the service role.
- [x] Automatic runtime attestation rejects raw-table, mutation, DDL, owner, or privileged-role
      drift before every public service method proceeds.

## Risks and rollback

Primary risks are excessive operator visibility, mutable-state history, concurrent double
execution, false provider completion, unbounded support actions, audit flooding, and privilege
drift. Safe projections, immutable event state, advisory-lock serialization, durable idempotency,
separate execution events, explicit policy limits, complete denial audit, a safe-off entrypoint, and
automatic attestation contain those risks.

Rollback disables the future route and executors. Existing operations, attempts, outcomes, and
audit-chain records remain append-only and queryable. No destructive migration, payment-fact
rewrite, or audit deletion is permitted.
