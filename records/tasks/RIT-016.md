# RIT-016: Retire and remove the public-shell rollout flag

- Backlog item: RIT-016
- Related records: D-089
- Owner approval: protected staging compatibility validation and registry v3 removal explicitly
  approved on 2026-07-29; production deployment, DNS, indexing, and public launch remain gated

The queue state, priority, milestone, dependencies, and owner gates remain canonical in
[BACKLOG.md](../../BACKLOG.md).

## Outcome

Retire the temporary `experience.public_shell` flag safe-off for one real registry compatibility
window, then remove its definition, adapter, branches, and old-history influence in registry v3.

## Scope

Phase one included: registry v2 retired tombstone; v1 no-reactivation; v2 exact append policy; and a
database-independent completed-rollout Web adapter.

Phase two included: protected v2/v1/v2 and v3/v2/v3 compatibility windows; registry v3; removal of
the retired key, adapter, proxy compatibility branches, obsolete synthetic matrices, and v1/v2
runtime-history influence.

Excluded: self-approved production migration or deployment; DNS; Search Console; public launch;
country, locale, provider, payment, astrology, AI, or content activation; destructive history
deletion; a replacement environment/request flag.

## Acceptance criteria

- [x] Registry v2 retains `experience.public_shell` as retired and safe-off.
- [x] A v2 public-shell on-version fails typed parsing and PostgreSQL policy.
- [x] New v1 on-versions are denied while emergency off history remains append-only.
- [x] Remaining v2 flags preserve exact owner approvals, scopes, safe-off defaults, and history.
- [x] Fresh local seeds no longer create an obsolete v1 public-shell activation.
- [x] Web request delivery no longer reads the public-shell flag or database.
- [x] Page/API availability remains independent from SEO inventory freshness.
- [x] Non-production remains noindex; production crawl output still requires current inventory.
- [x] One owner-approved deployment/rollback registry compatibility window is recorded.
- [x] Registry v3 removes the retired key, adapter, compatibility branches, and v1/v2 influence.
- [x] Focused type, unit, proxy, configuration, migration, PostgreSQL, architecture, record,
      lint/format, and build-export checks pass for both phases.

## Risks and rollback

The evidence is a protected staging compatibility deployment, not a production or public-release
claim. No external hosting project, customer traffic, production credentials, DNS, or indexing was
used.

Rollback selects the prior exact application revision and registry-version reader. Immutable
history is not deleted or rewritten; legacy writers may append `off` but cannot create a new
activation.
