# RIT-117: Offline SEO/GEO performance and freshness operations

- Related records: D-083, D-087

The queue state, priority, milestone, dependencies, and owner gates remain canonical in
[BACKLOG.md](../../BACKLOG.md).

## Outcome

Produce an auditable weekly SEO/GEO performance and freshness brief from approved aggregate
evidence without collecting private data, confusing missing data with failure, or automatically
taking content, indexing, provider, or production action.

## Scope

Included: strict offline aggregate schema; exact seven-day window; source labels and freshness;
exact 45-route authority; locale/content-family/coarse-intent summaries; crawl, index, query,
referral, editorial, source, and rights metrics; low-sample suppression; bounded review prompts;
SHA-256 evidence binding; private exclusive report files; deterministic Markdown; CI and build
contracts; operations documentation.

Excluded: live Search Console or analytics connection; browser tracking; raw query/referrer data;
user/session/private content; database persistence; provider credentials; automatic content or
metadata changes; indexing requests; route or locale expansion; deployment, DNS, and launch.

## Acceptance criteria

- [x] The parser accepts only exact aggregate crawl, index, query, and referral fields for the
      current 45 reviewed routes and rejects unknown/private fields, accessors, and authority drift.
- [x] Every source exposes kind, approval reference, observed-through time, maximum age, and
      current/stale/unavailable/synthetic status.
- [x] Stale, unavailable, or synthetic evidence yields null performance values, blocked decision
      use, and no performance recommendation.
- [x] Route query/referral detail is suppressed below 20 observations; 20–199 remains diagnostic;
      performance prompts require at least 200 observations.
- [x] Crawl, index, CTR, position, referral useful-action, generative-referral, content review,
      source review, and rights freshness metrics expose definitions and denominators.
- [x] Referral included, other/unknown, excluded, and useful-action buckets remain explicit.
- [x] Recommendations require human review and cannot publish, index, rewrite, expand, connect,
      activate, or modify production.
- [x] CLI reports bind real input, inventory, and editorial SHA-256 digests; reject symlinks and
      oversized inputs; write new mode-0600 files only; and never overwrite output.
- [x] Focused type, unit, CLI, CI-contract, architecture, records, and build-contract checks pass
      without rerunning the complete workspace test matrix.

## Verification evidence

- Analytics contract tests exercise exact parsing, raw-field and accessor rejection, source
  authority, stale/synthetic/unavailable blocking, thresholds, recommendation policy, inventory
  drift, deterministic rendering, and forged-report rejection.
- End-to-end CLI tests use the actual current 45-route inventory and assert exact byte digests,
  private file modes, exclusive output, and symlink denial.
- The dedicated verifier runs unavailable, synthetic, and approved aggregate scenarios without a
  provider or network request.
- The CI workflow and contract include `pnpm check:search-operations`; the package build contract
  requires the compiled policy and renderer exports.

## Risks and rollback

Real performance remains unavailable until approved aggregate exports are supplied. Aggregate
classification can lag provider state and cannot prove citation quality or causality. Thresholds
reduce but do not replace legal/privacy review for future collection.

Rollback removes the analytics module, CLI, tests, CI step, documentation, and decision record.
There is no migration, persisted user state, provider connection, or external action to reverse.
