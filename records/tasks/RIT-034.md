# RIT-034: Post-generation fact and safety verification

- Backlog item: RIT-034
- Related records: D-037, D-038, D-039, D-040, D-041

The queue state, priority, milestone, dependencies, and owner gates remain canonical in
[BACKLOG.md](../../BACKLOG.md).

## Outcome

RIT-034 turns an exact RIT-033 non-displayable provider candidate into either a verified,
displayable interpretation or an independently authorized deterministic safe replacement before
any provider prose can be stored or shown.

## Scope

Included: runtime-issued single-use candidate identity; exact input, retrieved-content, generation,
policy, reviewer, and canonical-candidate-digest binding; whole-output deterministic checks;
independently authorized semantic review; fail-closed uncertainty; deterministic safe replacement;
privacy-safe verification metadata; append-only owner-scoped verification-result persistence;
atomic fenced generation finalization; HMAC-authenticated exact replay, expiry, least-privilege,
pending-output non-disclosure, and legacy-pending non-display evidence.

Excluded: a real provider, reviewer, or model; provider SDK, API key, network request, paid
inference, production safety-policy/content/prompt/fallback activation, crisis or health/safety copy
changes, API routes, streaming/polling/UI, another locale/modality/tradition, release-level eval
thresholds, a new retention period, deployment, public launch, and payments.

## Acceptance criteria

- [x] Verification accepts only the exact package-issued, single-use RIT-033 pending candidate and
      exact runtime-issued input/retrieval/generation context. Clones, casts, mutations, cross-
      candidate verdicts, policy drift, replay, and concurrent second consumption fail closed.
- [x] Candidate self-reported safety literals are not authority. Every user-visible text leaf is
      checked, including title, summary, symbol meaning/possibility/limitation, perspectives,
      reflection questions, action text, ritual reason, and boundary note.
- [x] Deterministic checks reject wrong, swapped, extra, or unsupported card, position,
      orientation, source, tradition, cultural authority, or user-history claims even when the
      structural fact/source reference sets are valid. Orientation contradictions are checked
      across every user-visible text leaf, not only the symbol entry for the affected card.
- [x] Fixed policy checks conservatively catch guaranteed prediction/certainty, relationship mind
      reading, professional medical/legal/financial or other high-stakes advice, paid spiritual
      efficacy, fear/urgency/dependency/repeated-reading pressure, supernatural persecution or
      grandiosity, self-harm/dangerous action, prompt/retrieved-content injection, and locale or
      Unicode/confusable bypasses without treating safe negations as unsafe claims.
- [x] An independently registered and authorized semantic reviewer returns only a strict bounded
      fixed verdict. Deterministic rejection cannot be overridden; reviewer uncertainty, timeout,
      malformed output, contradiction, or execution failure cannot approve a candidate.
- [x] Unsafe or uncertain candidates trigger the exact already-authorized RIT-033 deterministic
      fallback without another generation-provider call. Trust, binding, registration,
      configuration, or authority ambiguity instead produces no output and is never disguised as
      fallback.
- [x] Verified and safe-replacement results are runtime-issued, recursively immutable, bound to the
      canonical candidate digest and policy/reviewer versions, and displayable only after durable
      persistence succeeds.
- [x] Rejected provider prose, raw reviewer responses/errors, matched excerpts, detailed safety
      categories, prompts, retrieved excerpts, private questions, and request/reading/session/
      subject/idempotency/claim identifiers are absent from errors, operational metadata, logs,
      analytics, and verification provenance.
- [x] An additive one-to-one append-only verification record inherits interpretation owner and
      expiry, is written atomically with fenced generation finalization, authenticates exact
      finalization replay with a keyed HMAC, hides provider output while verification is pending,
      leaves every legacy pending row without a verification child non-displayable with no recovery
      API, and grants runtime only exact read/insert columns under forced RLS.
- [x] Focused AI/Web, adversarial fixture, compiled-workspace, architecture, type, lint, formatting,
      real PostgreSQL race/fencing/ownership/retention/restore, and repository evidence gates pass
      while every production provider and reviewer remains safe-off.

## Risks and rollback

The verifier is a release safety boundary, not a claim that a synthetic reviewer is production-
approved. RIT-036 must still enforce the fixed release regression/adversarial thresholds, and
provider/reviewer/model selection and policy activation remain separate owner gates. No production
provider, reviewer, model, SDK, key, network request, paid inference, API/UI, payment, deployment,
or public launch is added or approved by this task.

The database change must be additive. Before production migration, rollback removes the unused
verification code and unapplied child-table migration. After production data exists, destructive
removal requires separate owner approval and a forward-fix/data-preservation plan.
