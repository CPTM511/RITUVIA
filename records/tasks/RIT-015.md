# RIT-015: Resilient page-level state patterns

- Backlog item: RIT-015
- Related records: D-028

The queue state, priority, milestone, dependencies, and owner gates remain canonical in
[BACKLOG.md](../../BACKLOG.md).

## Outcome

The shared UI and first public-shell feature now use accessible, localized, testable empty, error,
offline, and provider-unavailable presentation contracts without inventing a product, persistence,
PWA, or provider capability.

## Scope

Included: four closed `@rituvia/ui` state variants; quiet/polite/assertive timing; title focus
targets; decorative non-color-only markers; bounded local link and caller-button actions; reflow,
theme, forced-color, RTL, and long-text styling; typed English state and connection messages; a
truthful home empty state; an event-cleaned `navigator.onLine` advisory with a persistent polite live
region; a locale error boundary with user reset, safe home fallback, and no raw error
rendering/logging; app/UI mutation tests; synthetic four-state preview; and dynamic connection-state
Playwright/axe coverage in the existing four-route gate.

Excluded: readings, accounts, anonymous sessions, provider adapters, feature-flag error disclosure,
public state/fault routes or switches, service workers, caching, synchronization, persistence,
automatic retries, provider E2E/SLA claims, a generic degraded state machine, another locale,
analytics, database changes, production activation, and external actions.

## Acceptance criteria

- [x] Empty, error, offline, and provider-unavailable patterns share closed accessible semantics,
      local-only actions, long-text/mobile/RTL/theme behavior, and no embedded production prose.
- [x] Static visible states are quiet, online/offline transitions update a persistent polite live
      region, only an error pattern may be assertive, actions stay outside live regions, and the
      whole-page error target receives initial focus without repeated connection-change focus
      stealing or subtree replacement.
- [x] Typed English copy and Web consumers never expose raw `Error`, digest, stack, provider details,
      request IDs, private content, or unreviewed URLs; retry remains caller-owned and loading-safe.
- [x] The real public shell consumes truthful empty, offline, and error patterns while safe-off
      disabled/unavailable states remain identical empty private 404 responses.
- [x] The dependency-neutral provider variant is unit- and browser-previewed as synthetic only; no
      real provider capability or failure mapping is claimed.
- [x] Unit/mutation, architecture, format/lint/type, production build/resource, and Playwright/axe
      gates pass; documentation, durable records, queue state, and rollback match reality.

## Verification evidence

Exact Node.js 24.18.0 and pnpm 11.13.1 verification passes 479 unit/contract tests in 41 files and
the 31-artifact production build at maximum 6,055 B gzip HTML, 5,284 B gzip CSS, and 214,217 B gzip
JavaScript. The RIT-015 focused matrix passes 152 UI, localization, Web
consumer, message, shell, and safe-off proxy tests. Production browser acceptance passes the exact
four canonical routes with 17 axe scans and 156 exact gradient/background contrast nodes retained
only under token-level contrast tests, plus forward/reverse keyboard focus, 44px targets, 40%
expanded text, desktop/mobile RTL, dark/reduced-motion/no-JavaScript states, a persistent
online/offline/online advisory announcement, and local-only requests. A runtime component test
executes the actual locale error boundary and verifies its focus target, single caller reset, quiet
semantics, pending suppression, offline variant, and raw-error isolation. CLI Playwright inspection
of the synthetic UI preview confirms all four variants, 320px reflow with no horizontal overflow,
zero sub-44px enabled controls, inherited RTL, dark color scheme, working bounded anchor action, and
zero console warnings/errors.

## Risks and rollback

Primary risks are misclassifying a transport or provider failure, using assertive announcements for
static content, retrying a non-idempotent operation, exposing raw diagnostic/private data, treating
`navigator.onLine` as service health, or presenting the synthetic provider pattern as a real
integration. Closed APIs, typed app copy, runtime mutation tests, safe-off proxy contracts, exact
route inventory, and documentation constrain those risks. Current screen-reader, Firefox/WebKit,
and real zoom remain release-level manual work. Roll back by reverting the RIT-015 commit; no
migration, user data, external service, public activation, or data recovery is involved.
