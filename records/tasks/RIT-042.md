# RIT-042: Accessible free candle and incense Sanctuary

- Backlog item: RIT-042
- Related records: D-047

The queue state, priority, milestone, dependencies, and owner gates remain canonical in
[BACKLOG.md](../../BACKLOG.md).

## Outcome

Let an anonymous or signed-in owner complete a dignified free candle or incense experience from
the private Sanctuary using either a standard two-dimensional scene or an accessible linear mode,
with audio off by default, reduced-motion-safe presentation, explicit exit and completion, and a
fully usable static fallback.

## Scope

Included: rendering the approved `free_candle` and `free_incense` catalog definitions; reviewed
English interaction copy for the bounded template steps; a focused inline ritual stage with focus
entry and restoration; in-memory pause/resume; standard 2D and linear modes; decorative
candle/incense CSS visuals;
audio-off status with no autoplay or audio dependency; reduced-motion selection and static
equivalence; step-by-step keyboard and screen-reader operation; explicit exit without persistence;
completion through the existing historical ritual boundary only after the final acknowledgement;
catalog, network, image, animation, and offline degradation; responsive/RTL behavior; and focused
component, browser, accessibility, build, privacy, and request-ledger tests.

Excluded: a new ritual-session schema or migration; durable start/pause/resume state; exact
catalog/template/access snapshots; entitlement or consumable-pass reservation; completion API
changes; journal autosave changes; paid object redesign; audio assets; WebGL; new artwork; new
locale activation; notification delivery; analytics; production deployment; and public launch.
RIT-043 owns transactional ritual lifecycle, exact provenance, pass consumption, completion, and
private journal persistence.

## Acceptance criteria

- [x] The free candle and incense are equally prominent, always usable without payment, and bound
      to the approved canonical catalog definitions while historical persistence codes remain
      unchanged.
- [x] Starting either free ritual replaces the workspace with a focused inline stage aligned to the
      approved Sanctuary hierarchy, with always-visible pause/resume, exit, and completion controls,
      clear title and symbolic boundary, focus entry/restoration, Escape support, and no ritual
      request before explicit final completion.
- [x] Standard 2D mode provides a calm decorative candle or incense scene; linear mode presents the
      same ordered interaction and completion controls without requiring images, animation, audio,
      drag, precision, timing, or pointer input.
- [x] Audio is off and no audio resource autoplays; reduced-motion preference selects or preserves
      a static-equivalent path, all animation is nonessential and disabled under reduction, and
      animation/image failure leaves every step operable.
- [x] Loading, catalog-degraded, validation, offline, retry, completion-error, exit, and success
      states preserve the intention and never imply that an external outcome was sent, granted, or
      strengthened.
- [x] Focused tests and current-build Chromium acceptance cover both free rituals, keyboard,
      screen-reader semantics, 44px targets, 320px, RTL, reduced motion, offline retry, exact
      request timing/body, storage/network privacy, axe, console, and layout boundaries.
- [x] Formatting, lint, type checking, architecture, unit, AI-eval, configuration, database,
      production build, accessibility, evidence, instruction-pack, and secret gates pass.

## Risks and rollback

The primary risks are persisting a ritual before the user completes it, disrupting keyboard or
screen-reader focus, making the visual mode more complete than the linear mode, starting audio or
motion without consent, losing the private intention on exit/error, sending the new canonical code
to the historical v1 API, or letting a catalog/image/network failure remove the free path.

The implementation therefore keeps the new experience presentation-local until the final action,
replaces the interactive workspace with one labelled inline stage, derives both modes from one
ordered step state, keeps pause/resume in memory, keeps audio absent and off, maps only the two
reviewed canonical free definitions to their explicit historical v1 codes, and retains a reviewed
static fallback. Rollback removes the focused experience and restores the
current immediate legacy free-object action; no database, entitlement, payment, journal, or
customer data rollback is required.
