# RIT-091: Location and historical time-zone adapter

- Backlog item: RIT-091
- Status: Done
- Related decision: D-067
- Privacy/API approval gate: OWN-014

The queue state, priority, milestone, dependencies, and owner gates remain canonical in
[BACKLOG.md](../../BACKLOG.md).

## Outcome

RIT-091 adds a pure versioned location/historical-time-zone contract and a server-only Web
composition boundary. It resolves exact local inputs without fabricating time, makes DST folds and
gaps explicit, records provider and runtime provenance, and fails closed on malformed or
unavailable dependencies.

The selected production direction is an offline, self-hosted GeoNames snapshot, but this slice
does not import or activate real provider data. Node `24.18.0`, ICU `78.3`, and tzdata `2026b` are
pinned as part of the calculation provenance.

## Scope

Included: strict search and resolution schemas; opaque location selection; E6 coordinates; provider
adapter/data/source/license/attribution/digest versions; exact Node/ICU/tzdata provenance;
historical offsets; explicit fold choice and gap result; pre-1970 confidence; normalized bounded
English search without a dedicated query echo; private HMAC-keyed bounded process cache; single
flight; timeout cancellation; failure eviction; stable redacted errors; fixtures; architecture,
data, privacy, testing, cost, and reference records.

Excluded: real GeoNames data ingestion, production search index, HTTP route, UI, browser
geolocation, database migration, birth-profile persistence, analytics, external network request,
native astrology engine, payment, deployment, and public launch.

## Acceptance status

- [x] Zero, one, and multiple location candidates require truthful explicit selection behavior.
- [x] Historical resolution returns stored local input, selected location, IANA zone, UTC instant,
      offset, confidence, provider version/data digest, and runtime/ICU/tzdata version.
- [x] Ambiguous folds expose two candidates and require `earlier` or `later`; gaps expose no
      fabricated instant.
- [x] Non-hour offsets, historical DST, a skipped local date, and pre-1970 confidence have fixed
      fixtures.
- [x] Provider output is exact-schema, bounded, deduplicated, location-ID checked, and fail closed.
- [x] Results have no dedicated query echo; cache keys, errors, and telemetry contracts contain no
      raw query.
- [x] Search cache is bounded process memory with HMAC-only keys, provider/data partitioning,
      single flight, a maximum 15-minute TTL, timeout cancellation, and failure eviction.
- [x] No HTTP route resolves the canonical GET/privacy conflict without owner approval.

## Risks and rollback

Node/ICU/tzdata history before 1970 can be incomplete or platform-dependent, so that range remains
explicitly limited-confidence. A production GeoNames snapshot still needs immutable import,
attribution, search-index, update, rollback, performance, and operations evidence.

The canonical GET location-search inventory conflicts with birth-data URL privacy. OWN-014 must
approve the recommended private POST contract before UI work.

Rollback removes the two implementation modules, exports, tests, and records. No migration,
retained birth data, provider request, external cost, deployment, or public behavior exists to
reverse.
