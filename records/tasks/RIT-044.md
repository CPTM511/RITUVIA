# RIT-044: Revisit scheduling and completion

- Backlog item: RIT-044
- Related records: D-049

The queue state, priority, milestone, dependencies, and owner gates remain canonical in
[BACKLOG.md](../../BACKLOG.md).

## Outcome

Let an anonymous or signed-in owner schedule, reschedule, complete, and archive a private Revisit
that preserves the original intention and small action, respects the selected local calendar date,
IANA time zone, and optional quiet hours, and records what actually happened without presenting
the comparison as proof of prediction.

## Scope

Included: strict schedule, mutation, completion, bounded-list, and resource contracts; next-day,
seven-day, and custom local-date choices; IANA time-zone validation; optional overnight quiet
hours stored with reminders fixed off; one open Revisit per owner/intention; encrypted exact
intention/action snapshots; owner-scoped idempotent schedule/reschedule/complete/archive/delete
transitions backed by an append-only operation ledger; independently versioned encrypted
completion reflection and bounded non-clinical outcome tags; private collection/resource APIs;
same-origin CSRF; a private noindex `/en/revisit` experience; Sanctuary handoff using only an
opaque UUID; offline, conflict, not-found, empty, due, completed, archived, and deleted behavior;
immediate hiding after parent-intention deletion; PostgreSQL
race/constraint/privilege/restore evidence; and focused browser accessibility/privacy acceptance.

Excluded: email, push, SMS, webhook, or in-app notification delivery; reminder channel activation;
outbox jobs; frequency caps across delivered messages; unsubscribe processing; lock-screen
notification rendering; analytics; AI comparison or summary; automatic ritual/journal linking;
journal search; account history; physical deletion or retention changes; production activation;
deployment; new locale activation; and golden screenshot changes. RIT-045 owns consented reminder
delivery and RIT-046 owns privacy-safe core-loop analytics.

## Acceptance criteria

- [x] A strict versioned schedule accepts one owned v2 intention plus next-day, seven-day, or
      custom future local date, a valid IANA time zone, reminders fixed to none, and an optional
      valid quiet-hours interval without client-selected ownership, linked-resource, or due-state
      authority.
- [x] Scheduling snapshots the exact intention text, small action, and revision under
      owner/resource-bound authenticated encryption with its own key version and binds only the
      owner-scoped intention; ritual/journal auto-linking is deferred until composite ownership can
      be database-enforced.
- [x] One owner/intention has at most one scheduled Revisit; same-key replay returns the same
      resource, changed reuse conflicts, concurrent schedules have one winner, and failed
      transactions leave no partial snapshot or lifecycle state.
- [x] Reschedule, complete, archive, and soft delete use strict expected revisions and stable
      idempotency keys recorded in an append-only operation ledger; completion is allowed before,
      on, or after the selected date, stores encrypted factual reflection under an independent key
      version plus bounded user-owned tags, and archived permits only deletion.
- [x] Private list/read/mutation routes enforce owner-union isolation, exact same-origin and
      session-derived CSRF, bounded bodies, no-store/noindex, safe Problem Details, and
      indistinguishable missing/cross-owner/expired/deleted resources without exposing ciphertext
      or private text; deleting the parent intention immediately hides the Revisit.
- [x] The Revisit experience provides presets, custom date/time zone, optional quiet hours, clear
      reminder-off disclosure, original intention/action comparison, non-prophetic completion
      copy, empty/loading/error/retry/offline/conflict states, completion and archive, and an
      anonymous-first Sanctuary handoff that persists only an opaque UUID in tab storage.
- [x] Domain, real PostgreSQL, route, and current-build browser evidence cover DST/leap dates,
      future/retention boundaries, schedule races, replay/conflict, optimistic mutations, CSRF,
      IDOR, encryption, restore, reminder/outbox absence, private canaries, keyboard, focus, 320px,
      RTL, reduced motion, touch targets, axe, console, request, and storage boundaries.
- [x] Formatting, lint, type checking, architecture, unit, AI-eval, configuration, migration,
      database, production build, accessibility, evidence, instruction-pack, and secret gates pass.

## Risks and rollback

The primary risks are shifting a chosen date across DST, treating a stored quiet-hours preference
as notification consent, treating the selected date as a coercive lock, comparing against edited
rather than original words, crossing owners, leaking reflection text into
storage/logs/analytics/screenshots, or reviving an archived/deleted resource through replay.

The implementation therefore stores local date and IANA zone separately, fixes reminder channel
authority off, snapshots encrypted original prose at schedule time, uses database-clock due state
only for display, owner filters, optimistic revisions, an append-only operation ledger, terminal
soft deletion, and archive-with-delete-only semantics. Rollback disables the new page and routes
and leaves the additive tables unused; no historical row is rewritten and no delivery adapter or
production data exists in this slice.
