# RIT-052: Account history, settings, and session management

- Backlog item: RIT-052
- Related records: D-036, D-050, D-052, D-054

The queue state, priority, milestone, dependencies, and owner gates remain canonical in
[BACKLOG.md](../../BACKLOG.md).

## Outcome

Give a signed-in user one private account control surface for profile preferences, account-linked
history, and active-session management without copying private rows, exposing private prose in list
responses, or collecting device fingerprint data.

## Scope

Included: optional display name and IANA time-zone settings with optimistic revision protection;
stable account-scoped history summaries for currently retained readings, intentions, ritual
sessions, journal entries, and Revisits across every linked anonymous subject; explicit loading,
empty, error, retry, pagination, and conflict behavior; privacy-minimal current/other session
summaries; durable targeted revocation, current logout, and logout-all; exact same-origin
session-CSRF mutations; focused component, route, service, database, authorization, browser,
accessibility, privacy, and responsive verification; and current account/data/security/API/test
documentation.

History summaries contain only opaque resource identifiers, resource type, coarse lifecycle state,
approved catalog/theme codes where useful for labeling, and timestamps. Private intention,
journal, Revisit, question, interpretation, and account-identity prose remains absent from list
responses, URLs, browser storage, analytics, logs, metadata, and screenshots. Existing retention
and soft-deletion behavior is reused without extension.

Excluded: new retention periods or Plus-dependent history; private-content search; bulk or
selective deletion; export; consent/personalization controls; order, subscription, Credit, billing,
wallet, or payment settings; production email/OAuth/WebAuthn/SIWE providers; device names,
locations, IP addresses, user agents, fingerprints, or trust scoring; admin/MFA; production
deployment; public launch; new locale activation; and golden screenshot updates.

## Acceptance criteria

- [x] Account history uses stable bounded pagination over every linked anonymous subject and
      includes only currently visible reading, intention, ritual, journal, and Revisit summaries.
- [x] History collection accepts no client-selected user or subject identifier, exposes no private
      prose, and cross-account resources cannot enter another account's page.
- [x] Profile settings preserve the existing strict schema and optimistic revision conflict, with
      complete loading, success, error, retry, and changed-in-another-session behavior.
- [x] The account page identifies the current session and other active sessions using timestamps
      only, revokes another session durably, and supports current/all-session logout without
      claiming success when storage fails.
- [x] Every surfaced private resource keeps indistinguishable missing/cross-owner behavior, and the
      focused IDOR matrix covers readings, intentions, ritual sessions, journals, Revisits, account
      sessions, and existing account-owned commerce resources.
- [x] Focused unit, route, database, browser, accessibility, privacy, architecture, migration,
      secret, type, lint, formatting, record, and generated-evidence gates pass without repeating
      the unrelated complete workspace unit suite.

## Risks and rollback

Main risks are cross-account history disclosure, private prose leaking into summaries, unstable or
duplicated pagination, treating soft-deleted data as visible, accidental current-session
revocation, stale CSRF after authentication rotation, and false success when durable revocation
fails. Rollback removes the new account-history/session UI and collection endpoint while retaining
the existing immutable ownership links, profiles, sessions, and private resources. No destructive
migration, retention change, production mutation, provider activation, deployment, or golden
baseline change is authorized.
