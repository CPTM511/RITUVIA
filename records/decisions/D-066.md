## Context

RITUVIA requires deterministic Sun, Moon, planetary, Ascendant, house, and aspect facts that can
be reproduced from the stored UTC instant, location, time-zone source, input confidence, engine
version, and data version. AI cannot create or alter those facts. The production pack blocks natal
chart release until a lawful engine and data path is documented.

The repository had no approved engine, provider adapter, license record, or source/data pin.
OWN-003 authorizes the exact engine and license-model selection. It does not represent a vendor
contract, payment, legal opinion, or production activation.

## Decision

Select the Swiss Ephemeris C library version `2.10.03`, released `2022-08-27`, as the target
deterministic Western astrology engine. Separately select official source/data snapshot tag
`v2.10.3final`, commit `af9823fe7b06ffefe3d3968fdc5680be8b5eec5f`, dated `2026-04-14`.
The library release and later source/data snapshot are different provenance dimensions and must
never be collapsed into one version.

Target the June 2026 Swiss Ephemeris Professional Unlimited License:

- one-time list price: CHF 700;
- duration: 99 years;
- server use and compiled distribution: allowed;
- source distribution: optional, with complete-source and modified-source conditions requiring
  legal review;
- warranty: as-is without correctness or fitness guarantee;
- support: public community mailing list and reasonable-effort bug fixing only;
- SLA: none; RITUVIA owns availability, incident response, validation, and MTTR; and
- effectiveness: only after complete payment and provider countersignature.

Before execution, legal review must confirm the legal licensee plus affiliate, contractor,
assignment, transfer, merger/acquisition, and modified-source rights and obligations.

`@rituvia/divination` owns only the pure provider-neutral
`rituvia_astrology_ephemeris_adapter_v1` interface. It cannot host a native dependency under its
package rules. RIT-093 must register a separate server-only native implementation zone before
adding Swiss Ephemeris source, binary, wrapper, or data.

The selection V1 schema is permanently production-safe-off:

- it contains no state or boolean capable of authorizing production calculation;
- runtime network access and automatic Moshier, JPL, alternate-data, or alternate-engine fallback
  are forbidden;
- an unexpected returned engine flag fails unavailable without placements; and
- integration readiness requires immutable evidence records plus an independently supplied
  evidence-authority verifier. Every check receives the exact selection-manifest digest and
  code-specific subject digest; the selection JSON cannot validate its own license.

Required future evidence includes the legal licensee, countersigned contract, payment, legal
review, source/data archives, exact file checksums, compiler and flags, reproducible build, native
SBOM, ABI version, `SEFLG_SWIEPH` runtime verification, licensed reference vectors, supply-chain
review, and staging kill-switch exercise.

The approved selection manifest version is `1.0.0`, SHA-256
`0bd3409cd064b5762065bfc96e7c2d8d337046e8a52f8b7e8d37648171a53882`.

## Consequences

OWN-003 and RIT-090 are complete for the exact owner-approved selection and documentation. RIT-091
may proceed independently because location/time-zone work integrates no Swiss Ephemeris code.

OWN-013 remains the external execution gate for legal review, legal licensee, complete payment,
provider-countersigned contract, and private evidence references. It directly blocks RIT-093 and
all production natal calculations. No Swiss Ephemeris source, binary, wrapper, data file,
dependency, or derived calculation may be integrated before that gate and the native
supply-chain evidence pass.

Production `astrology_enabled` remains false. A later production activation requires a separate
versioned runtime configuration and owner-reviewed release evidence; selection V1 can never
activate it.

## Validation

The strict parser rejects unknown fields, unsafe URLs, runtime network access, automatic fallback,
provider birth-data transfer, malformed checksums, duplicate evidence, path escape, unsupported
schema, incomplete capability inventory, or any attempted production-activation field.

The structural assessment always remains non-authoritative. Only a caller-supplied evidence
authority can make a complete synthetic fixture integration-ready. Evidence is bound to exact
license/source/data subject digests, the selection-manifest digest, an evidence-code/reviewer-role
matrix, independent reviewer IDs, and review dates no later than the assessment date. Approved
source claims, legal questions, attribution/distribution terms, and replacement triggers reject
same-version drift. Even an accepted assessment keeps production activation false. Authority
rejection and exceptions fail closed without leaking private evidence.

## Rollout and rollback

There is no runtime rollout. RIT-093 may add a pinned native adapter only after OWN-013, registered
server-only architecture, reproducible build, SCA/license review, exact source/data checksums,
reference-chart tolerance tests, ABI/compiler/SBOM records, dual-run replacement design, returned
engine-flag checks, and staging kill-switch evidence.

Rollback removes the selection manifest, parser, tests, and records. No birth data, migration,
native code, provider call, payment, contract execution, secret, deployment, or public behavior
exists in this slice. A future replacement uses a new adapter and calculation version without
rewriting historical facts.
