# D-051: Safe-off consented-anonymous core-loop analytics baseline

- Date: 2026-07-24
- Owners: owner, product, backend, privacy, qa_security
- Related tasks: RIT-046, RIT-047, RIT-051, RIT-055
- Evidence references: docs/09_ANALYTICS_EXPERIMENTS.md, records/tasks/RIT-046.md

## Context

RIT-046 must define enough privacy-safe instrumentation to reconstruct the M4 reflection funnel and
calculate Weekly Meaningful Reflection Sessions. The product sources conflict between counting
distinct people and counting qualifying sessions, and they require session, consent, identity
merge, bot, and late-arrival definitions before implementation. The repository has a fail-closed
per-purpose anonymous consent ledger but no approved analytics notice, consent interface,
retention/deletion policy, vendor, event outbox, warehouse, or production activation.

## Decision

Define WMRS v1 as the distinct number of consented anonymous analytics subjects that have at least
one qualifying Tarot reflection session during the rolling UTC interval `[asOf - 7 days, asOf)`.
A reflection session is rooted in one server-authoritative reading. It qualifies when deterministic
reading completion occurs before or at one of: intention creation, ritual completion, private
journal creation, or Revisit completion. Report qualifying reflection-session count separately;
do not call that count WMRS. Use event time, recompute from the bounded input set for late data,
deduplicate semantic event keys, perform no account merge, and label bot filtering unavailable.

Freeze the RIT-046 core event set to `reading_started`,
`reading_deterministic_completed`, `interpretation_viewed`, `intention_created`, `ritual_started`,
`ritual_completed`, `journal_entry_created`, `revisit_scheduled`, and `revisit_completed`.
Each exact event union carries only purpose-scoped pseudonymous subject/session/reflection keys,
semantic event key, UTC time, locale, source, exact consent purpose/notice, and event-specific
allowlisted categorical fields. Raw questions, intention/action/journal/Revisit text, themes,
safety state, raw identity/session/resource IDs, exact schedule/time-zone data, and arbitrary
properties are forbidden.

Create server-authoritative event intents only after successful non-replayed state changes.
`interpretation_viewed` remains a typed client-source contract because generation completion is not
proof that the user saw the result; no browser queue, beacon, endpoint, or storage is activated.
The Web adapter requires the exact current `optional_product_analytics` consent and exact notice
version, then derives environment/purpose/version-isolated keyed pseudonyms. Missing, denied,
withdrawn, stale, invalid, account-only, or unavailable consent emits nothing.

Until legal notice, retention/deletion, and production activation are approved, production
composition remains a no-op. Provide only a bounded in-memory ledger for synthetic tests and metric
fixtures. Do not add a database event table, external exporter, observability reuse, historical
backfill, or production network path in this slice. A future durable implementation must add
transactional outbox/ledger semantics, deletion/suppression, key rotation, reconciliation, and
approved retention before activation.

## Alternatives considered

| Option | Benefits | Costs/risks | Why not selected |
| --- | --- | --- | --- |
| Count every qualifying session as WMRS | Matches one sentence in the analytics draft | Conflicts with the charter's distinct-user north star and rewards repetition | Keep sessions as a separate diagnostic |
| Emit `interpretation_completed` as viewed | Entirely server-side | Counts unseen results and distorts the funnel | Preserve a real viewed contract |
| Persist analytics events now | Stronger replay and aggregation evidence | Creates unapproved retention/deletion and production data obligations | Defer until policy and activation are approved |
| Reuse operational observability | Existing sink and redaction | Mixes optional product analytics with essential telemetry | Keep purposes and failure modes separate |
| Include theme/safety categories | More segmentation | Sensitive inference and small-cohort reidentification risk | Exclude from the RIT-046 minimum |

## Consequences

The repository now has an auditable event and metric contract without collecting production user
analytics. Synthetic fixtures can prove deduplication, late-event handling, funnel projection, and
WMRS arithmetic. Product operations cannot yet claim population-wide WMRS, durable delivery,
deletion compliance, bot-filtered metrics, or interpretation-view coverage.

## Rollout and rollback

Runtime services default to the safe-off analytics adapter. Enabling any real sink, notice,
retention, browser ingestion, vendor, account merge, or production deployment requires a later
approved decision. Roll back by removing the injected event intents and analytics package; no
persisted or transmitted analytics rows require cleanup.

## Validation

Focused package tests cover the exact nine-event union, unknown/private fields, raw UUIDs,
accessors, fallback consistency, bounded deduplication, rolling-window boundaries, distinct
subjects versus sessions, event ordering, and late observations. Focused Web tests cover safe-off
composition, exact consent, purpose/environment/key isolation, raw-identifier absence, semantic
deduplication, invalid roots, sink failure, and non-replayed reading/intention emission.
