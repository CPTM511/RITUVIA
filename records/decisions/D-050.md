# D-050: Layered local verification with milestone full-suite gates

- Date: 2026-07-24
- Owners: owner, engineering, qa_security
- Related tasks: RIT-046, RIT-047, RIT-052, RIT-084
- Evidence references: AGENTS.md, docs/14_TEST_STRATEGY.md, records/tasks/RIT-047.md,
  records/tasks/RIT-052.md

## Context

The complete workspace matrix currently includes more than fifteen hundred unit tests plus
PostgreSQL, build, accessibility, browser, AI, configuration, migration, evidence, and security
gates. Repeating every unaffected check after each small edit consumes substantial time and output
without increasing confidence proportionally. The owner directed Codex to use prior passing
evidence during feature development and reserve final integration testing for the appropriate
milestone.

## Decision

Use layered local verification. During implementation, run only directly affected tests. Close an
ordinary task with formatting, linting, type checking, architecture/evidence checks, and the
applicable feature, database, browser, accessibility, security, payment, or AI suites for the
changed slice. Run the complete workspace matrix at milestone integration tasks such as RIT-047,
release candidates, broad shared-runtime/toolchain changes, or an explicit risk trigger.

Prior passing evidence may be reused only when its source, dependency, toolchain, configuration,
and generated inputs remain unchanged. CI can retain a broader mandatory pull-request matrix.
Output should remain bounded during iteration, while retained evidence may preserve full logs.

## Consequences

Ordinary tasks complete faster with less repeated output while retaining risk-based evidence.
Task records must identify focused commands and any reused evidence. A task cannot skip a relevant
high-risk gate merely because it is expensive, and milestone/release closure still requires the
complete matrix.

## Alternatives considered

| Option                                   | Benefits                               | Costs/risks                                                               | Why not selected                                   |
| ---------------------------------------- | -------------------------------------- | ------------------------------------------------------------------------- | -------------------------------------------------- |
| Run the complete matrix after every edit | Maximum repetition of passing evidence | High latency and output with little added confidence for unchanged inputs | Use risk-triggered milestone gates                 |
| Run only focused tests at every closure  | Fastest local loop                     | Can miss cross-cutting integration failures                               | Milestone and release tasks retain the full matrix |

## Validation

RIT-046 demonstrates focused ordinary-task closure, while RIT-047 runs the complete workspace and
browser matrix. Reconsider this decision if affected-area selection misses a reproducible
regression or if evidence reuse cannot prove unchanged inputs.

## Rollout and rollback

Revert to the complete local matrix after every task if focused verification proves unreliable or
if affected-area selection cannot be audited.
