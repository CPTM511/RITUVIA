# D-077: Locale-safe writing systems and private-text preservation

- Date: 2026-07-27
- Owners: owner, localization, frontend, qa_security
- Related tasks: RIT-102
- Evidence references: `packages/ui/src/styles.css`; `packages/ui/test/controlled-preview.tsx`;
  `scripts/writing-system-policy.ts`; `scripts/verify-writing-systems-browser.mjs`;
  `packages/domain/src/question-intake.ts`

## Context

The UI system used Latin-first generic font stacks and had only static Japanese and Devanagari
preview text. It did not prove actual CJK line breaking, platform-font fallback, Devanagari
shaping, React-controlled composition input, localized native date values, or narrow-screen
behavior. The mobile Web shell also used `word-break: break-all`.

Several private human-text parsers normalized stored text with NFKC and rejected the complete
U+200B–U+200F range. That incorrectly rejected ZWNJ and ZWJ even though those characters can be
required for Indic orthography, while compatibility normalization could silently rewrite
user-authored text.

## Decision

Define local-only, locale-specific UI and display fallback stacks for Japanese, Korean, Simplified
Chinese, Traditional Chinese, and Devanagari. Use strict CJK line breaking, normal word breaking,
script-appropriate line height, and Devanagari ligature/shaping settings. Do not add remote fonts,
font downloads, or a production locale.

Preserve private human-authored text in NFC. Permit ZWNJ and ZWJ, while continuing to reject zero
width space, directional overrides/isolates, other unsafe controls, isolated surrogate code units,
and unsafe metadata delimiters where applicable. Use NFKC only on an isolated copy for safety
classification, never as the stored or rendered value. Bound representative names and private
text by Unicode scalar values rather than UTF-16 code units, and do not use native `maxlength` on
the account name field where that would disagree with the server boundary.

Require a mutation-tested repository policy and a local Chromium harness that loads both UI and
Web CSS. The harness bundles a test-only hydrated React controlled field, proves Japanese and
Hindi composition survives a forced rerender, checks four CJK line-break fixtures, reads actual
platform fonts through the browser protocol, measures Devanagari shaping, exercises canonical
Gregorian ISO date values, runs Axe, and denies external requests, storage writes, and locale
activation.

## Alternatives considered

| Option                                        | Benefits                                            | Costs/risks                                                              | Decision |
| --------------------------------------------- | --------------------------------------------------- | ------------------------------------------------------------------------ | -------- |
| Rely on generic `sans-serif` and screenshots  | Minimal code                                        | Missing glyphs and script-specific regressions remain invisible          | Rejected |
| Load one remote universal font                | Consistent screenshots                              | Adds CSP, privacy, supply-chain, and performance dependencies            | Rejected |
| Keep NFKC for stored private text             | Simplifies compatibility matching                   | Silently rewrites user-authored characters and still rejects Indic joins | Rejected |
| Static unhydrated input preview               | Fast                                                | Cannot detect React-controlled IME candidate loss                        | Rejected |
| Local stacks plus hydrated script-specific QA | No production activation or network font dependency | Release still needs device/browser and qualified linguistic review       | Selected |

## Consequences

The UI now exposes explicit fallback order without claiming that every deployment host contains
the preferred font. Automated Chromium evidence confirms that a platform font supplies glyphs and
does not fall to LastResort/tofu. Native device IME, WebKit/Firefox rendering, and qualified
Japanese/Korean/Chinese/Hindi visual review remain release checks rather than simulated approval.

English remains the only runtime and published locale. Test document languages, synthetic names,
and screenshots are temporary QA artifacts; they do not enter routes, messages, metadata,
sitemaps, storage, analytics, or production bundles.

## Validation

Focused unit tests cover locale stacks, unsafe line-breaking mutation, controlled fixture
presence, NFC preservation, ZWJ/ZWNJ admission, bidi/control rejection, supplementary CJK names,
private text, exact locale/time-zone formatting, and canonical ISO dates.

The browser gate runs at 320 CSS pixels, equivalent to 400% reflow from a 1280-pixel layout. It
verifies four CJK line-break profiles, five actual platform-font profiles, two hydrated
composition/rerender scenarios, two grapheme observations, two date controls, two screenshots,
two Axe scans, 44-pixel controls, and zero external request, storage, console, page, or locale
activation failures.

## Rollout and rollback

No migration, production data mutation, translation, country, font download, deployment, DNS,
payment, email, or public launch is involved. Roll back by reverting the font tokens, test
harness/policy, private-text normalization changes, and associated records. Existing NFC values
remain valid text if the implementation is rolled back.
