# D-078: Versioned lifecycle messages with strict delivery locale

- Date: 2026-07-27
- Owners: owner, localization, backend, qa_security
- Related tasks: RIT-104
- Evidence references: `content/localization/rituvia-lifecycle-messages.en.v1.json`;
  `packages/i18n/src/lifecycle.ts`; `packages/domain/src/revisit-reminder.ts`;
  `packages/db/prisma/migrations/202607270001_revisit_reminder_template_binding/migration.sql`;
  `apps/worker/src/revisit-reminder.ts`

## Context

RIT-045 established an English once-only Revisit reminder queue and a disabled provider adapter,
but its message copy was hardcoded in the Worker and queue rows did not retain the exact template
used. A delayed job could therefore outlive a template change, and authorization did not recheck a
Revisit date or time-zone change made after claim. RIT-104 must add localized-message architecture
without silently sending an unauthorized fallback, activating a non-English locale, or implying
that a real email/support operation exists.

## Decision

Create an independently checksummed `lifecycle_messages` English source catalog and runtime
projection. Persist an immutable template ID, positive version, source checksum, resolved locale,
and fallback-used flag on every reminder subscription. Keep every prior registry entry available
while a database row can reference it; register a new version before any writer can select it.
Unknown or mismatched bindings terminate safely before provider use.

Require exact authorized locale delivery. Unsupported production delivery locales are suppressed,
not silently sent in English. Explicit fallback to English is available only to local preview and
emits one deduplicated non-identifying event containing template and locale metadata. Synthetic
non-English catalogs remain test-only and do not activate a locale.

Render the reminder and support receipt as strict semantic HTML plus equivalent plain text. Reject
header/control/bidi injection and unsafe links; include no private question, intention, ritual,
journal, relationship, or generated prose. Use a fragment-only preference deep link so the private
route's query-denial boundary remains intact. Reauthorize ownership, preference, template binding,
scheduled local date, current time zone, 09:00 local threshold, and quiet hours immediately before
provider use. The reminder preference link is a same-origin GET-safe deep link that focuses
settings but never mutates consent.

Keep production safe-off before queue claims. Do not compose a scheduler or real provider, send
email, activate a support mailbox or service-level claim, approve legal unsubscribe text, publish
a non-English lifecycle catalog, deploy, or launch.

## Alternatives considered

| Option                                      | Benefits                                  | Costs/risks                                                       | Decision |
| ------------------------------------------- | ----------------------------------------- | ----------------------------------------------------------------- | -------- |
| Keep Worker-local English copy              | No catalog or migration                   | Queue output is not reproducible or review-bound                  | Rejected |
| Always fall back to English                 | Higher apparent delivery rate             | Sends an unauthorized language and hides localization gaps        | Rejected |
| Store only the current template version     | Smaller persistence surface               | Rollback and delayed jobs can change meaning or become unverifiable | Rejected |
| Versioned exact-locale binding and safe-off | Reproducible, observable, reversible       | Requires registry retention and explicit locale rollout           | Selected |

## Consequences

Template rollout is additive: code must recognize the new version before database writers select
it, and an old version cannot be removed until no durable row references it. Delivery remains
English-only and no fallback can bypass the locale gate. The support receipt demonstrates the
shared rendering contract only; it is not a support-service promise.

Locale and time-zone changes after claim can revoke a send, so a worker may release or terminally
handle work without provider use. This conservative behavior favors consent, time-zone correctness,
and rollback safety over delivery rate.

## Validation

Focused i18n tests prove source/runtime parity, strict headers and links, locale/date/time-zone and
quiet-hours output, HTML/plain equivalence, delivery suppression, preview-only fallback telemetry,
synthetic exact-locale rendering, and support receipt behavior. Domain and Worker tests prove exact
binding agreement and rejection before provider use.

The PostgreSQL gate deploys the additive migration and proves persistence, privacy export,
least-privilege access, once-only claims, and send-time rejection after a date/time-zone change.
The 320-pixel Chromium preview runs three Axe scans with zero external requests, storage writes,
layout failures, or locale activations. The focused Revisit browser proves the GET-safe settings
link and focus behavior.

## Rollout and rollback

No production data mutation, provider, email, support operation, non-English locale, deployment,
DNS, or public launch is involved. Roll forward by adding a new retained registry version before
selecting it for new rows. Roll back writers to a still-registered previous binding; never delete a
version while referenced. The additive provenance columns may remain safely if rendering code is
rolled back.
