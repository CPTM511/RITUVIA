# D-042: Private durable-only tarot interpretation polling boundary

- Date: 2026-07-18
- Owners: frontend, backend, ai_safety, qa_security, privacy, operations
- Related tasks: RIT-035, RIT-036, RIT-037, RIT-038, RIT-122
- Evidence references: apps/web/app/api/v1/readings/[readingId]/interpretation/route.ts, apps/web/server/interpretation-runtime.ts, apps/web/app/_contracts/tarot-interpretation-response.ts, apps/web/app/_components/tarot-interpretation-machine.ts, apps/web/app/_components/tarot-interpretation-transport.ts, apps/web/app/_components/tarot-interpretation-panel.tsx

## Context

D-040 makes provider work idempotent and fenced, and D-041 permits display only after a verified or
independently safe replacement is atomically durable. Neither decision defines the browser/API
handoff. D-037 includes a provisional-stream contract for provider-neutral orchestration, but
shipping provisional prose to a browser would contradict the later monotonic verification and
pending-output non-disclosure boundaries. RIT-035 therefore needs an explicit start/status protocol
whose read path cannot accidentally claim work or invoke paid capabilities.

## Decision

Expose one exact private resource at
`/api/v1/readings/{reading-id}/interpretation`. `POST` is the only start/resume operation. It requires
the owner session, same-origin request, empty body, empty query, and a strict UUID V4 idempotency
key. Exact replay reuses that operation; changed reuse conflicts. `GET` is a distinct owner-bound,
same-origin, no-store read. It must never call a claim/reclaim path, provider, reviewer, or any other
side-effecting capability.

Return only a strict versioned four-arm union. `processing` and `failed` are explicitly
non-displayable. `verified` and `reviewed_fallback` are displayable only when their D-041 result is
already durable. Project final output through a closed browser DTO that excludes provider/model,
reviewer, provenance, source/fact identifiers, digests, claim/lease state, token/cost data, and all
other operational metadata. The API re-parses this projection before serialization; processing
uses `202` with a matching bounded `Retry-After`, while terminal responses use `200`. Bound all
response bytes to 128 KiB, large enough for the maximum legal UTF-8 DTO but small enough to prevent
unbounded browser allocation.

Load the shared one-card/three-card interpretation panel only after a deterministic result exists.
Starting is always an explicit user action. The client uses a pure finite state machine, one
in-flight request, abortable recursive timeouts rather than overlapping intervals, stale-response
sequence rejection, foreground-only polling, cancellation, and at most eight polls. A transient
manual retry reuses the same operation ID and POST; terminal failures do not silently retry or
redraw. No provisional text, skeleton prose, private prompt, free-text input, or browser storage is
introduced.

Label durable model output `AI-generated interpretation · independently checked`, label the safe
replacement `Reviewed non-AI fallback`, and display the exact boundary `Symbolic reflection, not
professional advice.` The panel has localized loading, final, offline, retry, rate-limit,
permission, session, not-found, conflict, unavailable, and invalid-response states with semantic
live/focus behavior and keyboard-reachable controls.

Keep production composition hard safe-off. The route and client contract are complete, but both
server adapters return only the privacy-safe unavailable error until a separate task composes an
approved catalog, content, safety policy, provider/model/reviewer, budget, and owner-bound durable
read path. No real provider, network request, credential, paid inference, or production activation
is authorized by this decision.

## Alternatives considered

| Option | Benefits | Costs/risks | Why not selected |
| --- | --- | --- | --- |
| Stream provisional provider prose | Fast perceived response | Can expose text before D-041 verification and persist unsafe UI state | Poll status only and reveal durable final output atomically |
| Let GET claim or resume work | Fewer endpoints | Reads become paid side effects; refresh/prefetch can duplicate work | Keep POST start and GET status capabilities separate |
| Automatically start after the card reveal | One fewer click | Removes consent and makes every reading potentially billable | Require an explicit interpretation action |
| Retry with a new operation ID | Simple client reset | Can duplicate inference and break exact replay | Reuse the original operation ID for manual retry |
| Return internal generation records | Less projection code | Leaks identifiers, provenance, digests, cost, and lease state | Re-parse a closed public DTO before serialization |
| Enable a synthetic provider locally | Immediate demo text | Misrepresents activation and weakens provider/content approval gates | Ship complete safe-off adapters and deterministic test fixtures only |

## Consequences

One-card and three-card readings now share a bounded, accessible final-only interpretation
experience. Refreshes and polling cannot start work, late responses cannot overwrite a newer state,
and users can distinguish verified AI output from independently reviewed non-AI fallback. The API
can later receive a production adapter without changing the browser contract or exposing transient
provider text.

The feature remains unavailable on an ordinary production/local runtime until the existing catalog,
provider/model/reviewer, content, safety, budget, and deployment gates are satisfied. RIT-036 must
still enforce release regression/adversarial thresholds; RIT-037 owns constrained regeneration and
history; RIT-038 owns approved privacy-safe metrics; and RIT-122 owns production denial-of-wallet
controls.

## Validation

RIT-035 contract, machine, transport, panel, route, runtime, proxy, and message tests cover all four
response arms; exact public projection; maximum legal UTF-8 response size; private-key rejection;
same-origin/body/idempotency rules; read-only GET composition; bounded foreground polling; stop,
stale response, same-operation retry, and terminal failure behavior; final-only rendering; and
safe-off runtime errors. The full repository unit, formatting, lint, type, architecture, production
build, configuration-boundary, and production-artifact accessibility gates pass. The final
production-artifact browser path also proves exact explicit start, private failure, same-operation
retry, held non-displayable processing, durable verified output, offline zero-start, reconnect,
reviewed fallback, focus, mobile reflow, and local-only requests across 31 Axe scans.

## Rollout and rollback

No production provider, model, reviewer, SDK, key, network request, paid inference, content or
safety-policy activation, payment, migration, deployment, or public launch changes. Before any
production activation, rollback removes the unused route, safe-off adapters, client panel, and
translation keys. After activation, rollback disables the adapter through its approved operational
gate while preserving durable interpretation/verification records under their existing parent
expiry; destructive data changes require separate owner approval.
