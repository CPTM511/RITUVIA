# D-027: Production-artifact accessibility and pseudolocale gate

- Date: 2026-07-17
- Owners: qa_security, frontend, localization, architect
- Related tasks: RIT-014, RIT-028, RIT-100, RIT-101
- Evidence references: .github/workflows/ci.yml, scripts/verify-web-accessibility.mjs, apps/web/test/accessibility-policy.mjs, apps/web/test/accessibility-contrast.test.ts, apps/web/test/web-accessibility-policy.test.ts

## Context

The English public shell has four reviewed server-rendered routes, an accessible shared UI contract,
and a finite production build. It still needs a repeatable CI boundary for browser semantics,
keyboard behavior, target size, text expansion, logical RTL layout, themes, reduced motion, and
no-JavaScript content. Pseudolocales must exercise the layout without becoming public routes or
claiming that the later ICU and Arabic milestones are complete. Axe cannot calculate contrast over
the shell's radial gradients and transparent header blend, so a blanket incomplete-result waiver
would hide future regressions.

## Decision

Run exact pinned Playwright Chromium and axe versions in the existing Quality job, immediately after
the reviewed production build. Install only the Chromium headless shell in CI. Serve an in-memory
allowlist containing the four exact documents and only the local artifacts referenced by those
documents on an ephemeral loopback address; block external requests, unexpected request targets,
HTTP failures, browser errors, and console warnings/errors.

Scan all four pages in light English, at-least-40% expanded LTR, RTL, and dark states with WCAG 2.0,
2.1, and 2.2 AA plus best-practice tags. Independently verify complete forward and reverse keyboard
order, visible unclipped focus, skip-link transfer, 44px targets, native selected-option fit,
desktop/mobile reflow, logical RTL geometry, reduced-motion computed behavior, and meaningful
no-JavaScript content. `en-XA` and `ar-XB` are test-only DOM language/direction markers; URLs,
canonical metadata, public links, the supported-locale catalog, and build inventory remain English.

All axe violations and all unexpected incomplete nodes fail. The only accepted incompletes are the
exact route-and-state `color-contrast` selectors already caused by gradient or transparent blended
backgrounds, and source tests must prove their foreground tokens meet 4.5:1 against the worst-case
light, dark, and system-dark composites. The no-JavaScript context may ignore only the expected
same-origin script-preload failure with Chromium's exact `csp` reason; every other failure remains
blocking.

## Alternatives considered

- Add a fourth CI job: rejected because the current remote owner contract names exactly three
  required jobs and the smoke belongs to the existing build-producing Quality job.
- Publish real pseudolocale routes: rejected because RIT-100 and RIT-101 own production ICU and full
  Arabic/RTL architecture, review, and activation.
- Suppress all axe `color-contrast` incompletes: rejected because that could hide a new selector,
  theme, or non-gradient contrast failure.
- Test only component fixtures or only the home page: rejected because the four built documents and
  information-page backgrounds differ from the shared component catalog.

## Consequences

CI now pays the cost of one pinned headless browser install and a four-route browser matrix, so the
Quality timeout rises from 20 to 30 minutes. The gate is deterministic, has no production/database
dependency, sends no remote request, and does not create a language, legal, payment, analytics, or
content activation. Chromium/axe remains complementary evidence; current screen readers,
Firefox/WebKit, real zoom, and complete ICU/Arabic behavior remain later release work.

## Validation

Unit and mutation tests must lock exact browser versions, install and execution order, route and tag
inventory, path safety before artifact reads, 40% expansion and placeholder preservation, public
pseudolocale rejection, exact axe incomplete handling, and worst-case contrast math. The production
browser run must report four routes, 16 axe scans, bidirectional keyboard coverage, 44px targets,
expanded LTR, desktop/mobile RTL, dark/reduced-motion/no-JavaScript states, and local-only traffic.

## Rollout and rollback

No production rollout, public-shell activation, locale activation, data migration, or external state
change occurs. Revert the RIT-014 commit to remove the browser dependency, CI steps, scripts, tests,
and small responsive select fix; the previous three-job workflow and English shell remain. Rebuild
before rerunning the smoke so local evidence cannot refer to stale artifacts.
