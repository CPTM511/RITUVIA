## Context

D-098 intentionally kept the recovery branch NO-GO for production and real value. Item 12 then
found bounded repository gate defects before a production candidate could be nominated. Separately,
the current Stripe adapter rejects every production/live configuration even when correct live
credentials are supplied. That hard rejection means an eligible customer could not pay.

Owner authority can remove an internal approval gate. It cannot create a legal entity record,
provider underwriting, account capability, tax decision, policy text, support contact, price,
statement descriptor, credential, production database, or successful provider response that has
not actually been supplied and verified.

## Decision

Close Item 12 from a new before-state. If every mandatory recovery gate passes, implement the
smallest production-capable real-funds slice through Stripe-hosted Checkout. The application must
support both explicit `test` and `live` modes without accepting mixed-mode keys, prices, sessions,
events, accounts, catalogs, policies, databases, or webhook secrets.

The first live rollout is Stripe only. Coinbase/USDC remains a future non-custodial option and is
not activated by this first-provider rollout. Production AI with private content also remains off.
This sequencing limits blast radius; it does not permanently remove either capability.

“Support real funds” means that, when every required live fact and credential is present, an
eligible customer can create a server-priced Stripe-hosted Checkout Session, pay through Stripe,
return to a truthful pending state, receive value exactly once after a verified live webhook, and
be reconciled, refunded, audited, disabled, and rolled back safely. It does not require creating a
fake customer or forcing a charge when no customer exists.

## Required factual production prerequisites

Before checkout can be enabled, the exact environment must prove all of the following without
printing or committing secrets:

1. legal seller registered particulars and authorized operating account;
2. United States / English / 18+ production country-policy version;
3. Stripe live account identity and required product/country capabilities;
4. live restricted secret key, unique live webhook secret, live Price IDs, and expected account ID;
5. production catalog version, USD minor-unit amounts, subscription intervals, refund-policy
   version, statement descriptor, support contact, and terms/privacy versions;
6. selected tax or Merchant-of-Record treatment and provider configuration;
7. isolated production database roles, encrypted secrets, backups/PITR, non-empty restore, and
   least-privilege attestation;
8. live webhook delivery, duplicate/out-of-order handling, refund/dispute, reconciliation, alerts,
   kill switches, and rollback evidence;
9. exact source SHA, SBOM/provenance, AGPL notices, and durable Corresponding Source route; and
10. zero open Critical/High findings and a passing limited-production smoke test.

Any absent, stale, malformed, unverifiable, test-mode, or cross-environment value keeps new
purchases disabled. No placeholder may satisfy a factual production prerequisite.

## Consequences

The repository may now implement and deploy a production-capable Stripe Live path, configure an
approved production environment, and support real customer funds. Existing hard-coded sandbox
rejections must become explicit mode-isolation checks rather than being deleted. Test Mode remains
fully supported and must never share credentials, prices, events, accounts, webhooks, or data with
Live Mode.

The broad Owner approval does not close OWN-002 by assertion. OWN-002 closes only when the exact
Stripe live account and capabilities are verified against the intended business and launch scope.
Likewise, missing legal/commercial particulars remain factual blockers that code must surface and
enforce. Coinbase/USDC, production AI with private content, and non-English paid launch remain off
in the first rollout.

## Rollout and rollback

- Enable `stripe_checkout_enabled` and `new_purchases_enabled` server-side, one provider at a time.
- Start with the United States, English, adults 18+, a limited cohort, conservative transaction
  and daily-volume caps, and one exact catalog.
- Keep emergency disable available without a code change and test it before accepting customers.
- Use hosted Checkout only; never handle PAN/CVC or grant Credits from a return URL.
- Monitor webhook age/failure, order/provider drift, duplicate grants, refunds/disputes, and
  reconciliation continuously during the limited launch.
- Stop new purchases on provider-mode mismatch, reconciliation drift, missing source disclosure,
  restore failure, private-data leak, or a Critical/High finding.

Rollback disables `new_purchases_enabled` and `stripe_checkout_enabled`, expires or cancels
outstanding hosted sessions where supported, continues accepting and reconciling already-issued
signed webhook events, preserves payment and ledger history, reverts traffic to the last verified
source SHA, and rotates any credential implicated by the rollback. Never delete provider events,
orders, ledger entries, refund/dispute records, backups, migrations, or archive evidence.

## Validation

Validation requires Node `24.18.0` and pnpm `11.13.1`, the complete Item 12 matrix, mixed-mode
negative tests, Stripe live configuration contract tests without secrets, production build and
browser tests, database migration/restore, protected staging regression, exact-source deployment,
live account attestation, live webhook verification, and a bounded production smoke/reconciliation
result. A successful build or test-mode checkout alone is insufficient.
