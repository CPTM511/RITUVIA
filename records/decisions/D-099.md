# D-099: Suppress one exact historical Gitleaks schema-version false positive

- Date: 2026-08-01
- Owners: qa_security, operations
- Related tasks: RIT-121
- Evidence references: `scripts/run-pinned-ci-tool.mjs`; `tests/pinned-tool-contract.test.ts`;
  `packages/db/src/commercial-fulfillment-persistence.ts`;
  `docs/reports/RITUVIA_RIT_121_PROTECTED_BETA_THREAT_MODEL_2026-08-01.md`

## Context

The pinned Gitleaks 8.30.1 complete-history scan reported one `generic-api-key` finding at commit
`b99f5234c99f842f3616c773e7871cb6b612db77`, path
`packages/db/src/commercial-fulfillment-persistence.ts`, line 8. The redacted match was the literal
`commercial.fulfillment.v1`.

Source and call-site review proves that the literal is a public idempotency schema-version label
persisted with fulfillment records. It is not a provider credential, bearer, key, token, connection
string, or secret-derived value. Rotating it would be a data-contract change, not secret rotation.

## Decision

Add only this exact immutable fingerprint to the temporary ignore file generated by
`scripts/run-pinned-ci-tool.mjs`:

`b99f5234c99f842f3616c773e7871cb6b612db77:packages/db/src/commercial-fulfillment-persistence.ts:generic-api-key:8`

Keep the Gitleaks default rule set, full-history mode, redaction, checksum-pinned binary, current
repository secret policy, and `--ignore-gitleaks-allow` unchanged. Do not add a path, regex, rule,
commit range, or repository configuration allowlist. Any future finding, content change, tool/rule
change, path/line change, or fingerprint drift must fail again and receive a new review.

The exception expires when the immutable commit is no longer in the scanned history or a reviewed
Gitleaks release no longer reports the fingerprint. Shared history must not be rewritten merely to
remove it, so the practical review trigger is every pinned Gitleaks update.

## Alternatives considered

| Option | Benefits | Costs/risks | Decision |
| --- | --- | --- | --- |
| Disable the generic rule | Removes the false positive | Hides unrelated current and future leaks | Rejected |
| Add a path or regex allowlist | Shorter configuration | Suppresses unknown findings in a security-sensitive persistence file | Rejected |
| Rename the current constant | Avoids a current-source match | Historical commit still fails; changing an idempotency version risks replay drift | Rejected |
| Rewrite Git history | Removes the historical line | Destructive, breaks shared audit history and branch protection | Rejected |
| Ignore one exact fingerprint | Preserves all other scanning | Requires durable review evidence | Selected |

## Consequences

The full-history security job can distinguish the reviewed non-secret historical literal without
weakening current or future secret detection. The exact count increases from 11 to 12 reviewed
historical fingerprints. RIT-121 records the scope, reason, review trigger, and verification.

## Validation

The pinned-tool unit contract requires 12 exact generic-key fingerprints and the new complete
fingerprint literal. It passes 1/1. The checksum-pinned Gitleaks 8.30.1 rerun scans 85 commits and
about 13.38 MB with no remaining leak.

## Rollout and rollback

Roll out only through the repository-owned temporary ignore-file generator and its test. No secret,
provider, deployment, runtime, database, migration, product, or user-data behavior changes.

Rollback removes the exact fingerprint. That intentionally reopens the historical scan until a
reviewed tool/rule update no longer reports the immutable literal; never replace it with a broader
suppression.

## Sources and approvals

- RIT-121 `qa_security` review of the exact source, historical commit, and all call sites.
- Production security requirement that suppressions record reason, scope, expiry, and approver.
- Root prohibition on disabling or weakening security tools to make a build pass.
