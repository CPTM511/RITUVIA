# D-039: Fail-closed pre-generation safety and request-bound authorization

- Date: 2026-07-18
- Owners: ai_safety, architect, qa_security, privacy
- Related tasks: RIT-032, RIT-033, RIT-034, RIT-036
- Evidence references: packages/domain/src/question-intake.ts, packages/domain/test/question-intake.test.ts, packages/ai/src/safety.ts, packages/ai/src/provider.ts, packages/ai/test/safety.test.ts, packages/ai/test/fixtures/pre-generation-safety-v1.json, scripts/verify-workspace-build.mjs

## Context

The owner-approved `question-intake.en.v1` lexical boundary stops known high-stakes and crisis
phrasing before a reading, but D-030 explicitly leaves nuanced or probabilistic moderation to
RIT-032. D-037 created an opaque allowed-only generation authorization, yet its original binding
did not prove that the exact intake request had passed a production-approved safety policy.
RIT-033 must not be able to continue divination, retrieval, prompt assembly, or generation by
trusting a client-supplied route, a structurally forged decision, or an authorization minted for a
different request.

## Decision

Keep the RIT-032 boundary pure and provider-neutral in `@rituvia/ai`. It accepts bounded raw JSON,
re-parses it with the domain intake contract, and re-runs `question-intake.en.v1`; client-provided
evaluations and routes are never inputs. Theme-only requests can be allowed without exposing text
to a classifier. A lexically detected crisis stops immediately. Every other non-empty question
requires an externally injected classifier whose exact classifier version, checksummed policy,
and approval reference are independently checked against server-owned authority before the text is
shared.

Classifier output is strict bounded JSON with fixed categories and exact registration provenance.
Malformed, unavailable, unapproved, or mismatched classification fails closed. The route is merged
with the intake result using immutable precedence `crisis > blocked > reframed > allowed`; a later
stage may only retain or strengthen the earlier restriction. Uncertainty has a `reframed` floor,
while any reported crisis or blocked category still takes precedence. Unsafe suggestions are only
fixed domain codes; a crisis has no suggestion.

Raw and normalized questions remain transient inside evaluation. Public evaluation, decision,
error, and continuation values omit the question, classifier categories, prompts, journal data,
and arbitrary diagnostics. The classifier is the only callback that can receive question text.
Non-allowed routes return before any continuation callback, policy-activation verifier, or
authorization issuer runs. The shared intake parser rejects lone UTF-16 surrogate code units before
normalization or classification while preserving valid supplementary characters such as emoji.

An allowed route still cannot continue until a second injected authority verifies the exact
pre-generation policy approval reference. Only then can the internal issuer mint an opaque
authorization bound to request ID, modality, reading type, locale, theme, intake policy, safety
policy, and policy approval. Neither authorization issuer is exported from the package root.
RIT-033 must validate that complete binding before constructing a provider request.

## Alternatives considered

| Option | Benefits | Costs/risks | Why not selected |
| --- | --- | --- | --- |
| Trust the intake API response | Reuses an existing result | A client can forge or replay routes; later policy drift is hidden | The gate re-evaluates the bounded raw contract |
| Classify only lexically unknown text | Fewer classifier calls | Nuanced crisis wording inside allowed or blocked text could be missed | Every non-empty non-crisis question is classified |
| Export a general authorization issuer | Easier orchestration | Any package caller could mint permission without the gate | Issuance stays internal to the safety module |
| Persist risk categories for analysis | Easier moderation analytics | Creates sensitive profiling and retention without consent or necessity | Categories remain transient and synthetic fixtures provide evaluation evidence |
| Activate a concrete model or provider | End-to-end behavior now | Crosses provider/model, credential, safety-policy, and production approval gates | RIT-032 defines injected contracts only |

## Consequences

RIT-033 receives one allowed-only continuation boundary and cannot accidentally run downstream work
for `reframed`, `blocked`, or `crisis` evaluations. Request-bound authorization also prevents
confused-deputy reuse across readings. Classifier and policy authority correctness remain the
responsibility of the future server composition; there is deliberately no permissive default.

The policy is English/Tarot-only and safe-off. It does not approve a classifier, model, provider,
credential, crisis-resource program, new wording, another locale or country, persistence, API/UI
route, or production activation. Those actions retain their explicit owner gates. RIT-034 still
must verify generated prose, and RIT-036 must add release-level multilingual and adversarial evals.

## Validation

Synthetic fixtures cover theme-only continuation, all four routes, mixed-category precedence,
uncertainty, no-downgrade behavior, high-stakes and crisis language, safe-context false positives,
registration and result drift, classifier denial/failure, policy denial/failure, forged values,
request-binding mismatch, zero unsafe continuation, immutability, and private canaries. Type,
architecture, lint, unit, compiled-artifact, configuration-boundary, and evidence gates enforce the
contract without a network or database dependency.

## Rollout and rollback

No runtime route, database, migration, provider, model, credential, external request, content,
payment, or deployment is changed. Rollback removes the unused safety module, its additional
authorization binding, the intake parser's lone-surrogate rejection, fixtures, tests, and build
evidence; there is no external side effect or stored data cleanup.
