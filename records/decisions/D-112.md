# D-112: Require one database-atomic invite before protected-Beta session issuance

- Date: 2026-08-03
- Owners: product, qa_security, privacy, operations
- Related tasks: RIT-168, RIT-130
- Evidence references: `docs/runbooks/RIT-168_PROTECTED_BETA_INVITES.md`;
  `packages/db/scripts/verify-protected-beta-invites.ts`;
  `scripts/verify-protected-beta-invite-browser.mjs`; D-097; D-100; D-104

## Context

D-104 approved an at-most-25-person, English-speaking adult protected Beta with deny-by-default,
single-use, revocable admission. The anonymous-session path still had no invite state, atomic
cohort limit, replay contract, operator issuance/revocation path, or user-facing recovery screen.
An old active anonymous cookie could therefore not be distinguished from a protected-Beta session.

## Decision

Require one opaque, unexpired, unconsumed, and unrevoked invite under the exact
`own-019.protected-beta-invite.v1` policy before creating or resolving a protected-Beta anonymous
session. Enforce the 25-seat issuance cap, invite consumption, session binding, revocation, and
idempotency in PostgreSQL transactions. A pre-policy anonymous cookie has no protected-Beta
authority and cannot bypass admission.

Store only a SHA-256 invite-token digest and bounded state metadata. Never persist or log the raw
invite, IP address, user agent, device identifier, question, journal, or other private content. The
raw invite is emitted once to a new exclusive mode-`0600` operator file outside the repository and
is never printed to standard output. Revocation also revokes the bound anonymous session.

Use `/en/beta` as the private user entry. Its exact Button is `Enter protected Beta`. The invite is
kept only in component memory and the bounded same-origin request body, never in a URL, referrer,
browser storage, analytics event, or error response. Missing, invalid, used, expired, revoked, and
temporarily unavailable admission share calm, non-enumerating recovery.

## Alternatives considered

Public signup, reusable cohort passwords, URL query tokens, email-provider delivery, IP/device
fingerprinting, account-first admission, browser-local allowlists, and non-atomic counters were
rejected. They either expand public access, leak credentials, introduce unnecessary personal data
or providers, or permit replay and race-condition over-admission.

## Consequences

Repository-local protected-Beta session issuance is now deny-by-default and bounded to 25 issued
seats. Exact same-request idempotency can recover a lost response without issuing a second session;
changed replay, concurrent double use, expired/revoked use, and seat 26 fail closed.

This decision does not send invitations, provision standing staging, configure edge protection,
activate a provider, prove provider restore, complete external security review or Gate H, deploy,
change DNS, or authorize launch.

## Validation

Focused configuration, server, route, proxy, PostgreSQL concurrency/privilege/restore, production
Web build, real-browser accessibility/mobile/privacy, architecture, migration, record, generated
evidence, and secret checks are required for RIT-168 closure.

## Rollout and rollback

Rollout requires the normal additive migration, least-privilege roles, private operator procedure,
standing-staging rehearsal, external ingress, and Owner gates. Rollback disables invite admission
composition and preserves immutable invite/session evidence. Record deletion, retention changes,
production migration, or deployment require separately reviewed forward actions and Owner
approval.
