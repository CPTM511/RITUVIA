# D-022: Canonical repository record workflow

- Date: 2026-07-17
- Owners: product, architect
- Related tasks: RIT-009
- Evidence references: RIT-009 repository review and verification

## Context

RITUVIA already had a canonical backlog, current-status document, concise decision register, four
record templates, a task-result JSON schema, and generated manual/checksum evidence. They were not
connected by an enforced contribution workflow. Copying task status and dependencies into a second
task document could drift, task-result output had no durable record references, and the two generated
artifacts could be refreshed in the wrong order.

## Decision

Keep queue fields exclusively in `BACKLOG.md`, current truth in `PROJECT_STATUS.md`, and the concise
decision/supersession index in `DECISIONS.md`. Store detailed task, decision, incident, and experiment
records as stable ID-named Markdown files below typed `records/` directories. Require task-result
output to link the applicable records, enforce the record graph in local and CI checks, and expose one
generated-evidence synchronizer that always rebuilds the compact record index, renders the manual,
and only then hashes the tracked repository.

The explicitly grandfathered completed tasks are RIT-000, RIT-001, RIT-002, RIT-003, RIT-005,
RIT-006, and RIT-007. RIT-004 is not grandfathered. Any other implementation task must gain a task
dossier when work begins and retain it after completion.

## Alternatives considered

| Option | Benefits | Costs/risks | Why not selected |
| --- | --- | --- | --- |
| Put all detail in `BACKLOG.md` and `DECISIONS.md` | Few files | Large mutable tables, repeated evidence, poor incident/experiment structure | It increases conflict and stale duplication. |
| Use external issue/project software as canonical | Rich workflow UI | Requires a remote/vendor, permissions, availability, and owner setup | RIT-009 must work locally and cannot invent remote approval. |
| Use one flat `records/` namespace | Short paths | Conflicts with the established `D-NNN` namespace and weakens type-specific policy | Typed directories make grammar and retention explicit. |
| Embed every record in the compiled manual | Complete single file | Unbounded growth and wider incident-evidence exposure | The manual embeds only the compact index and repository-safe policy. |

## Consequences

Contributors maintain one task dossier for active work. A deterministic compact index supplies
discoverability without duplicating full record text. Automation gains stable paths but must emit the
expanded task-result contract. CI adds a fast local record gate. Checksums cover only Git-indexed
package files and remain last in the generation order, so unrelated untracked personal files cannot
pollute canonical evidence.

Detailed records are repository-visible and therefore contain only minimized, non-sensitive facts.
Secrets, private user content, raw logs/provider payloads, screenshots, dumps, and approval originals
remain in access-controlled systems referenced by opaque non-secret IDs.

## Validation

`pnpm check:records` validates IDs, headings, required sections, canonical-field exclusions, backlog
coverage, reference and supersession graphs, schema/example semantics, contribution rules, remote
content restrictions, and exact generated-index coverage. Mutation tests exercise representative
bypasses, while an exact schema fingerprint and CI contract lock the full committed contract.
`pnpm check` invokes record and generated-evidence checks through the evidence chain, while
instruction-pack validation checks schema and artifact shape offline.

Reconsider the directory layout only after measured merge/search/scale evidence shows it is a
bottleneck or an approved external system can preserve offline history and stable links.

## Rollout and rollback

RIT-009 introduces the policy, first task/decision records, schema change, CI step, and generation
command in one repository-only commit. Rollback removes the new gate and record references, restores
the old schema/prompts, and regenerates the manual/checksums. It does not touch production or
external state.
