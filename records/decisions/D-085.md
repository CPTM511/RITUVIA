# D-085: Local-only redacted one-card share artifacts

- Date: 2026-07-29
- Owners: product, frontend, localization, qa_security
- Related tasks: RIT-115
- Evidence references: `apps/web/app/_components/tarot-share-card-artifact.ts`;
  `apps/web/app/_components/tarot-share-card.tsx`;
  `scripts/verify-tarot-share-browser.mjs`

## Context

RITUVIA needs opt-in sharing without turning a private reading result into public metadata,
uploading a personalized asset, or carrying a question, result identifier, interpretation, birth
data, intention, journal text, or account data into another surface. The current runtime locale is
English; `en-XA` and `ar-XB` remain test-only and cannot be accepted as production share locales.

The product specification asks for card, orientation, a generic reflection line, and the bounded
selected theme by default, while also requiring preview and redaction control. Device share APIs
do not consistently support files, and a separate HTML approximation would not prove what the
downloaded or shared SVG actually contains.

## Decision

Implement sharing only for the completed private one-card flow. Build one immutable
`tarot-share-card.v1` projection from an exact allowlist: configured brand, reviewed card title,
localized orientation, optional bounded theme label, fixed generic reflection, fixed safety
boundary, localized accessible description, and the public locale Tarot library canonical URL.
Reject unsupported locales, control or bidi characters, malformed or credential/query/fragment
URLs, private result paths, and bounded-text violations.

Generate a self-contained 1200 by 630 SVG locally. Preview that exact SVG Blob rather than a
separate HTML facsimile. Include the bounded theme by default but let the user remove it before
preview, download, or share; theme removal must affect the projection, accessible description,
SVG bytes, and native-share payload. The fixed filename contains no identifier.

Offer local SVG download on every supported browser. Expose native sharing only when the browser
supports `navigator.share`, `navigator.canShare`, and the exact SVG file payload. Do not silently
fall back to a link-only share while claiming the card was shared. Do not upload, persist, cache,
tokenize, or analyze the artifact.

Keep the private result page noindex and without canonical, Open Graph, or Twitter output. The
public canonical appears only inside the local share artifact and explicit native-share payload.
Production projection accepts only an active reviewed locale. Tests may construct `en-XA` and
`ar-XB` projections directly against the serializer to verify expansion and RTL structure without
admitting either locale into routes or runtime share output.

## Alternatives considered

| Option | Benefits | Costs/risks | Decision |
| --- | --- | --- | --- |
| Public share URL or uploaded image | Easy social previews | Creates retention, access-control, deletion, abuse, and private-leak surface | Rejected |
| Client screenshot of the full result | Minimal design work | Captures private prompts, IDs, interpretations, and unrelated UI | Rejected |
| HTML preview plus separate SVG | Easy responsive preview | Preview cannot prove final artifact bytes or layout | Rejected |
| File share with link-only fallback | Broader device support | Success message can falsely claim an image was shared | Rejected |
| Exact local SVG preview/download/file share | Auditable, private, offline-capable | Native file sharing is unavailable on some browsers | Selected |

## Consequences

Three-card, numerology, astrology, ritual, uploaded, public-token, and social Open Graph share
artifacts remain outside RIT-115. New locales require reviewed source and translation records plus
the existing owner language-launch gate. Traditional card artwork remains absent.

The Web CSP admits `blob:` only for `img-src` so the locally generated SVG can be previewed; script,
connect, object, frame, worker, media, and external image boundaries remain unchanged. Object URLs
are revoked after replacement, download, or preview closure.

## Validation

Pure tests cover the exact allowlist, theme redaction, XML escaping, canonical restrictions,
control characters, normalization, length limits, production pseudolocale rejection, and
test-only expanded LTR/RTL serializer structure. The dedicated production-artifact Chromium gate
checks the exact preview Blob, downloaded SVG, native file-share payload, localized alt text,
private canaries, no social metadata, no upload or external request, exact storage boundary,
object-URL revocation, 320px reflow, touch targets, and serious/critical Axe findings.

## Rollout and rollback

No database, provider, object storage, worker, analytics, public route, deployment, DNS, country,
or locale activation is added. Rollback removes the one-card component, serializer, dedicated
browser gate, and `blob:` image allowance. No data reversal is required.
