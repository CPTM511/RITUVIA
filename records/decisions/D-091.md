## Context

The production build pack explicitly permits Stripe Test Mode integration without further
production activation approval and separately requires Codex to stop before live Stripe. The
existing OWN-002 backlog item is broader: it is complete only when primary and backup payment
providers have supplied written approval for the exact business, products, countries, prices, and
refund description.

The owner instructed Codex to approve OWN-002 and unlock RIT-063. No provider letter, provider
account evidence, backup-provider selection, live eligibility, country underwriting scope, or
production contract was supplied. Treating the owner instruction as external provider evidence
would weaken the payment gate and create a false production-readiness claim.

## Decision

Create OWN-017 as the exact sandbox-development approval and mark it Done. RIT-063 depends on
RIT-062 and OWN-017 rather than production underwriting.

The approved RIT-063 scope is:

- Stripe Test Mode hosted Checkout Sessions;
- one-time payment mode only, with subscriptions remaining in RIT-070;
- synthetic United States policy and USD prices only;
- products and integer minor-unit prices resolved from the immutable server catalog;
- exact Stripe test Price IDs independently checked against the server amount and currency;
- provider idempotency derived from the internal order/payment attempt;
- hosted HTTPS redirect only, with no card data handled by RITUVIA;
- return state remaining pending until later signed-webhook processing; and
- no Credits, entitlement, paid-state, refund, dispute, reconciliation, or production activation
  authority.

Keep OWN-002 Blocked under its existing acceptance criterion. It continues to block RIT-140 until
written primary and backup provider approval covers the exact production entity, business
description, products, launch countries, prices, refund terms, statement descriptor, support,
fraud controls, and any recurring scope.

## Alternatives considered

| Option | Benefit | Risk | Decision |
| --- | --- | --- | --- |
| Mark OWN-002 Done from the owner message | Minimal queue change | Falsely represents external underwriting | Rejected |
| Keep RIT-063 blocked on production approval | Maximum conservatism | Conflicts with the pack's explicit Test Mode permission | Rejected |
| Remove every provider gate from RIT-063 | Faster development | Loses explicit sandbox scope and auditability | Rejected |
| Split sandbox approval from production underwriting | Accurate scope and safe sequencing | Adds one owner-gate record | Selected |

## Consequences

RIT-063 is the sole Ready engineering task. It may implement and locally verify the Stripe Test
Mode boundary, but real sandbox network verification still requires test credentials and exact
test Price IDs supplied through the approved secret/configuration path. Missing credentials must
remain a truthful dynamic-verification blocker rather than being replaced by live keys, committed
secrets, or a claim that a mock is Stripe.

RIT-064 through RIT-069 remain sequentially closed until their dependencies complete. Production
checkout, legal/tax/country activation, live credentials, production migration, deployment, DNS,
indexing, customer communication, and public launch remain unchanged and unapproved.

## Validation

Backlog validation must show OWN-017 Done, OWN-002 Blocked, RIT-063 Ready with complete
dependencies, and RIT-140 still dependent on OWN-002. Record/index/generated-evidence checks must
pass. No provider request, credential creation, external payment call, database mutation,
deployment, or launch occurs in this decision-only change.

## Rollout and rollback

Rollout changes only the durable decision and queue state. If the sandbox scope is withdrawn,
return RIT-063 to Blocked or Planned and record a superseding decision; do not reinterpret
OWN-002. Production provider evidence can close OWN-002 only through a later record that identifies
the actual provider approvals and exact approved scope.
