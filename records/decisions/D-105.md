# D-105: Use fail-closed private cost guardrails before budget activation

- Date: 2026-08-02
- Owners: operations, qa_security, privacy, product
- Related tasks: RIT-127, OWN-005
- Evidence references: `packages/analytics/src/cost-guardrails.ts`;
  `scripts/generate-cost-guardrail-report.ts`; `docs/runbooks/RIT-127_COST_GUARDRAILS.md`;
  `docs/reports/RITUVIA_OWN_005_COST_BUDGET_DECISION_REQUEST_2026-08-02.md`

## Context

RIT-038 already reports provider-estimated AI cost and coverage without treating missing cost as
zero. RIT-120 preserves unavailable cost as `unknown`. RIT-127 must add provider/feature allocation,
anomaly evaluation, approved alert/degradation directives, and atomic runtime enforcement, but
OWN-005 has not approved production amounts, vendors, currencies, alert destinations, or runtime
activation.

## Decision

Adopt `cost-guardrail.v1` as one strict framework-independent daily safe-off simulation contract.

- Use one exact 24-hour UTC window captured within six hours of window close. Durable source
  evidence expires after 30 hours; unavailable, stale, or synthetic sources cannot authorize spend.
- Accept only `unavailable` or `proposed_policy`; proposed policy cannot carry an approval reference
  and never authorizes spend. A future approved schema must bind exact policy bytes, environment,
  effective/expiry time, and a real Owner decision before gaining authority.
- Use finite provider and feature code registries rather than arbitrary labels. Require proposed
  line allocations to sum exactly to the proposed total. Observed provider/feature spend
  without a line is `unbudgeted`; a missing observation or incomplete reporting makes remaining
  budget and utilization unavailable rather than zero.
- Carry the proposed warning threshold and warning/limit action on each line. The evaluator
  may recommend only alert/annotation, reduced non-critical background concurrency, paused
  non-essential content generation, or disabled non-essential paid-provider spend.
- Classify safety, payment integrity, backups, privacy rights, and existing entitlements as
  `essential_no_automatic_degradation`; their only permitted budget action is alert/annotation.
- Keep decision status blocked and all non-essential spend authorization denied. The evaluator does
  not expose a non-atomic admission API, reserve cost, call a provider, mutate runtime
  configuration, or execute a degradation action.
- Keep every generated report private, input-digest-bound, mode `0600`, no-overwrite, and free of
  private content, user/session/order identifiers, raw provider payloads, and free-text metadata.

OWN-005 remains the authority for exact production budget amounts and activation. Until that
approval and a durable aggregate/provider integration exist, the current report remains blocked
and production paid-provider spend remains safe-off.

## Alternatives considered

| Option                              | Benefits                    | Costs/risks                                    | Decision |
| ----------------------------------- | --------------------------- | ---------------------------------------------- | -------- |
| Invent production amounts           | Immediate green dashboard   | Unauthorized spend policy                      | Rejected |
| Add a live admin/runtime controller | Direct control              | No durable source, provider hook, or approval  | Rejected |
| Reuse global Web read-only mode     | Existing containment        | Could impair privacy rights or essential flows | Rejected |
| Strict safe-off evaluator           | Small, testable, reversible | Activation remains separately gated            | Selected |

## Consequences

RIT-127 remains Blocked by OWN-005 and the missing durable atomic reserve/commit/release contract.
The Owner dashboard may show only the safe-off guardrail simulation as locally verified while
keeping exact monetary budget and production cost state unavailable. RIT-128 can proceed as the
sole independent Ready item and exercise the blocked/reporting/provider-failure cases without
claiming that RIT-127 is complete.

Future production integration must add a durable cost aggregate, provider-specific deduplication
and late-correction rules, atomic reservation/enforcement where needed, approved external alert
routing, and explicit OWN-005 values. This decision does not approve any vendor, model, payment,
marketing spend, deployment, DNS change, public access, or launch.

## Validation

Unit and private-file tests cover exact parsing, allocation reconciliation, partial reporting,
stale/synthetic/unavailable sources, unbudgeted spend, warning/limit actions, essential-service
protection, fixed registries, denied spend authority, private-field/accessor rejection, digest
binding, mode `0600`, no overwrite, symlink rejection, compiled exports, and CI inclusion.

## Rollout and rollback

This record activates no runtime control. Rollback removes the analytics module, private report
generator, CI/build contracts, runbook, and task record. There is no migration, provider state,
customer data, budget, or production action to reverse.
