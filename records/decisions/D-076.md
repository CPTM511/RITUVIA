# D-076: Approval-bound localized public route registry

- Date: 2026-07-27
- Owners: owner, growth_seo, localization, frontend, qa_security
- Related tasks: RIT-103, RIT-105, RIT-106, RIT-113, RIT-114
- Evidence references: `apps/web/app/_i18n/localized-public-routes.ts`;
  `apps/web/app/_i18n/public-routes.ts`; `apps/web/app/_i18n/seo.ts`;
  `apps/web/test/localized-public-routes.test.ts`

## Context

The English public shell had exact canonical, robots, and sitemap controls, but paths were spread
across page-family constants, metadata factories hard-coded `en` alternates, the root document
hard-coded English direction, and the single sitemap could not represent locale/content-type
inventories. No real second locale or stale public slug has been approved.

## Decision

Use stable language-neutral route IDs and an exact approval-bound localization record as the only
source for public static parameters, canonical paths, reciprocal alternates, robots allows,
sitemap membership, substantive-change dates, and redirect targets. Every published localization
must use a canonical BCP 47 tag, finite canonical slug segments, an approved decision reference,
content version, reviewer, and review date. Missing default-locale content, duplicate paths,
unapproved records, and invalid redirect targets fail closed.

Keep `en` as the only production registry locale. Synthetic unit fixtures may exercise
locale-specific `es-419` slugs and same-locale stale-slug redirects, but test records do not enter
runtime, metadata, hreflang, robots, or sitemaps. Future locale admission still requires OWN-004,
RIT-105, RIT-104, RIT-106, and all content/support/country approval evidence.

Serve `/sitemap.xml` as a production-only sitemap index with exact non-empty
`/sitemaps/{locale}-{content-type}.xml` URL sets. Each URL set includes only approved public
documents and reciprocal same-route hreflang links, with `x-default` bound to the reviewed default
locale. Private, personalized, calculator, checkout, account, query, RSC, and unsupported paths
remain absent and noindex.

Execute only explicit, queryless, same-locale redirect-history records as canonical 308 responses
after the public-shell activation check. The production redirect registry remains empty because
Git history contains no superseded public content slug; do not invent aliases merely to populate
the registry. The existing locale-less `/` to `/en` redirect remains the separately reviewed
default-locale redirect.

Move the HTML document root under the validated locale segment so SSR `lang` and `dir` derive from
the admitted locale. Keep a separate root redirect layout. This does not activate any new locale.

Use a checksummed, source-bound runtime message projection containing only approved message text.
Do not ship source rights, reviewer, server configuration, or fallback brand metadata in client
static assets.

## Alternatives considered

| Option                                                 | Benefits                                            | Costs/risks                                                 | Decision |
| ------------------------------------------------------ | --------------------------------------------------- | ----------------------------------------------------------- | -------- |
| Keep page-family route constants                       | Minimal immediate change                            | Canonical, sitemap, redirect, and locale state can drift    | Rejected |
| Activate a synthetic second locale                     | Exercises production hreflang directly              | Falsely bypasses owner, content, support, and country gates | Rejected |
| Invent redirect aliases                                | Populates redirect behavior in production           | Creates unsupported public URLs with no historical basis    | Rejected |
| Stable approval-bound registry plus synthetic fixtures | One runtime source with safe future-locale evidence | Requires generic routes and stricter evidence validation    | Selected |

## Consequences

One matrix now controls the fourteen approved English public routes and three locale/content-type
sitemaps. Numerology and astrology public route files are consolidated into generic dynamic
segment pages, allowing reviewed future collection and guide slugs without parallel route trees.
Metadata and JSON-LD links use the same route IDs as static params and crawl output.

RIT-114 still owns full structured-data eligibility and rich-result crawl validation. This
decision does not authorize another locale, translation, country, language switcher, Search
Console submission, production deployment, DNS change, or public launch.

## Validation

Focused unit and mutation-style tests cover stable IDs, synthetic localized slugs, reciprocal
alternates, exact stale-slug lookup, approval evidence, duplicate/missing-default rejection,
metadata, routing, robots, sitemap index/shards, proxy discovery, and build artifacts.

The production build statically generates all fourteen approved routes through the generic
localized route tree. The real HTTP configuration boundary verifies production sitemap shards,
disabled/unavailable states, RSC/query/private denial, client-delivery isolation, and fail-closed
startup. Production-artifact Chromium verifies fourteen public and three private routes with
accessibility, expanded text, RTL, keyboard, mobile, no-JavaScript, and local-only requests.

## Rollout and rollback

No migration or external state exists. Roll back by reverting the registry, generic route,
metadata, sitemap, proxy, and root-layout changes. No URL redirect restoration is necessary because
the production stale-slug history is empty.
