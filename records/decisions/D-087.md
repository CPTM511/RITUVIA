# D-087: Fail-closed offline SEO/GEO performance and freshness operations

- Date: 2026-07-29
- Owners: product, growth_seo, operations, privacy, qa_security
- Related tasks: RIT-117, RIT-120
- Evidence references: `packages/analytics/src/search-operations.ts`;
  `scripts/generate-search-operations-report.ts`; `scripts/verify-search-operations.ts`;
  `tests/search-operations-report.test.ts`

## Context

The approved English public surface contains exactly 45 source-bound routes with deterministic
quality, crawl, structured-data, and visible GEO authority gates. Those gates prove publication
quality but do not prove actual search-system crawl, index, query, referral, or content-review
performance. No production analytics provider, Search Console connection, tracking notice,
retention policy, or external data access is approved.

An operations loop must therefore distinguish unavailable evidence from poor performance, avoid
small-cohort disclosure, bind every result to current content authority, and produce reviewable
investigation prompts without taking a gated external action.

## Decision

Adopt `seo-geo-operations.v1` as a strict offline aggregate policy over the exact current
45-route inventory.

- Use one exact seven-day UTC window. Capture must occur within 96 hours after the window end.
- Require four explicitly labeled streams: crawl, index, query, and consented referral.
- Treat crawl evidence older than 24 hours, index/query evidence older than 96 hours, and referral
  evidence older than 72 hours as stale.
- Treat stale, unavailable, or synthetic streams as unusable: performance values become null and
  performance recommendations are prohibited.
- Derive index eligibility, locale, content family, user intent, review dates, editorial records,
  sources, and rights freshness only from current repository authority.
- Suppress route query/referral detail below 20 observations. Allow diagnostic display from 20
  through 199, but require at least 200 observations for a performance recommendation.
- Trigger a snippet-review prompt only when average position is at most 10 and CTR is below 2%.
  Trigger a referral-alignment prompt only when useful-action rate is below 1%.
- Mark review deadlines within 30 days as due soon. Expired editorial review or rights evidence
  blocks decision use.
- Keep referral included, other/unknown, excluded, and useful-action aggregate buckets explicit.
- Reject raw query text, full referrer URLs, user/session identifiers, private content, exact
  location, arbitrary metadata, accessors, unknown routes, path drift, symlinks, and oversized
  input.
- Bind output to SHA-256 digests of the exact input bytes, public-page inventory, and editorial
  manifest. Write only new mode-0600 JSON and Markdown files and never overwrite existing output.

Recommendations are bounded human-review prompts for crawl repair, index investigation, snippet
alignment, referral alignment, and content/source review. They cannot publish or rewrite content,
request indexing, change metadata, expand routes, activate locales, connect providers, enable
tracking, or modify production.

## Alternatives considered

| Option                               | Benefits                       | Costs/risks                                                | Decision |
| ------------------------------------ | ------------------------------ | ---------------------------------------------------------- | -------- |
| Connect live provider APIs now       | Current external data          | Lacks provider, notice, retention, and activation approval | Rejected |
| Infer performance from build quality | No external inputs             | Confuses publishability with observed performance          | Rejected |
| Store raw queries and referrer URLs  | Detailed diagnosis             | Sensitive data and small-cohort disclosure risk            | Rejected |
| Auto-apply recommendations           | Faster iteration               | Crosses content, indexing, locale, and production gates    | Rejected |
| Offline aggregate fail-closed brief  | Auditable, private, reversible | Requires reviewed manual exports                           | Selected |

## Consequences

CI verifies the policy using unavailable, stale, synthetic, low-sample, current, and poisoned
fixtures without contacting a provider. Real weekly performance remains blocked until an approved
aggregate export exists. The report always states sources, freshness, window, denominators,
known gaps, and content/source/rights status. Current inventory and editorial digests prevent a
brief from silently carrying forward after authority changes.

## Validation

Pure analytics tests cover strict parsing, accessor safety, exact route authority, freshness,
sample thresholds, metric projection, recommendation suppression, denominator buckets, and
renderer branding. CLI tests cover actual SHA-256 binding, exact 45-route projection, private
mode, no overwrite, and symlink rejection. The CI contract requires the dedicated offline
operations verifier.

## Rollout and rollback

No database, migration, analytics vendor, provider credential, tracking runtime, user data,
Search Console action, indexing request, route, locale, DNS, deployment, or public launch is
added. Rollback removes the policy module, CLI, quality gate, and records. Generated reports are
local private evidence and are not committed or uploaded automatically.
