# D-037: Provider-neutral, public-fact-only AI interpretation contracts

- Date: 2026-07-18
- Owners: architect, ai_safety, backend, qa_security, privacy
- Related tasks: RIT-030, RIT-031, RIT-032, RIT-033, RIT-034
- Evidence references: packages/ai/src/interpretation.ts, packages/ai/src/provider.ts, packages/ai/test/fixtures/tarot-interpretation-v1.json, scripts/verify-workspace-build.mjs

## Context

RITUVIA needs an AI boundary before selecting or connecting a production provider. Deterministic
tarot facts already have a reviewed public projection, while retrieval, pre-generation policy,
generation orchestration, post-generation verification, and provider activation are separate
backlog slices. A broad interface now could accidentally admit private questions, draw-audit data,
provider-specific objects, or invented future modality facts.

## Decision

Create a pure TypeScript `@rituvia/ai` package with no provider SDK, environment access, network
call, or external runtime dependency. Its first modality contract is Tarot V1 only. Input consumes
the public `TarotDrawFactsV1` projection and exact versioned prompt, approved-content,
approved-ritual, locale, theme, tone, request, and allowed-safety references. It excludes raw or safe questions, journals,
intentions, birth/contact/payment/account/session/reading data, idempotency material, entropy, and
the internal draw execution/audit envelope.

Use capability-shaped structured-generation and optional-streaming interfaces. A provider request
requires an opaque, package-issued generation authorization backed by runtime identity; a plain
`{ route: "allowed" }` object is neither type-valid nor runtime-valid. The internal issuer rejects
blocked, crisis, and reframed states and is not part of the package's public export. Provider
adapters must return only a normalized success or categorical failure; raw provider responses and
errors remain adapter-private. Stream deltas are explicitly provisional, and only a final
structured result can enter validation. Operational metadata is a fixed allowlist of categorical versions,
locale/theme, result, usage, cost, and latency fields rather than prompts or responses.

Represent the canonical runtime output with the camelCase fields in the AI safety specification:
title, summary, symbols with stable position-derived fact references, perspectives, reflection
questions, one small action, optional approved ritual reference, boundary note, source references,
and exact reflective safety literals. These fields implement the nested AI instructions'
observed-symbol, possible-meaning, reflection-question, small-action, uncertainty/boundary, and
source-provenance semantic blocks; the snake_case names are semantic labels, not a second JSON
shape.

Parse input only from bounded JSON, then parse output through exact-key, versioned, bounded,
normalized, fail-closed runtime contracts and return recursively frozen values. The parsed input is
runtime-opaque. The only public final-output parser requires that exact parsed input and rejects
missing, extra, or invented fact/source references plus any ritual code absent from its approved
input list. RIT-031 still owns approved content retrieval and prompt assembly; RIT-033 owns provider
orchestration, timeout/retry/fallback, and persistence; prose safety and fabrication verification
belongs to RIT-034. No future numerology or astrology fact schema is represented until its
deterministic engine exists.

## Alternatives considered

| Option | Benefits | Costs/risks | Why not selected |
| --- | --- | --- | --- |
| Install one provider SDK now | Faster first remote call | Crosses provider/model/budget gates and couples public contracts to one vendor | Provider selection and generation are later approved work |
| Use generic `unknown` modality facts | Appears extensible | Makes invented or private facts structurally admissible | Add each modality only after a deterministic public projection exists |
| Include safe question and personalization now | Richer interpretation | Preempts RIT-032/RIT-055 consent and safety controls | Keep the first contract theme-only and data-minimal |
| Defer all reference binding to orchestration | Smaller parser | A structurally valid output could invent facts, sources, or ritual codes | Bind exact input-owned references now and leave prose verification to RIT-034 |

## Consequences

Provider adapters and orchestration can change without changing product-domain contracts. The
compiler and runtime fixtures now reject internal draw envelopes, non-allowed safety states,
unsupported versions, non-JSON/accessor inputs, forged generation permission, unsafe text, unsafe
output safety flags, duplicate or input-unbound references, and unbounded collections. The contract does not claim that structurally valid model
prose is safe or factually grounded; generation remains unavailable until later retrieval, safety,
semantic verification, fallback, telemetry, and owner-gated provider work are complete.

## Validation

Focused tests cover one-card and three-card fixtures, all supported tones and time horizons,
optional ritual output, strict versions and keys, locale/provenance rejection, private-field and
internal-audit rejection, accessor/proxy non-execution, malformed/oversized JSON,
NFC/control/invisible/Bidi text, duplicate/invalid/input-unbound references, forged and non-allowed
authorization rejection, unsafe safety literals, fake structured and streaming
providers, categorical failures, and the operational metadata allowlist. TypeScript, lint,
architecture, compiled-package, and workspace-artifact checks include the new package.

## Rollout and rollback

This decision activates no model, credential, network call, production content, database change,
deployment, or user-facing behavior. Rollback removes the unused package and its build evidence;
there is no stored data, migration, external side effect, or destructive cleanup.
