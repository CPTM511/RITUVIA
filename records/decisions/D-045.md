## Context

After the local RIT-158 MVP, the owner supplied a production development pack that freezes a new
golden UI, bilingual product contract, machine-readable commercial/model requirements, proposed
database and OpenAPI contracts, threat model, security-negative matrix, and production-readiness
gates. The existing backlog otherwise selected RIT-037, but proceeding directly would skip the
pack's required repository reality audit and could duplicate or contradict current architecture.

## Decision

Install the 2026-07-23 production pack under `docs/codex/rituvia-production-2026-07-23/` and execute
RIT-159 as the single owner-directed Phase 0 reconciliation before further feature work. Preserve
the golden prototype and screenshot bytes exactly; normalize the security matrix from CRLF to the
repository-required deterministic LF form and update the repository copy of the pack manifest. The
pack's safety and security invariants take precedence over older conflicting product details. Its
golden prototype and screenshots govern approved visual behavior and reviewed English/Simplified
Chinese copy, but not simulated browser state, fake providers, or backend architecture.

Reuse the current modular TypeScript/PostgreSQL system where sound. Adapt proposed SQL and OpenAPI
contracts to existing models and routes instead of copying them as a migration or creating parallel
services. Keep all production provider capabilities disabled and retain every repository
human-approval floor.

## Alternatives considered

| Option | Benefits | Costs/risks | Why not selected |
| --- | --- | --- | --- |
| Continue immediately with RIT-037 | Preserves prior queue order | Skips owner-required Phase 0 and new production contracts | Reconcile first, then re-rank from evidence |
| Replace the repository with the prototype/schema | Fast apparent fidelity | Duplicates sound modules and imports insecure simulations | Prototype is UI evidence, not backend code |
| Install only selected pack files | Smaller diff | Breaks manifest integrity and omits threat/test evidence | Commit the complete verified pack with recorded LF normalization |

## Consequences

RIT-037 returns to Planned behind RIT-159. The repository gains a review-protected dated source
pack and a truthful capability/gap/security baseline before implementation resumes. No feature,
provider, migration, production data, payment, credential, deployment, or public behavior changes
in Phase 0.

## Validation

Validation requires the package verifier and declared hashes, machine-readable contract parsing,
current repository quality gates, production-artifact browser/accessibility evidence, module-route-
schema/API mapping, an explicit adaptation plan, and a final diff review proving production flags
remain safe-off.

## Rollout and rollback

Rollout is documentation and audit evidence only. Rollback removes the installed dated pack and
reverts its instruction, backlog, decision, status, and task records. No runtime or database
rollback is required.
