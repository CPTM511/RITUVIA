# D-069: Adopt AGPLv3 for RITUVIA and Swiss Ephemeris

- Date: 2026-07-26
- Owners: owner, architect, backend, qa_security, operations
- Related tasks: OWN-003, OWN-013, RIT-090, RIT-093
- Evidence references: owner reply `同意将 RITUVIA 整个可交付项目按 AGPLv3/兼容许可证开源，并公开线上部署版本的完整对应源代码。`;
  root `LICENSE`; `docs/OPEN_SOURCE_COMPLIANCE.md`

## Context

D-066 selected Swiss Ephemeris under a future Professional Unlimited License because the repository
was not then approved for AGPL distribution. The owner has now explicitly authorized licensing the
entire RITUVIA deliverable project under AGPLv3-compatible terms and publishing the complete
Corresponding Source for every deployed network version.

Swiss Ephemeris is dual licensed. Its official notice requires a license choice before distribution
or public-service activation and states that the AGPL path places the whole software project under
AGPL or a compatible license. Product positioning as entertainment, reflection, or research does
not replace those obligations.

## Decision

RITUVIA adopts `AGPL-3.0-only` as the repository license. Swiss Ephemeris integration uses the
official AGPL path rather than the June 2026 Professional Unlimited License. No Professional
License payment, contract signature, provider countersignature, legal-licensee evidence, or private
commercial-license evidence is required.

The selected engine and provenance remain:

- Swiss Ephemeris library version `2.10.03`;
- official source/data snapshot tag `v2.10.3final`;
- source commit `af9823fe7b06ffefe3d3968fdc5680be8b5eec5f`; and
- offline, checksum-pinned Swiss Ephemeris data with `SEFLG_SWIEPH` required at runtime.

The repository must retain the complete AGPL license, Swiss Ephemeris copyright/license notices,
the exact source and data inventory, every RITUVIA modification, native bridge source, build and
installation scripts, interface definitions, and information needed to reproduce the deployed
object code. Each public network deployment must expose a durable, prominent source-code route or
link for the exact running version before public activation.

AGPL acceptance removes the commercial execution blocker but does not weaken native supply-chain,
correctness, privacy, security, or production-release gates. Local integration may proceed after
the root license and immutable upstream manifest exist. Production activation remains forbidden
until source/data checksums, compiler and flags, reproducible build, native SBOM, ABI, reference
vectors, engine-flag verification, supply-chain review, Corresponding Source dry run, and staging
kill-switch evidence pass.

Third-party assets, fonts, content, and dependencies retain their own notices and terms. Material
license incompatibility blocks public release and must be resolved without deleting attribution or
silently narrowing source availability. Qualified counsel review is carried by the legal launch
gate before unrestricted production publication; it no longer blocks local AGPL integration.

## Consequences

OWN-013 is satisfied as an owner approval and repository-license gate, not as execution of the
superseded Professional License. RIT-093 becomes Ready. D-066 remains historical evidence only.

Selection V1 remains immutable and production-safe-off for replay. A new AGPL selection V2 and
native evidence manifest must supersede it; code must never mutate V1 into a falsely executed
commercial contract.

Production `astrology_enabled` remains false. This decision does not approve deployment, public
launch, legal-policy activation, production migration, private-content AI, payments, or any other
human-gated action.

## Alternatives considered

| Option                 | Benefits                                                       | Costs/risks                                                      | Decision             |
| ---------------------- | -------------------------------------------------------------- | ---------------------------------------------------------------- | -------------------- |
| Whole-project AGPLv3   | No license fee, public auditability, same deterministic engine | Complete Corresponding Source and compatibility obligations      | Selected             |
| Professional Unlimited | Closed-source option and compiled server distribution          | CHF 700, contract execution, private evidence                    | Superseded           |
| MIT astronomy engine   | Permissive TypeScript path                                     | Missing complete house-system implementation and added math risk | Retained exit option |
| Hosted astrology API   | Faster integration                                             | Sends birth data, network dependency, weak replayability         | Rejected             |

## Validation

Repository checks must assert the root AGPL identifier and license text, the owner approval
reference, exact upstream commit and per-file checksums, preserved notices, no runtime download,
and no Professional License activation claim.

## Rollout and rollback

Rollback disables and removes the native adapter and generated build artifacts while retaining this
decision, the AGPL repository license for already distributed versions, and all required source
offers. A distributed AGPL version cannot be retroactively made closed source.
