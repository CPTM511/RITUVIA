# D-028: Presentation-only resilient state boundary

- Date: 2026-07-17
- Owners: frontend, product, qa_security, localization, architect
- Related tasks: RIT-015, RIT-020, RIT-024, RIT-025, RIT-028
- Evidence references: packages/ui/src/primitives.tsx, apps/web/app/_components/resilient-state.tsx, apps/web/app/_components/connection-state.tsx, apps/web/app/_components/connection-notice.tsx, apps/web/app/[locale]/error.tsx, apps/web/test/locale-error.test.tsx, scripts/verify-web-accessibility.mjs

## Context

The first public shell needs reusable empty, error, offline, and dependency-unavailable
presentation without pretending that readings, accounts, persistence, PWA caching, or a provider
integration already exists. Static absence, an inserted connection advisory, an unclassified route
failure, and a typed dependency failure require different announcement timing. A generic component
that classifies errors, reads raw provider payloads, automatically retries, or owns English copy
would weaken privacy, localization, idempotency, and product-truth boundaries.

## Decision

Keep four closed page-level presentation patterns in `@rituvia/ui`: empty, error, offline, and
provider-unavailable. They accept only caller-owned non-empty localized title/description text,
bounded title elements, decorative allowlisted icons, explicit quiet/polite/assertive timing, and
at most one dominant action plus one secondary action. Actions are caller-owned buttons or bounded
local links; the component never fetches, classifies, logs, stores, retries, or receives raw errors,
provider responses, URLs, questions, journals, or other private content. Static states are quiet by
default, assertive announcements are valid only for errors, actions remain outside live regions,
and the consumer owns any programmatic focus transfer.

The low-level discriminated `StatePattern` renderer keeps one React component and semantic host
boundary when a consumer changes between reviewed kinds. Named wrappers remain the preferred API
for static variants. This preserves an already-focused whole-page title during a connection-state
copy/kind update instead of replacing its subtree.

The English public shell is the first real consumer. Its home page truthfully states that personal
reflection experiences are not open in the current foundation; its small client island shows a
polite advisory only after `navigator.onLine` explicitly reports offline. A live region is mounted
empty before any connection transition, then receives cautious offline/online advisory copy while
the visible state remains quiet. The locale-segment error boundary uses reviewed static copy, a
user-triggered reset, a safe home link, and an initial H1 focus target without reading or logging the
supplied `Error`. The existing feature-flag disabled/unavailable states continue to return the same
empty private 404 and never render these patterns. No public state/fault route, query, header,
cookie, or debug switch is permitted.

Provider-unavailable is implemented and browser-previewed only as a dependency-neutral synthetic
presentation pattern. It does not claim a provider adapter, 503 classifier, fallback, automatic
retry, availability SLA, or provider E2E. A future typed provider consumer must classify its own
safe error and idempotent retry before using it. Loading continues to use the RIT-011 Button,
Spinner, and Skeleton primitives; a generic partial/degraded network state remains deferred until a
real networked feature defines it.

## Alternatives considered

- Expose the feature-flag unavailable state as a provider page: rejected because it would disclose
  an internal activation distinction and overturn D-023's fail-closed public boundary.
- Add public test routes or query switches for each state: rejected because fixtures could become
  crawlable, cacheable, or usable as a fault-injection surface.
- Let the UI package inspect `Error`, network, or provider objects and retry automatically: rejected
  because presentation cannot establish privacy-safe classification or operation idempotency.
- Keep every variant only in a component preview: rejected because RIT-015 requires a real first
  feature consumer, which the existing public shell now provides.

## Consequences

Applications must supply localized copy, truthful classification, announcement timing, focus, and
safe recovery actions. The public shell gains a small client connection listener but remains fully
server-readable with JavaScript disabled and makes no offline-storage promise. English is still the
only active locale; adding another locale must provide locale-aware recovery context rather than
silently retaining the current default-English error boundary. Current screen-reader announcement
behavior remains release-level manual evidence; Chromium/axe verifies DOM and accessibility-tree
semantics but is not screen-reader certification.

The home-page empty state is truthful only while personal experiences remain unavailable. The first
personal-experience launch must remove or replace that state in the same change; it must not remain
as stale launch copy.

## Validation

Unit and mutation tests cover all four variants, default and dynamic live-region semantics,
heading/title relationships, action isolation and loading suppression, local-link enforcement,
control-character rejection, forged enum/action/host props, typed English state inventory, raw
error isolation, listener cleanup, safe-off proxy continuity, the actual error-boundary runtime,
and three real Web consumers. The production build must retain the exact four canonical routes and
resource budgets. Playwright/axe must verify the four routes plus a persistent
online/offline/online advisory transition, 320px and expanded-text reflow, RTL,
dark/reduced-motion/no-JavaScript behavior, keyboard focus, 44px targets, and local-only requests.
The synthetic UI preview must expose all four closed variants without claiming a product incident
or provider capability.

## Rollout and rollback

No production activation, public route, locale, database, provider, analytics, user data, or
external state changes. Roll back by reverting the RIT-015 commit; the earlier English public shell
and safe-off activation boundary remain intact and no migration or data recovery is required.
