# D-072: Separate astrology implementation completion from deployed-source publication

- Date: 2026-07-27
- Owners: owner, backend, qa_security, operations
- Related tasks: RIT-093, RIT-094, RIT-142, RIT-143
- Preserves: D-069 and all `AGPL-3.0-only` Corresponding Source obligations
- Evidence references: owner instruction to close RIT-093 after the final archive and enter
  RIT-094; release archive output for revision `1fded12559b4e2986a317f2a6fee4008a2c22b8a`

## Context

RIT-093 now passes its deterministic engine, privacy, persistence, runtime, native security,
independent-vector, component-source, and exact-clean complete release-source gates. Revision
`1fded12559b4e2986a317f2a6fee4008a2c22b8a` produced a 914-file complete repository plus pinned
native-source archive with SHA-256
`68cc39041511e1de29fa9355efc512d065c32612e88d396d6dbfe9aebafb4ae6` and repeated the native
rebuild without network access.

The remaining upload, public source link, and deployed-revision binding can only be performed for
an actual owner-approved deployment. Keeping those production operations inside RIT-093 would
block the dependent natal UI before a deployable product exists, while performing them now would
cross the production deployment gate and still could not prove the source of a future deployed
revision.

## Decision

Close RIT-093 when an exact clean revision produces and verifies the complete local release-source
archive. Move the operational publication proof to RIT-142 and the owner go/no-go enforcement to
RIT-143.

For every deployed revision, RIT-142 must:

1. run the locked component and complete release-source gates against the exact deployment SHA;
2. upload the immutable archive to the approved public source location;
3. re-download it and verify its recorded SHA-256 and complete inventory;
4. expose a prominent source link from the deployed service; and
5. prove that the deployment revision, archive manifest, public link, and rollback source remain
   bound to the same SHA.

RIT-094 may proceed while `experience.astrology` remains disabled. This decision does not authorize
deployment, public launch, DNS, provider activation, or a production feature-flag change.

## Alternatives considered

| Option                                      | Benefits                                    | Costs/risks                                           | Decision |
| ------------------------------------------- | ------------------------------------------- | ----------------------------------------------------- | -------- |
| Split implementation and deployment proof   | Enables dependent UI without weakening AGPL | Requires explicit release-task enforcement            | Selected |
| Keep RIT-093 open until production launch   | One task contains all source evidence       | Blocks M9 UI until M14 and still proves no future SHA | Rejected |
| Publish the local archive immediately       | Produces an early public artifact           | Cannot bind a nonexistent deployed revision           | Rejected |
| Waive upload/readback for the first release | Simplifies launch                           | Violates D-069 and owner-approved AGPL obligations    | Rejected |

## Consequences

RIT-093 can truthfully become Done without claiming that a local archive is already a public source
offer. D-069 remains fully binding for any network deployment or distribution. RIT-142 cannot pass
without upload/readback/link evidence, and RIT-143 cannot approve production rollout without the
RIT-142 evidence.

## Validation

The focused release-source suite, architecture policy, CI contract, production-pack integrity, and
secret policy pass. The complete archive for the implementation revision is retained locally as
ignored release evidence. The final documentation revision must repeat both archive gates before
handoff.

## Rollout and rollback

No remote system changes in this decision. Rollback reopens RIT-093 and blocks RIT-094 only if the
local exact-clean archive gate or natal-engine evidence regresses. A production source offer is
never removed while its corresponding deployed version remains available.
