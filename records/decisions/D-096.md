# D-096: Pin the repository and deterministic runtime to Node.js 26.5.1

- Date: 2026-07-31
- Owners: owner, architect, backend, qa_security
- Related tasks: RIT-163
- Evidence references: owner instruction in the 2026-07-31 Codex task; official Node.js 26.5.1
  release; `.node-version`; `package.json`; `pnpm-workspace.yaml`; `scripts/ci-contract.ts`;
  `apps/web/server/astrology-location-time-zone.ts`

## Context

The repository and CI contract were pinned to Node.js 24.18.0 LTS. The owner explicitly requested
an upgrade to the latest Node.js release before RIT-162. On 2026-07-31, the official current
release is Node.js 26.5.1. The repository also records exact Node, ICU, and tzdata provenance for
historical time-zone resolution, so changing only the package engine would create a false runtime
contract.

## Decision

Pin local development, CI, package-engine enforcement, pnpm dependency resolution, Node type
declarations, and the Web historical-time-zone runtime descriptor to exact Node.js 26.5.1. Keep
pnpm 11.13.1. The official Node.js 26.5.1 binary reports ICU 78.3 and tzdata 2026b, so those two
deterministic provenance values remain unchanged.

This decision supersedes the active Node.js 24.18.0 pins in D-015 and D-067. Their files and all
completed task records remain unchanged as historical evidence. Persisted records continue to
carry the runtime provenance under which they were created; new results use the 26.5.1 descriptor.

Node.js 26 is the Current release line on the decision date rather than an LTS line. This is an
intentional owner-directed toolchain choice, not permission to deploy, activate a provider, change
production data, or relax any release gate.

## Alternatives considered

| Option | Benefits | Costs/risks | Decision |
| --- | --- | --- | --- |
| Keep Node.js 24.18.0 | Existing LTS evidence remains directly reusable | Does not satisfy the owner instruction and retains an older security baseline | Rejected |
| Upgrade to Node.js 24.18.1 LTS | Lower release-line churn | Is not the latest Node.js release requested by the owner | Rejected |
| Upgrade exactly to Node.js 26.5.1 | Satisfies the instruction and removes runtime drift | Current-line upgrades require a full workspace regression gate | Selected |
| Use a floating `26` or `latest` range | Automatically follows releases | Makes builds and deterministic provenance unreproducible | Rejected |

## Consequences

Every active toolchain declaration must agree on 26.5.1, and CI continues to read the exact
`.node-version` file. The Node type package advances to the matching current major. Historical
time-zone fixtures advance only the runtime version because ICU and tzdata are unchanged.

Future Node upgrades require another explicit decision and the same full workspace, database,
browser, architecture, security, and generated-evidence gates. Homebrew lag does not change the
repository contract; verification must execute the official exact binary selected here.

## Validation

The CI contract rejects any drift among `.node-version`, `package.json`, and
`pnpm-workspace.yaml`. Focused CI-contract and historical-time-zone tests must pass first. The
complete workspace quality, PostgreSQL, browser/accessibility, native security, and generated
evidence matrix must then pass under Node.js 26.5.1 and pnpm 11.13.1.

## Rollout and rollback

Rollout changes repository tooling and new deterministic runtime provenance only. It does not run a
database migration, rewrite a stored result, update a golden screenshot, deploy, or activate a
production provider.

Rollback restores the active pins and new-result runtime descriptor to Node.js 24.18.0 plus the
matching Node type declaration and lockfile. Historical persisted provenance remains unchanged in
either direction.
