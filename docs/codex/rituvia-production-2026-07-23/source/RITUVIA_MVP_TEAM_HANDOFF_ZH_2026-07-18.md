## 1. 快速访问

- 本机验收链接：[http://127.0.0.1:4175/en](http://127.0.0.1:4175/en)
- 当前状态：本机后台服务正在运行，首页已验证返回 HTTP `200`。
- 适用范围：该地址只能在运行 RITUVIA 的这台 Mac 上访问。
- 团队远程访问：其他电脑无法通过 `127.0.0.1` 访问本机服务。团队远程评审需要后续建立 HTTPS Preview/Staging 环境，或在明确授权后使用受控临时隧道。

## 2. 当前 MVP 的目标

RITUVIA 是一个面向全球用户的象征性自我反思、个人仪式和私密数字圣所产品。当前 MVP 已把核心产品闭环实现为：

1. 用户匿名选择一个反思主题并抽取塔罗牌。
2. 系统展示非预测、保留用户自主性的象征性解释。
3. 用户设置一个意图和一个现实中可执行的小行动。
4. 用户完成免费或已拥有的数字仪式。
5. 用户保存一段加密的私密反思。
6. 用户可以登录、查看内容并在适当时间重新访问。
7. 本地支付模拟器验证订单、Webhook、账本和数字权益闭环，但不会真实扣款。

## 3. 已实现功能

### 3.1 产品入口与基础体验

- 英文响应式 Web 产品界面，并保留后续 PWA 扩展架构。
- 首页、方法说明、安全原则、隐私说明、登录、账户、塔罗、Sanctuary 和结账相关页面。
- 支持桌面和移动端布局、键盘操作、焦点状态、深色视觉、减弱动画和基础 RTL 架构。
- 匿名用户无需注册即可获得第一次有效体验。

### 3.2 塔罗反思

- 一张牌和三张牌两种固定牌阵。
- 使用操作系统安全随机源进行无放回抽牌；抽牌事实与解释文案分离。
- 新读数使用完整 22 张大阿卡纳，采用 Rider–Waite–Smith 常见顺序：Strength 为 VIII，Justice 为 XI。
- 每张牌包含正位、逆位和十种反思主题的受控英文内容。
- 英文解释和抽象符号是 RITUVIA 基于 Lumora 原型制作的原创反思内容，不是历史牌义权威、专家审校生产内容或真实牌面艺术。
- 结果明确说明它不是预测、命令或专业建议。
- 支持读取历史结果、冷静的重新反思限制和分类报告入口。
- 早期 `Threshold / Mirror / Lantern` 三张 RITUVIA 原创临时牌不再用于新抽牌，只保留给旧读数回放。

### 3.3 Digital Sanctuary

- 用户可以直接进入 Sanctuary，不再强制要求先完成塔罗读数。
- 支持独立意图，也支持自动关联当前标签页中最新有效的读数。
- 意图包含主题和一个用户可控制的现实小行动。
- 免费蜡烛和免费香始终可用。
- 已拥有的付费数字物品可用于仪式；付费不会被描述为“更灵验”。
- 用户可以完成仪式并保存加密的私密日志。
- 已实现加载、成功、错误、离线、重试和降级状态。

### 3.4 本地账户体验

- 本地 Passwordless 登录、退出、退出全部会话和匿名数据合并。
- 会话使用 HttpOnly、SameSite 和固定过期策略。
- 当前登录仅接受 `@example.test` 测试邮箱。
- 当前页面会展示本地回调链接，不会真正发送邮件。

### 3.5 商业和支付基础

- 服务端维护产品、币种和整数价格，客户端不能修改金额。
- 已实现订单、幂等键、签名 Webhook、追加式账本和数字权益发放。
- 已实现 Stripe Hosted Checkout 适配器和 Stripe Webhook 验签边界。
- 当前环境使用 HMAC 签名的本地 Checkout 模拟器，不会真实扣款。
- 付费前要求账户登录和明确的 18+ 声明。
- 当前四种一次性数字物品为：Mindful Incense、Moonlit Lotus、Amethyst Guardian、Golden Intention Bowl。
- 当前本地模拟价格分别为 USD 0.99、1.99、3.99 和 5.99；它们不是已经批准的线上正式售价。

### 3.6 隐私、安全与内容边界

- 用户问题只发送受控主题；自由文本问题默认不持久化或进入分析数据。
- 意图小行动和私密日志在写入数据库前加密。
- 日志、祈愿、出生信息和关系问题不进入广告画像。
- AI 内容与确定性计算分离；当前本地塔罗主结果使用已审阅内容。
- 对医疗、法律、财务、危机和确定性预测保持明确边界。
- 不包含储值钱包、提现、代币、NFT、赌博或“付费更灵验”机制。

## 5. 当前已知问题和限制

| 优先级 | 问题/限制 | 当前影响 | 处理方向 |

| P0 | 真实邮箱登录未接入 | 只能使用 `@example.test` 和本地回调链接 | 选择 Resend/Postmark 等供应商，验证发件域名并配置服务端密钥 |
| P0 | Stripe 未激活 | 当前结账不会真实收费 | 完成 Stripe Test Mode、Price ID、Webhook、国家政策和承保/法务审批 |
| P0 | 上线国家、主体、税务和法律文本未确定 | 不能公开商业上线 | 确定公司主体、首发国家、税务/MoR、退款、隐私和条款 |
| P0 | 品牌和域名未正式清查 | 不能把 RITUVIA 视为已完成商标确认 | 完成商标、域名和语言风险检索 |

| P1 | 目前只有英文正式内容 | 还不能面向多语言市场发布 | 按审核流程逐步增加语言，避免机器直接发布文化敏感内容 |
| P1 | 生产 AI 供应商仍安全关闭 | 当前主要依赖已审阅反思内容 | 完成供应商、模型、成本、安全评估和回滚演练后再激活 |
| P1 | 缺少真实运营后台 | 无法高效处理退款、争议、内容报告和用户支持 | 增加受权限保护的运营和审核工具 |

| P2 | 暂无真实产品数据和增长指标 | 不能判断激活率、完成率、付费意愿和留存 | 上线前定义隐私安全的事件与核心指标 |

## 6. 建议的下一阶段计划

### 阶段 A：团队可远程评审（最高优先级）

1. 建立受密码或团队身份保护的 HTTPS Preview/Staging 环境。
2. 使用独立的测试数据库和非生产密钥。
3. 让产品、设计、安全、支付和运营成员共同完成验收清单。
4. 收集问题时标注页面、设备、复现步骤、预期结果和实际结果。

### 阶段 B：真实身份与 Stripe 测试联调

1. Owner 确定邮件供应商，完成发件域名验证。
2. 实现真实 Magic Link 邮件投递、统一成功响应、限流、反枚举和退信处理。
3. Owner 完成 Stripe 测试账户、产品和一次性 Price 配置。
4. 在 HTTPS Staging 上完成 Hosted Checkout 和签名 Webhook 验收。
5. 演练重复/乱序事件、退款、争议、支付失败、供应商故障和对账。

### 阶段 C：产品体验完善

1. 根据团队测试修复 P0/P1 UX 问题。
2. 制作或授权完整的 22 张大阿卡纳卡面。
3. 优化首次体验、读牌到 Sanctuary 的引导和结账解释。
4. 增加隐私安全的漏斗指标：开始读牌、揭牌、设置意图、完成仪式、保存反思、登录和结账开始/完成。
5. 补充真实屏幕阅读器、Firefox、WebKit 和高倍缩放测试。

### 阶段 D：商业上线准备

1. 确定首发国家、公司主体、税务、退款、账单描述符、支持渠道和价格。
2. 获得支付服务商书面承保确认。
3. 完成隐私政策、服务条款、Cookie/同意策略和数据保留审批。
4. 完成域名、商标、备份、监控、告警、灾难恢复和上线/回滚演练。
5. Owner 审阅全部证据后执行最终 Go/No-Go。

### 计划治理说明

当前规范 Backlog 中唯一标记为 `Ready` 的工程任务是 RIT-037（解释重新生成、报告和版本历史）。本报告建议把远程 Preview、真实邮箱和 Stripe Sandbox 作为商业化 P0；如果采用这一顺序，需要由 Owner 明确批准重新排序或建立新的集中式商业上线任务，不能把建议计划误写成当前已批准队列。

## 7. 团队建议验收路径

团队成员在同一台测试电脑上可以按以下顺序验证：

1. 打开 [http://127.0.0.1:4175/en](http://127.0.0.1:4175/en)。
2. 进入一张牌或三张牌体验，确认抽到的是标准大阿卡纳。
3. 进入 Sanctuary，选择意图、填写现实小行动并放置免费蜡烛或香。
4. 保存一段私密反思，确认完成页出现。
5. 使用类似 `reviewer@example.test` 的本地测试邮箱登录。
6. 查看账户、会话和历史内容。
7. 选择付费数字物品并执行本地模拟结账；确认页面明确说明不会真实扣款。
8. 在桌面和手机宽度下检查导航、卡片、表单、错误状态、焦点和文字可读性。

## 10. 当前结论

当前版本已经达到“可以在本机完整体验和验证商业闭环”的 MVP 水平。核心读牌、意图、免费仪式、私密反思、本地账户、模拟支付、订单、账本和权益链路均已实现并通过自动化验证。

它还没有达到“可公开收费上线”的状态。阻塞上线的主要问题不是基础产品代码，而是真实邮件、Stripe 与国家政策、法律/税务、远程托管、品牌权利、运营能力和生产级监控。建议下一步首先建立团队可访问的 HTTPS Preview 环境，然后并行推进真实邮件与 Stripe Test Mode 联调。
